**9. 주의사항 및 노하우**  
- 업무 팁:
  - Git 이력상 BackroomCompany는 merge commit 비중이 높다. 실제 기능 변경은 non-merge commit과 변경 파일을 함께 확인하는 편이 정확하다.
  - Unreal `.uasset` 및 World Partition 외부 액터 파일은 라인 수보다 파일 경로/에디터 확인이 중요하다.
  - `develop_v20*`와 `develop_sik_v20*`를 오가는 병합이 많으므로, 릴리즈 대상 브랜치가 맞는지 먼저 확인한다.
- 문제 & 해결법:
  - 패키징/컴파일 오류: 누락 에셋, `BindWidget` 메타데이터, enum redirect, GameplayTag/DataTable 변경 여부 확인
  - 네트워크 이슈: multicast/RPC/Delegate 흐름과 클라이언트 예측 처리 확인
  - UI 표시 문제: WidgetComponent owner, render state, distance scale, marker/compact bar 보간 확인
  - 음성/오디오 이슈: PlayerVoice/CustomVoice/BGMSubsystem의 초기화 순서, GC 예외, attenuation, multicast 트리거 확인
- 중요 포인트:
  - BackroomCompany 최근 이슈는 FlashLight, Repeater Minimap, Item Deploy, TechTree, Storage, Revival/Stage Result 주변에 집중되어 있다.
  - BackroomCleaners EntityHealthBar는 tracker/actor/component/widget module 구조가 연결되어 있어 한쪽만 수정하면 표시 상태가 깨질 수 있다.
  - VAT 작업은 Parasyte/Turret 에셋, LOD, MID, shadow, invisible/double mesh 조건을 같이 확인해야 한다.

**11. 개선 제안**  
- 문제점:
  - Unreal 바이너리 에셋과 World Partition 파일 변경량이 커서 Git 이력만으로 실제 업무 범위 파악이 어렵다.
  - merge commit이 많아 기능 단위 추적 시 노이즈가 크다.
  - 기능별 문서가 일부만 남아 있어 신규 담당자가 진입할 때 코드/에셋 참조를 직접 따라가야 한다.
- 개선 아이디어:
  - 기능별 소유 파일, 테스트 방법, 대표 QA 케이스를 `Docs`에 남기기
  - 릴리즈 브랜치 병합 전 체크리스트 표준화
  - 에셋 변경이 큰 기능은 에디터 스크린샷/레벨 위치/데이터 테이블명을 함께 기록
  - Debug/QA 커밋은 가능하면 티켓 번호 또는 재현 조건을 커밋 메시지에 포함
