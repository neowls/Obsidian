Weekly Detail

Week 0 - 재개 준비

빌드, PIE, P0 map, asset 재사용 후보를 확정한다.

  • C++ build와 DevLevel PIE 실행 확인.
  • P0 대상 map은 기본적으로 DevLevel 사용.
  • 아트 담당자에게 P0 범위와 금지선을 공유.
Gate: P0 대상 map과 첫 2주 작업 board 확정.

Week 1-2 - Route Skeleton

VS-BLOCKOUT-01, VS-BLOCKOUT-02를 잠근다.

  • 관리실, 2층, 3층, 지하, 307호 앞 route 연결.
  • LocationId marker와 gate 배치.
  • 아트는 corridor, door/nameplate, lighting fixture부터 진행.
Gate: 관리실에서 307호 앞까지 막힘 없이 이동.

Week 3-4 - 첫 민원 루프

상호작용, 민원 runtime, Board/Report UI를 실제 상태에 연결한다.

  • 보드, 공구함, 손전등, 보고 위치 interaction.
  • 첫 민원 state transition 구현.
  • 관리실 kit와 2층 203호 기준점 제작.
Gate: 첫 민원이 보고까지 닫힘.

Week 5-6 - 데모 체인

10단계 route chain, 정전, 지하, 307호 앞 맛보기를 연결한다.

  • 민원/progression chain end-to-end 구성.
  • audio/lighting placeholder baseline 추가.
  • 3층, 지하 전기실, 307호 앞 최소 밀도 확보.
Gate: 30-45분 흐름이 처음부터 끝까지 진행.

Week 7 - Demo Lock

새 기능 추가를 멈추고 재현성과 읽기성을 잡는다.

  • 10단계 시작 상태 재현.
  • critical bug fix와 최소 checkpoint/debug recovery.
  • 조명 tone, 오염, 라벨, 소리 원인 포인트 정리.
Gate: 외부 테스트 후보 빌드.

Week 8 - 외부 테스트

3-5명 테스트로 다음 제작 방향을 판정한다.

  • 첫 5분 이해도, completion time, 307호 기억 여부 기록.
  • 길찾기 실패 지점과 반복 실패 top 3 정리.
  • demo polish, 본편 전환, scope 축소 중 하나로 판정.
Gate: 이후 4주 첫 priority 결정.

Role Split

PM / Developer

사용자가 일정, 기획, 개발, FX, 사운드 placeholder, 통합 리뷰를 맡는다.

  • route skeleton과 runtime 연결 우선.
  • 문서 update log와 gate 결과 관리.
  • 새 기능보다 첫 민원 루프 검증 우선.

Environment / Prop Art

아트 담당자는 주 8-12시간, Unreal Editor 직접 작업 기준으로 잡는다.

  • corridor, door/nameplate, lighting fixture 먼저.
  • 단일 이벤트용 asset 대신 2개 이상 민원 재사용 kit 제작.
  • 307호 내부는 P0 범위 밖.

FX / Sound Placeholder

사운드와 FX는 후반 장식이 아니라 route와 evidence 이해를 돕는 상태 출력으로 둔다.

  • 형광등 buzz, 인터폰 static, TV hum, 펌프/배전반 hum.
  • 정전, 비상등, 물기/오염, 문틈 cue.
  • 음악보다 환경 loop와 interaction cue 우선.

Acceptance Gates And Cut Rules

P0 Demo Gate

  • 30-45분 안에 시작부터 307호 앞 맛보기까지 진행 가능.
  • 5분 안에 민원 처리 공포 콘셉트 이해.
  • 정상 민원과 이상 민원 차이가 한 세션 안에서 체감됨.
  • 괴물 직접 노출 없이 긴장 유지.
  • 플레이어가 307호 내부를 다음 목표로 기억.

Cut Rules

  • route가 불안하면 민원 수를 줄인다.
  • 첫 민원 루프가 불안하면 UI polish를 줄인다.
  • 아트가 밀리면 신규 공간보다 corridor/office/door kit 완성도를 올린다.
  • 사운드가 밀리면 음악보다 환경 loop와 interaction cue를 우선한다.
  • 저장/로드가 밀리면 debug checkpoint로 대체한다.
