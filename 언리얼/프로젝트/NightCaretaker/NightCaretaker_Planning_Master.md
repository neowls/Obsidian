## 1. One-Page Game Brief

| 항목 | 결정 |
| --- | --- |
| 한 줄 정의 | 플레이어는 오래된 아파트의 야간 관리인이 되어 주민 민원을 처리하지만, 밤이 깊어질수록 평범한 고장이 건물의 규칙을 어기는 이상 현상으로 변해 간다. |
| 장르 | 1인칭 싱글플레이 심리 공포, 탐색, 짧은 업무 시뮬레이션 |
| 핵심 약속 | 플레이어는 괴물을 사냥하거나 퇴마하지 않는다. 맡은 일을 처리하려고 할수록 건물과 기록을 신뢰할 수 없게 된다. |
| 핵심 루프 | 접수 -> 도구 선택 -> 현장 이동 -> 단서 확인 -> 정상/이상 판정 -> 조치 -> 보고 -> 다음 민원 |
| 핵심 차별점 | 공포가 금지된 장소 탐험이 아니라 "해야 하는 야간 업무"에서 발생한다. |
| 주요 훅 | 307호는 초반부터 보이지만 바로 소비하지 않는다. 플레이어가 스스로 신경 쓰게 만든 뒤 후반에 문턱을 넘게 한다. |
| 수직 슬라이스 목표 | 첫 15~20분 안에 야간 관리인 역할, 민원 루프, 정상/이상 구분, 307호 호기심을 증명한다. |

### 현재 제품 판단

이 게임의 중심은 `민원 처리 공포`다.
기획, 레벨, UI, 사운드, 구현은 모두 다음 문장에 종속된다.

> 플레이어는 평범한 업무 절차를 믿고 움직이지만, 매 민원이 끝날수록 그 절차가 현실을 설명하지 못한다고 느낀다.

이 문장을 강화하지 않는 시스템은 P0 범위에 넣지 않는다.

## 2. Product Identity

### 플레이어 판타지

플레이어는 이 건물의 영웅이나 탐정이 아니다.
플레이어는 야간 관리인이고, 권한과 도구가 제한된 상태에서 접수된 문제를 처리해야 한다.

| 요소 | 결정 |
| --- | --- |
| 직업 정체성 | 오래된 아파트의 야간 관리인 |
| 권한 | 관리실 접근, 공용구역 점검, 기본 수리, 민원 보고 |
| 한계 | 전투 불가, 임의 침입 제한, 전문 장비 부족, 주민 정보 제한 |
| 압박 | 민원 누적, 야간 고립, 관리 기록의 모순, 307호 반복 노출 |
| 기억해야 할 감정 | "나는 그냥 민원 처리만 하면 될 줄 알았다." |

### 하지 않을 것

| 금지 범위 | 이유 |
| --- | --- |
| 전투 시스템 | 관리인 판타지와 제작 범위를 해친다. |
| 퇴마/의식 시스템 | 업무 공포가 초자연 해결 게임으로 바뀐다. |
| 자유 운영형 건물 시뮬레이션 | 핵심 루프가 민원 공포에서 경제/운영으로 분산된다. |
| 장시간 NPC 대화 트리 | 고립감과 공간 기반 공포가 약해진다. |
| 복잡한 조합 퍼즐 | 플레이어가 공포보다 퍼즐 해법에 집중한다. |
| 완전 랜덤 이상 현상 | 공포 리듬과 검증 가능성이 낮아진다. |

## 3. Design Pillars

| Pillar | 구현 규칙 | 금지 예시 | 검증 |
| --- | --- | --- | --- |
| Mundane duty becomes horror | 모든 공포는 먼저 평범한 민원, 고장, 기록, 시설 점검으로 시작한다. | 초반부터 괴물, 저주, 의식 장면을 직접 보여준다. | 플레이어가 첫 민원을 "일"로 이해한 뒤 뒤늦게 의심한다. |
| Few actions, high meaning | 접수, 이동, 확인, 조치, 보고를 반복하되 결과와 맥락을 바꾼다. | 민원마다 새 미니게임을 만든다. | 플레이어가 같은 행동을 해도 이번에는 결과가 다를 수 있다고 느낀다. |
| Uncertainty before threat | 직접 위협 전 시간, 공간, 정체, 행동 선택의 불확실성을 쌓는다. | 이유 없는 즉사, 반복 점프스케어를 남발한다. | 플레이어가 위협을 보기 전에 멈춰 듣거나 되돌아본다. |
| Safe place erodes | 관리실, 복도, 엘리베이터 같은 기준점이 단계적으로 흔들린다. | 초반부터 모든 장소를 무력하고 무작위로 만든다. | 플레이어가 안전하다고 믿던 장소를 다시 확인한다. |
| 307 is the conclusion | 307호는 단일 방이 아니라 모든 민원과 기록 불일치가 모이는 결론이다. | 307호를 초반 점프스케어 장소로 소비한다. | 플레이어가 307호에 들어가기 전 이미 의미를 부여한다. |

## 4. Player Verbs

| Verb | 플레이어 행동 | 시스템 반응 | 목표 감정 | 통과 기준 |
| --- | --- | --- | --- | --- |
| 접수한다 | 관리실 단말, 무전, 쪽지에서 민원을 확인한다. | 위치, 증상, 우선도, 필요 도구 힌트가 열린다. | 업무 시작, 책임감 | 첫 1분 안에 다음 목적지를 이해한다. |
| 챙긴다 | 도구함에서 필요한 도구를 선택한다. | 인벤토리 제한과 되돌아갈 비용이 생긴다. | 작은 선택 부담 | 잘못 챙기면 동선 비용이 생기지만 즉시 실패하지 않는다. |
| 이동한다 | 복도, 계단, 엘리베이터, 지하실로 간다. | 조명, 문, 소리, 표지판 상태가 진행도에 따라 변한다. | 예감, 공간 기억 | 플레이어가 주요 반복 경로를 외운다. |
| 확인한다 | 문, 스위치, 배전반, 누수, 소리, 기록을 본다. | 단서가 정상 원인 또는 이상 징후로 분류된다. | 의심 | 플레이어가 정상/이상 판단을 설명할 수 있다. |
| 조치한다 | 수리, 차단, 재가동, 사진/기록, 보고 준비를 한다. | 현장 상태가 변하고 다음 정보가 열린다. | 안도 또는 찝찝함 | 완료 후에도 하나 이상의 미해결 감각이 남는다. |
| 보고한다 | 관리실에서 결과를 기록한다. | 다음 민원, 기록 모순, 307 단계가 갱신된다. | 의미 부여 | 보고가 단순 종료가 아니라 다음 불안의 시작으로 작동한다. |

## 5. Core Loop

### 루프 스케일

| 스케일 | 길이 | 내용 | 설계 목적 |
| --- | --- | --- | --- |
| Micro | 5~20초 | 문 확인, 소리 방향 확인, 스위치, 단서 줍기 | 순간 판단과 감각 반응 |
| Short | 1~3분 | 민원 접수에서 현장 도착까지 | 목적지 이해와 동선 긴장 |
| Medium | 5~10분 | 한 민원 해결과 보고 | 정상/이상 판정 경험 |
| Session | 15~40분 | 한 밤의 민원 묶음 | 307호와 건물 규칙 변화 체감 |
| Full Game | 목표 2~4시간 | 307호 진실과 마지막 보고 | 업무 루프 붕괴의 결론 |

### 한 민원 루프

| 단계 | 플레이어 목표 | 시스템 책임 | 실패/지연 처리 |
| --- | --- | --- | --- |
| 1. 접수 | 무엇을 해야 하는지 파악한다. | 민원 정보와 위치를 명확히 제시한다. | 목표를 못 찾으면 관리실 내 보조 힌트를 제공한다. |
| 2. 준비 | 필요한 도구를 고른다. | 접수 내용에서 도구 힌트를 준다. | 잘못 고르면 현장에서 되돌아가게 한다. |
| 3. 이동 | 현장에 도착한다. | 익숙한 경로와 작은 변화를 함께 제공한다. | 길찾기 실패는 표지판/조명으로 보정한다. |
| 4. 확인 | 단서를 찾는다. | 최소 단서와 선택 단서를 분리한다. | 필수 단서는 놓쳐도 다시 확인 가능해야 한다. |
| 5. 판정 | 정상 고장인지 이상 현상인지 판단한다. | 양쪽 해석이 가능한 정보를 제공한다. | 오판은 즉시 사망보다 기록/시간/긴장도 비용을 만든다. |
| 6. 조치 | 수리 또는 보고 준비를 한다. | 상태 변화를 눈/귀로 확인시킨다. | 조치 누락 시 다음 민원에서 압박으로 돌아온다. |
| 7. 보고 | 결과를 기록한다. | 다음 민원, 기록 모순, 307호 단계 갱신을 처리한다. | 보고 내용에 따라 후속 텍스트/사운드가 달라진다. |

## 6. Complaint And Anomaly Model

민원은 스토리 문장이 아니라 반복 제작 가능한 데이터 단위다.
모든 민원은 정상 원인과 이상 레이어를 분리해 작성한다.

| 필드 | 설명 |
| --- | --- |
| `ComplaintId` | 고유 ID. 예: `CMP_CH1_203_WaterAtDoor` |
| `DisplayTitle` | 플레이어에게 보이는 접수 제목 |
| `LocationId` | 현장 위치. 예: `L_2F_203Door`, `L_B1_PumpRoom` |
| `ShiftPhase` | 등장 가능한 진행 단계 |
| `RequiredTool` | 필요한 도구 또는 없음 |
| `NormalCause` | 현실적인 원인 |
| `AnomalyLayer` | 정상 원인 위에 얹히는 이상 징후 |
| `ClueList` | 필수/선택 단서 |
| `CompletionRule` | 해결 또는 보고 가능 조건 |
| `MisreportRule` | 오판/누락 시 결과 |
| `HorrorBeat` | 감정적으로 남겨야 하는 장면 |
| `ReuseAssets` | 재사용 가능한 프랍, 사운드, UI |
| `ValidationNote` | 플레이테스트에서 확인할 반응 |

### 민원 도메인

| 도메인 | 정상 원인 예시 | 이상 레이어 예시 | 역할 |
| --- | --- | --- | --- |
| 전기/조명 | 형광등, 차단기, 비상등 | 해결 후에도 특정 문틈만 어둡다. | 시야와 안전감 조절 |
| 물/배관 | 누수, 밸브, 펌프 | 물소리가 수리한 위치가 아닌 307호 쪽으로 이동한다. | 위치 불확실성 |
| 소리/진동 | TV, 인터폰, 배관음 | 같은 소리가 시간차로 복제된다. | 보이지 않는 존재감 |
| 기록/표기 | 이름표, 우편함, 단말 기록 | 307호가 비어 있는데 기록만 갱신된다. | 신뢰 붕괴 |
| 출입/공간 | 문잠김, 엘리베이터 오류 | 같은 복도가 한 번 더 이어지는 듯 보인다. | 공간 기억 오염 |

### P0 민원 세트

수직 슬라이스는 아래 3개 민원을 우선 구현한다.

| ID | 목적 | 정상 원인 | 이상 레이어 | 통과 기준 |
| --- | --- | --- | --- | --- |
| `CMP_PRO_OfficeLightBuzz` | 관리실 상호작용 튜토리얼 | 관리실 형광등 점멸 | 수리 후 관리실 단말에 접수 시간이 1분 어긋남 | 플레이어가 접수/도구/보고를 이해한다. |

## 7. Horror Rules

### 네 가지 불확실성

| 불확실성 | 사용법 | 금지선 |
| --- | --- | --- |
| 시간 | 언제 소리가 다시 날지, 언제 기록이 바뀔지 예측하기 어렵게 한다. | 완전 랜덤 반복으로 테스트 불가능하게 만들지 않는다. |
| 공간 | 소리와 흔적의 위치가 조금씩 이동한다. | 길찾기가 불가능한 미로를 만들지 않는다. |
| 정체 | 고장, 사람, 건물, 기록 오류 중 무엇인지 확정하지 않는다. | 답이 없는 척하다가 아무 설명도 남기지 않는다. |
| 행동 | 수리, 보고, 무시, 재확인 사이에서 고민하게 한다. | 정답을 알 수 없는 선택으로 즉시 실패시키지 않는다. |

### Agency 제한 규칙

| 허용 | 금지 |
| --- | --- |
| 문이 잠겨 우회 경로를 찾게 한다. | 입력을 갑자기 빼앗아 죽인다. |
| 손전등/조명이 약해져 시야가 줄어든다. | 예고 없이 화면을 장시간 가린다. |
| 관리실 지시가 모순되어 보고 판단을 요구한다. | 플레이어가 배운 규칙을 이유 없이 무효화한다. |
| 익숙한 복도에 미세한 차이를 넣는다. | 랜덤 워프처럼 공간 규칙을 완전히 부순다. |

## 8. Room 307 Escalation

307호는 초반 목표지가 아니라 누적되는 결론이다.

| Stage | 노출 방식 | 플레이어가 알아야 하는 것 | 사용 가능 민원 |
| --- | --- | --- | --- |
| 0. Absence | 307호는 지도/표지에 있으나 민원 없음 | 그냥 존재하는 방 | 없음 |
| 1. Number Echo | 기록, 우편함, 단말 시간에 307 숫자가 스친다. | 숫자가 반복된다. | 관리실/우편함 |
| 2. Record Mismatch | 공실인데 기록만 갱신된다. | 건물 기록을 믿기 어렵다. | 이름표, 단말 |
| 3. Sound Leak | 다른 민원 해결 후 소리가 307호 쪽에 남는다. | 정상 원인으로 설명되지 않는다. | 배관, TV, 인터폰 |
| 4. Route Bend | 3층 복도 이동 시 307호 앞 체류가 길어진다. | 공간이 307호를 중심으로 휘는 듯하다. | 조명, 엘리베이터 |
| 5. Threshold | 문 앞에서 생활감, 그림자, 내부 소리가 발생한다. | 들어가야 할 이유가 생긴다. | 307 택배/소음 |
| 6. Interior | 내부 진입, 마지막 보고, 결말 | 민원 루프가 붕괴한다. | 최종 점검 |

307호 연출은 직접 등장보다 "이미 해결한 민원이 끝나지 않았다"는 감각으로 연결한다.
