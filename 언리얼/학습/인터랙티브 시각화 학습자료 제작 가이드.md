# 인터랙티브 시각화 학습자료 제작 가이드

> [!summary] 요약
> 이 문서는 Unreal 학습자료를 HTML/CSS/JS로 만들거나 개선할 때 쓰는 시각화 기준이다.
> 단순 설명형 카드보다, 학습자가 조건을 바꾸고 결과를 즉시 확인할 수 있는 조작형 자료를 우선한다.

## 핵심 결론

- Markdown 원본 개편과 HTML 동기화는 별도 단계로 다룬다.
- HTML 학습자료는 텍스트 설명만 반복하지 말고 상태, 흐름, 조건, 결과를 시각화한다.
- 인터랙티브 예제는 `조작 입력 -> 시각 장면 -> 상태 요약 -> 결과 로그` 구조를 갖춘다.
- 디자인은 어둡고 주황색 계열의 Linux 개발자/터미널 느낌을 유지한다.
- 접근성, 반응형, reduced motion, 텍스트 겹침 방지를 필수 검증 항목으로 둔다.

## 개요

HTML 학습자료는 Markdown 원본을 그대로 꾸민 복사본이 아니라, 독자가 개념을 조작하고 결과를 관찰할 수 있게 만든 학습 도구이다.

특히 Unreal 개념은 상태, 소유권, 충돌, 경로, 평가 점수, 네트워크 실행 위치처럼 정적인 문장만으로 이해하기 어려운 경우가 많다. 이런 주제는 가능한 한 실제 게임 상황에 가까운 장면으로 보여준다.

## 기본 구조

좋은 조작형 자료는 다음 구조를 가진다.

| 구성 | 역할 | 예시 |
| --- | --- | --- |
| 조작 입력 | 학습자가 조건을 바꿈 | 버튼, 슬라이더, 토글, 세그먼트 컨트롤 |
| 시각 장면 | 상태 변화가 즉시 보임 | SVG 월드, 캐릭터, 패킷, 충돌 이펙트 |
| 상태 요약 | 현재 결과를 짧게 압축 | 실행 위치, 히트 순서, 점수, 선택된 분기 |
| 결과 로그 | 왜 그런 결과가 나왔는지 설명 | 이벤트 로그, 실패 이유, 조건 해석 |

## 공통 HTML 패턴

```html
<div class="interactive-lab topic-lab" data-topic-sim>
  <div class="lab-toolbar stacked-toolbar">
    <!-- controls -->
  </div>

  <div class="sim-workbench">
    <!-- scene -->
  </div>

  <div class="lab-state-row" aria-live="polite">
    <!-- state chips -->
  </div>

  <div class="event-log" data-topic-log>
    <!-- result explanation -->
  </div>
</div>
```

## 대표 시각화 패턴

### Trace와 Collision

- 발사 주체는 캐릭터, 무기, 센서처럼 실제 Trace Source로 표현한다.
- Line, Sphere, Capsule 등 검사 형태가 실제 경로로 보이게 한다.
- 충돌 지점은 객체 중심이 아니라 표면 ImpactPoint에 둔다.
- Overlap, Block, Ignore/필터 제외의 차이를 색과 텍스트로 함께 보여준다.
- Single/Multi 차이는 반환 수와 히트 순서로 보여준다.

> [!caution]
> SVG에서 `transform="translate(...)"`로 위치를 잡은 그룹에는 CSS `transform: scale(...)` 애니메이션을 직접 걸지 않는다. 위치 transform이 덮여 좌측 상단으로 튈 수 있다.

### 내적과 외적

- 수학 벡터 도형과 게임 예시를 함께 배치한다.
- 내적은 시야 원뿔, 정면/측면/후방 판정, 백어택, 조준 보정에 연결한다.
- 외적은 좌회전/우회전, 회전 보간 방향, 면적 또는 방향성 표시에 연결한다.
- 하나의 각도 슬라이더가 수학 도형과 게임 장면을 동시에 갱신하게 만든다.

### RPC와 네트워킹

- 서버, owning client, other client, owned pawn, world actor를 실제 객체처럼 배치한다.
- RPC 호출 시 패킷 또는 신호가 이동하는 경로를 보여준다.
- 호출한 머신, RPC 종류, actor ownership, 실행 위치, 차단 이유를 구분한다.
- 차단된 호출은 붉은 강조와 로그 설명을 함께 둔다.

### AI, EQS, Navigation

- Behavior Tree는 selector, sequence, task, decorator, service의 현재 상태를 보여준다.
- EQS는 candidate generation, test, score, selected item을 보여준다.
- Navigation은 path, link, area cost, filter, crowd/RVO avoidance를 보여준다.
- AI Perception은 listener, stimulus, sense, memory age, Blackboard update를 보여준다.

## 디자인 기준

- 배경은 어두운 갈색/검정 계열을 사용한다.
- 주황/앰버는 활성, 진행, 성공, 주요 경로에 사용한다.
- 붉은색은 차단, 실패, 위험, 잘못된 조건에 사용한다.
- 색상은 장식보다 상태 표현에 사용한다.
- 카드 안에 카드를 중첩하지 않는다.
- 텍스트가 버튼, 카드, SVG 라벨 밖으로 넘치지 않게 한다.

## 구현 기준

- 기존 `학습/HTML/styles.css` 공통 컴포넌트를 우선 재사용한다.
- `.interactive-lab`, `.lab-toolbar`, `.segmented-control`, `.mini-button`, `.primary-button`, `.metric-grid`, `.state-chip`, `.event-log` 패턴을 우선 사용한다.
- 버튼에는 `aria-pressed`를 반영한다.
- 동적으로 바뀌는 상태 요약에는 필요하면 `aria-live="polite"`를 사용한다.
- SVG에는 `role="img"`, `title`, `desc` 또는 `aria-label`을 제공한다.
- `prefers-reduced-motion` 환경에서 애니메이션을 줄인다.
- 모바일에서는 복잡한 그리드를 1열로 접는다.

## 검증 체크리스트

- [ ] 버튼, 슬라이더, 토글이 실제로 상태를 바꾼다.
- [ ] 시각 요소 위치가 실제 의미와 맞는다.
- [ ] 상태 칩과 로그가 현재 조건과 일치한다.
- [ ] 모바일 폭에서 그리드와 텍스트가 겹치지 않는다.
- [ ] 선택 상태가 `aria-pressed` 또는 적절한 상태 속성에 반영된다.
- [ ] 색상만으로 상태를 구분하지 않는다.
- [ ] CSS 애니메이션이 SVG 위치 transform을 덮어쓰지 않는다.
- [ ] 인라인 스크립트 문법 검사를 통과한다.

## 작업 지시 템플릿

```text
이 학습자료는 HTML + CSS 기반의 반응형 학습자료로 만들어줘.
단순 설명형 카드만 만들지 말고, 학습자가 직접 조작할 수 있는 interactive 시각 예제를 포함해줘.
디자인은 어둡고 주황색 계열의 Linux 개발자/터미널 느낌을 유지해줘.
개념은 실제 Unreal 게임 상황에 연결해서 캐릭터, 월드 오브젝트, 서버/클라이언트, Trace 발사/충돌 같은 장면으로 표현해줘.
조작에 따라 시각 장면, 상태 칩, 결과 로그가 함께 갱신되도록 구성해줘.
모바일에서도 텍스트와 도형이 겹치지 않게 반응형으로 검토해줘.
```
