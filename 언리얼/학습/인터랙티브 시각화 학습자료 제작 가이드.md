# 인터랙티브 시각화 학습자료 제작 가이드

이 문서는 Unreal 학습자료를 HTML + CSS로 만들거나 개선할 때 반복해서 참고하기 위한 작업 지시 기준이다.
단순 설명형 카드보다, 학습자가 직접 조건을 바꾸고 결과를 즉시 확인할 수 있는 조작형 시각 자료를 우선한다.

## 기본 방향

- 학습자료에는 가능하면 인터랙티브 예제를 포함한다.
- 개념 설명은 텍스트로 끝내지 않고, 실제 게임 상황에서 어떻게 쓰이는지 장면으로 보여준다.
- 시각화는 반응형이어야 하며, 모바일과 데스크톱에서 텍스트와 도형이 겹치지 않아야 한다.
- 디자인 톤은 어둡고 주황색 계열의 Linux 개발자/터미널 느낌을 유지한다.
- 색상은 장식보다 상태 표현에 쓴다.
  - 주황/앰버: 활성, 진행, 성공, 주요 경로
  - 붉은색: 차단, 실패, 위험, 잘못된 조건
  - 어두운 갈색/검정: 배경, 비활성 영역

## 인터랙티브 예제 원칙

좋은 조작형 자료는 다음 구조를 가진다.

1. 사용자가 조작할 수 있는 입력
   - 버튼, 슬라이더, 토글, 세그먼트 컨트롤을 사용한다.
   - 선택된 버튼에는 `is-selected` 또는 `aria-pressed` 상태를 반영한다.

2. 즉시 변하는 시각 장면
   - 선, 벡터, 객체, 캐릭터, 월드 오브젝트, 패킷, 충돌 이펙트 등이 실제로 움직이거나 강조된다.
   - 단순 박스/카드만 나열하지 않고, 가능하면 게임 월드에서의 의미가 보이도록 구성한다.

3. 상태 요약
   - `state-chip` 형태로 핵심 결과를 짧게 보여준다.
   - 예: 실행 위치, 히트 순서, 경로 처리, 시야 판정, 회전 방향

4. 로그 또는 결과 설명
   - 현재 조건에서 왜 그런 결과가 나왔는지 한두 줄로 설명한다.
   - 이벤트가 발생하면 로그 영역에 갱신 애니메이션을 줄 수 있다.

## 대표 패턴

### Trace 시각화

Trace 자료는 다음을 반드시 보여주는 것이 좋다.

- 발사 주체: 캐릭터, 무기, 센서 등 Trace Source를 명확히 표현한다.
- 발사 경로: Line/Sphere/Capsule 등 검사 모양이 실제 경로로 보이게 한다.
- 충돌 지점: 객체 중심이 아니라 표면 ImpactPoint에 마커와 이펙트를 둔다.
- 반응 차이:
  - Overlap: 감지되지만 통과
  - Block: 경로 정지
  - Ignore/필터 제외: 흐리게 처리하거나 결과에서 빠짐
- Single/Multi 차이:
  - Single은 반환 배열에 하나만 들어간다는 점을 강조한다.
  - Multi는 경로상 수집되는 순서를 보여준다.

주의할 점:

- SVG에서 `transform="translate(...)"`로 위치를 잡은 그룹에는 CSS `transform: scale(...)` 애니메이션을 직접 걸지 않는다.
  위치 transform이 덮여 좌측 상단으로 튀는 문제가 생길 수 있다.
- 히트 이펙트는 위치는 SVG attribute로 고정하고, CSS에서는 `opacity`, `stroke-width`, `stroke-opacity` 위주로 애니메이션한다.

### 내적과 외적

내적/외적 자료는 수학 도형만 보여주지 말고 게임 대표 사례를 함께 배치한다.

- 내적 대표 예시:
  - 시야 원뿔 판정
  - 정면/측면/후방 판정
  - 백어택 또는 후방 공격 판정
  - 조준 보정, 락온 가능 여부

- 외적 대표 예시:
  - 좌회전/우회전 방향 결정
  - 회전 보간 방향 선택
  - 벡터가 만드는 면적 또는 방향성 표시

추천 구성:

- 하나의 각도 슬라이더가 수학 벡터 도형과 게임 예시 장면을 동시에 갱신하게 만든다.
- Dot 값은 "앞/옆/뒤"처럼 해석을 붙인다.
- Cross Z 값은 "왼쪽/오른쪽/동일선"처럼 회전 방향으로 해석한다.

### RPC / 네트워킹

RPC 자료는 머신 카드만 배치하면 추상적이므로 실제 객체 느낌을 넣는다.

- Server는 서버 랙 또는 Authority 영역으로 표현한다.
- Owning Client는 캐릭터 또는 플레이어 아바타로 표현한다.
- Other Client는 관찰자 클라이언트로 표현한다.
- Actor 문맥은 Owned Pawn, World Door, Projectile 같은 실제 Actor 모습으로 표현한다.
- RPC 호출 시 패킷 또는 신호가 이동하는 애니메이션을 넣는다.
- 실패 조건은 패킷 차단, 붉은 강조, 로그 설명으로 보여준다.

반드시 구분할 것:

- 호출한 머신
- RPC 종류: Server, Client, NetMulticast, Remote
- Actor ownership
- 실제 실행 위치
- 호출이 차단되는 이유

## HTML/CSS 구현 기준

- 가능한 한 독립 실행 가능한 HTML + CSS + 최소 JS 구조로 만든다.
- 기존 `styles.css` 공통 컴포넌트를 우선 재사용한다.
- 카드 안에 카드를 중첩하지 않는다.
- 버튼은 고정 높이와 명확한 상태를 가진다.
- SVG나 장면 요소는 `viewBox`, `aspect-ratio`, `min-height`를 사용해 반응형으로 만든다.
- 모바일에서는 복잡한 그리드를 1열로 접는다.
- 텍스트가 버튼, 카드, SVG 라벨 밖으로 넘치지 않게 한다.
- `prefers-reduced-motion` 환경에서는 애니메이션이 과도하게 동작하지 않도록 한다.

## 접근성 및 상태 관리

- 조작 버튼에는 `aria-pressed`를 반영한다.
- 동적으로 바뀌는 상태 요약 영역에는 필요하면 `aria-live="polite"`를 사용한다.
- SVG에는 `role="img"`, `title`, `desc` 또는 `aria-label`을 제공한다.
- 색상만으로 상태를 구분하지 말고 텍스트 라벨도 함께 제공한다.

## 검증 체크리스트

작업 후 최소한 다음을 확인한다.

- 주요 HTML의 인라인 스크립트 문법이 깨지지 않았는가?
- 버튼, 슬라이더, 토글이 실제로 상태를 바꾸는가?
- 시각 요소 위치가 실제 의미와 맞는가?
  - Trace는 총구에서 출발하는가?
  - 충돌 이펙트는 객체 중심이 아니라 표면에 있는가?
  - RPC 패킷은 호출 조건과 실행 위치를 반영하는가?
- 모바일 폭에서 그리드와 텍스트가 겹치지 않는가?
- 선택 상태와 로그가 현재 조건과 일치하는가?
- CSS 애니메이션이 SVG 위치 transform을 덮어쓰지 않는가?

## 작업 지시 템플릿

새 학습자료를 만들거나 기존 자료를 개선할 때 아래 문장을 함께 지시하면 된다.

```text
이 학습자료는 HTML + CSS 기반의 반응형 학습자료로 만들어줘.
단순 설명형 카드만 만들지 말고, 학습자가 직접 조작할 수 있는 Interactive 시각 예제를 포함해줘.
디자인은 어둡고 주황색 계열의 Linux 개발자/터미널 느낌을 유지해줘.
개념은 실제 Unreal 게임 상황에 연결해서 캐릭터, 월드 오브젝트, 서버/클라이언트, Trace 발사/충돌 같은 장면으로 표현해줘.
조작에 따라 시각 장면, 상태 칩, 결과 로그가 함께 갱신되도록 구성해줘.
모바일에서도 텍스트와 도형이 겹치지 않게 반응형으로 검토해줘.
```

## 기존 개선 사례 기준

- Trace: 총구에서 Trace가 발사되고, Glass/Pawn/Wall 표면의 ImpactPoint에서 반응 이펙트가 발생해야 한다.
- 내적/외적: 각도 슬라이더가 벡터 도형뿐 아니라 시야 원뿔, 백어택, 회전 방향 예시를 동시에 갱신해야 한다.
- RPC: 서버/클라이언트 카드를 나열하는 대신, 서버 랙, 캐릭터, Owned Pawn, World Door 같은 실제 객체 장면으로 표현해야 한다.
