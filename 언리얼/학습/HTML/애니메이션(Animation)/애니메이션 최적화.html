애니메이션 최적화

애니메이션 최적화의 핵심은 매 Tick마다 Game Thread에서 실행되는 작업을 줄이고, 가능한 연산을 Worker Thread와 엔진 내부 복사 경로로 옮기는 것입니다. Thread Safe 함수, Property Access, Animation Fast Path, URO, Animation Budget Allocator를 함께 이해해야 합니다.

원본: 애니메이션(Animation)/애니메이션 최적화.md 난이도: 중급 퍼포먼스 핵심: Thread Safe Update, Property Access, Fast Path, URO, Budget Allocator 검수 기준: Unreal Engine 5.7.4

최적화 목표

공식 문서 기준으로 Animation System의 성능은 Game Thread와 Worker Thread가 각 Tick에서 애니메이션을 처리하는 데 걸리는 시간으로 판단합니다. AnimGraph의 블렌딩, IK, 피직스, 커브, Notify, Event Graph 로직은 모두 비용을 만듭니다.

가장 먼저 줄일 것

일반적으로 Animation Blueprint에서 가장 비싼 작업은 Event Graph 로직입니다. Event Graph는 Game Thread에서 순차 실행되므로, 매 Tick 수행되는 캐릭터 참조, 캐스팅, 계산, 블루프린트 함수 호출을 줄이는 것이 우선입니다.

비용 영역 최적화 방향
Event Graph Thread Safe 함수와 Property Access로 이동하고, 외부 오브젝트 직접 접근을 줄입니다.
AnimGraph 변수 접근 Blueprint VM 호출이 생기지 않도록 Fast Path 가능한 형태로 단순화합니다.
먼 캐릭터 Update Rate Optimization 또는 Animation Budget Allocator로 평가 빈도를 낮춥니다.
Bounds / Physics 불필요한 Physics Asset 기반 Bounds 재계산과 피직스 업데이트를 줄입니다.

멀티 스레드 애니메이션 업데이트

Animation Blueprint의 Event Graph는 항상 Game Thread에서 실행됩니다. Worker Thread를 활용하려면 Tick마다 필요한 계산을 Blueprint Thread Safe Update Animation 오버라이드와 Thread Safe 함수로 옮기고, 외부 데이터 접근은 Property Access를 통해 읽어야 합니다.

Blueprint Thread Safe Update Animation

AnimBP의 Thread Safe 업데이트 진입점입니다. Tick마다 필요한 변수 계산을 여기로 옮깁니다.

Thread Safe 함수

함수 Details에서 Thread Safe를 켠 블루프린트 함수입니다. 스레드 안전하지 않은 객체 직접 접근은 피해야 합니다.

Property Access

Thread Safe 함수에서 외부 Blueprint, Component, 변수 데이터를 안전하게 읽기 위한 접근 경로입니다.

데이터 방향

외부 Actor가 AnimBP에 값을 밀어 넣는 방식보다, AnimBP가 필요한 데이터를 안전하게 읽는 방향이 스레드 안전성에 맞습니다.

Animation Fast Path

Animation Fast Path는 AnimGraph 업데이트에서 Blueprint VM을 호출하지 않고 엔진이 값을 내부적으로 복사하게 만드는 최적화 경로입니다. 멤버 변수, 부정된 bool 변수, 중첩 구조체 멤버처럼 단순 접근은 Fast Path가 가능하지만, 그래프 안에서 계산 함수를 끼워 넣으면 Fast Path가 깨질 수 있습니다.

가능한 형태 피해야 할 형태
멤버 변수 직접 읽기 AnimGraph 핀에서 곱하기, 함수 호출, 캐스팅 수행
부정된 bool 멤버 변수 조건 계산을 핀 근처에서 매번 구성
Split Struct Pin으로 중첩 구조체 멤버 읽기 Break Transform처럼 내부 변환이 들어가는 Break 노드 남용

컴파일러 경고 켜기

Warn About Blueprint Usage를 AnimBP Class Settings의 Optimization에서 켜면, AnimGraph에서 Blueprint VM 호출이 필요한 지점이 Compiler Results에 경고로 표시됩니다.

URO와 Animation Budget Allocator

캐릭터 수가 많아지면 모든 Skeletal Mesh를 매 프레임 같은 품질로 평가할 수 없습니다. 원본 노트와 공식 문서 모두 거리와 중요도에 따라 평가 빈도를 낮추는 접근을 권장하며, URO보다 Animation Budget Allocator 플러그인을 사용하는 쪽을 더 현대적인 선택지로 제시합니다.

기능 역할 적용 기준
URO Skeletal Mesh Component의 애니메이션 업데이트/평가 빈도를 낮춥니다. 먼 캐릭터를 15Hz 이하로 낮추는 식의 직접 제어가 필요할 때 사용합니다.
Animation Budget Allocator 전역 애니메이션 CPU 예산 안에서 중요도 기반으로 Tick Rate와 보간 여부를 동적으로 조정합니다. 다수 캐릭터가 등장하고 플랫폼별 예산을 관리해야 할 때 우선 검토합니다.
Fixed Skel Bounds Physics Asset을 사용한 Bounds 계산 대신 Skeletal Mesh의 고정 Bounds를 사용합니다. 캐릭터가 피직스 에셋 기반 Bounds 갱신이 필요 없을 때 켭니다.

5.7.4 API 확인

5.7 Python API 기준으로 SkeletalMeshComponentBudgeted는 AnimationBudgetAllocator 플러그인에 속하며, auto_calculate_significance와 auto_register_with_budget_allocator 같은 예산 시스템 관련 속성을 제공합니다.

프로파일링할 때 볼 것

  • Rewind Debugger로 PIE 구간을 기록하고 애니메이션 변수, 평가 흐름, Notify 타이밍을 확인합니다.
  • Animation Insights에서 Game Thread와 Worker Thread 작업이 어떻게 나뉘는지 봅니다.
  • FParallelAnimationCompletionTask가 Main Thread에 크게 보이면 Physics, Notify, URO 보간, Curve 블렌딩 비용을 분해합니다.
  • Blueprint Notify는 Blueprint VM 호출을 만들 수 있으므로, 자주 발생하는 Notify는 가능하면 네이티브 기반으로 처리합니다.
  • Root Motion이 Character Movement에 필요하면 병렬 업데이트가 제한될 수 있습니다.
  • Cloth, Rigid Body Anim Node, Morph Target, Curve 평가가 실제로 필요한 컴포넌트에만 켜져 있는지 확인합니다.

복습 질문

Q1. Event Graph 로직을 줄이는 것이 중요한 이유는?

Event Graph는 Game Thread에서 Tick마다 순차 실행되므로, 캐릭터 수가 늘수록 병목이 되기 쉽습니다.

Q2. Thread Safe 함수에서 외부 객체를 직접 접근하면 안 되는 이유는?

Worker Thread에서 평가될 수 있으므로 스레드 안전하지 않은 Blueprint나 Component 접근은 데이터 경합과 크래시 위험을 만들 수 있습니다. Property Access를 사용해야 합니다.

Q3. Fast Path가 깨지는 대표적인 상황은?

AnimGraph 핀에서 변수를 직접 읽는 대신 계산 함수, 곱셈, 변환 노드처럼 Blueprint VM 호출이 필요한 로직을 추가하는 경우입니다.
