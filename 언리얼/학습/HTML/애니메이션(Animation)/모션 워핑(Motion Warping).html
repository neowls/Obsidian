Animation / Root Motion

모션 워핑(Motion Warping)

Motion Warping은 Root Motion 애니메이션의 이동과 회전을 런타임 타깃에 맞게 보정하는 기능입니다. 넘기, 문 열기, 암살, 점프 착지처럼 "애니메이션은 정해져 있지만 실제 목표 위치는 매번 달라지는" 상황에서 사용합니다.

원본: 애니메이션(Animation)/모션 워핑(Motion Warping).md 원본 상태: 개요 제목만 존재 핵심: Root Motion, Motion Warping Component, Warp Target, Notify Window 검수 기준: Unreal Engine 5.7.4

Motion Warping 궤적 실험판

원본 Root Motion은 정해진 거리로 움직이지만, Motion Warping은 Notify Window 동안 목표 지점에 맞도록 이동 궤적과 회전을 보정합니다. Target 위치를 바꿔 원본 경로와 보정 경로를 비교하세요.

원본 도착 거리180cm애니메이션에 baked된 이동량
Target 거리220cm런타임 상호작용 지점
회전 보정20도타깃 방향으로 루트 회전 보정
주의적정차이가 너무 크면 새 애니메이션 후보가 낫습니다.

한 줄 정의

Motion Warping은 애니메이션 몽타주의 특정 시간 구간에서 Root Motion을 목표 지점에 맞게 변형하는 시스템입니다. 애니메이션 원본이 "앞으로 180cm 이동"하도록 만들어졌더라도, 런타임에는 실제 문턱, 적, 난간 위치에 맞춰 루트 이동량과 회전을 보정할 수 있습니다.

Motion Matching과 구분

Motion Matching은 "어떤 포즈를 선택할지"를 결정하고, Motion Warping은 "선택된 Root Motion을 어디에 맞출지"를 보정합니다. 둘은 경쟁 관계가 아니라, 데이터 기반 선택과 목표 정렬을 나누어 맡는 관계로 사용할 수 있습니다.

시각화 요약: Root Motion을 목표에 맞추는 경로

Root Motion Montage 원본 애니메이션의 루트 이동과 회전이 기준이 됩니다.
Notify Window 보정할 시간 구간과 Modifier 타입을 지정합니다.
Warp Target 난간, 적, 상호작용 지점 같은 목표 위치와 회전을 등록합니다.
MotionWarpingComponent Montage 구간과 Target 이름을 매칭해 보정 작업을 생성합니다.
Root Motion Modifier Skew, Scale, Rotation 방식으로 루트 이동량을 변형합니다.
Aligned Motion 캐릭터가 애니메이션을 유지하면서 목표 지점에 자연스럽게 도착합니다.

기본 구성 순서

1 플러그인 활성화 Motion Warping 플러그인을 켜고 에디터를 재시작합니다.
2 컴포넌트 추가 Character 또는 Pawn에 MotionWarpingComponent를 추가합니다.
3 Root Motion 준비 Root Motion이 들어 있는 Montage 또는 Animation을 사용합니다.
4 Notify Window 설정 몽타주 구간에 AnimNotifyState_MotionWarping을 배치합니다.
5 Warp Target 등록 블루프린트에서 같은 이름의 타깃 위치/회전을 등록하고 몽타주를 재생합니다.
구성 요소 역할
MotionWarpingComponent Warp Target을 보관하고 활성 Root Motion Modifier를 업데이트합니다. 5.7 API 기준으로 타깃 추가, 갱신, 제거 함수가 제공됩니다.
MotionWarpingTarget 월드 정렬 지점입니다. 이름, 위치, 회전, 컴포넌트, 본 이름, 컴포넌트 추적 여부, 오프셋을 가질 수 있습니다.
AnimNotifyState_MotionWarping 애니메이션 안에서 실제 워핑이 적용될 시간 구간을 정의합니다. 타깃 이름과 워핑 방식이 여기에서 연결됩니다.
RootMotionModifier Notify Window가 활성화될 때 루트 모션을 어떤 방식으로 변형할지 처리하는 내부 단위입니다.

Warp Target 등록 방식

공식 5.7 Python API 기준으로 MotionWarpingComponent는 위치, 위치+회전, Transform, Component 기반으로 Warp Target을 추가하거나 갱신할 수 있습니다. 중요한 것은 Notify Window의 Warp Target Name과 블루프린트에서 등록한 이름이 정확히 같아야 한다는 점입니다. 

// Blueprint 흐름을 C++ 의사 코드처럼 표현
MotionWarpingComponent->AddOrUpdateWarpTargetFromTransform(
    WarpTargetName = "VaultTarget",
    TargetTransform = LedgeTransform
);

PlayAnimMontage(VaultMontage);

Location 타깃

회전은 유지하고 위치만 맞추고 싶을 때 적합합니다. 단순한 점프 착지나 발판 맞춤에 사용하기 쉽습니다.

Location + Rotation 타깃

상호작용 대상의 방향까지 맞춰야 할 때 사용합니다. 문 열기, 처형 애니메이션, 장치 조작에 자주 맞습니다.

Component 타깃

움직이는 대상이나 소켓을 따라가야 할 때 사용합니다. follow_component를 켜면 워핑 중에도 갱신됩니다.

Remove 타깃

상호작용이 끝났거나 중단된 경우 타깃을 제거합니다. 재사용 캐릭터에서 오래된 타깃이 남지 않도록 정리합니다.

워핑 방식 선택 감각

방식 사용 감각 주의점
Skew Warp 루트 모션의 경로를 기울여 목표 위치와 회전에 맞춥니다. 원본 애니메이션과 목표가 너무 멀면 발 미끄러짐이나 자세 왜곡이 커집니다.
Scale 루트 이동량을 스케일링해 더 짧거나 긴 거리로 맞춥니다. 거리 차이가 클수록 애니메이션 속도감이 부자연스러워질 수 있습니다.
Adjustment Blend Warp API 목록에는 존재하지만 5.7 플러그인 API에서 실험 성격이 표시됩니다. 프로덕션 핵심 흐름은 안정적인 방식으로 먼저 구성하고, 실험 기능 의존은 문서화합니다.

자주 틀리는 부분

  • Motion Warping은 일반 In-Place 애니메이션을 마법처럼 이동시키는 기능이 아닙니다. Root Motion 구간이 있어야 보정할 이동량이 있습니다.
  • Warp Target 이름이 Notify Window의 이름과 다르면 워핑이 적용되지 않습니다.
  • 타깃 등록은 워핑 창이 시작되기 전에 끝나야 합니다. 몽타주를 먼저 재생하고 뒤늦게 타깃을 넣으면 첫 구간이 어긋날 수 있습니다.
  • 컴포넌트 추적 타깃은 틱 순서 영향을 받습니다. 대상 Actor가 나중에 틱되면 한 프레임 늦을 수 있으므로 Tick Prerequisite을 검토합니다.
  • 목표 위치가 원본 애니메이션 이동 범위와 너무 다르면 보정보다 새 애니메이션 또는 다른 상호작용 지점이 필요합니다.
  • 네트워크 게임에서는 서버 권한, 몽타주 재생, 타깃 Transform 복제 방식이 일관되어야 합니다.

복습 질문

Q1. Motion Warping을 쓰기 전에 애니메이션에서 반드시 확인할 것은?

워핑할 구간에 Root Motion이 있는지, 몽타주 또는 애니메이션에서 Motion Warping Notify Window가 올바른 시간에 배치되어 있는지 확인합니다.

Q2. Warp Target Name이 중요한 이유는?

Notify Window가 참조하는 이름과 컴포넌트에 등록한 타깃 이름이 일치해야 해당 구간의 루트 모션을 목표 지점으로 보정할 수 있습니다.

Q3. 움직이는 대상에 붙는 워핑은 어떤 타깃 등록 방식을 고려해야 하는가?

Component 기반 타깃과 follow_component 사용을 고려합니다. 다만 틱 순서로 한 프레임 오차가 생길 수 있어 필요하면 Tick Prerequisite을 설정합니다.
