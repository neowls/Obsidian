Networking / Replication

리플리케이션(Replication)

Replication은 서버가 가진 authoritative state를 각 클라이언트의 Actor 복사본에 동기화하는 시스템입니다. 함수 호출이 아니라 상태 동기화이며, 나중에 접속한 플레이어도 현재 서버 상태를 받을 수 있다는 점이 RPC와 다릅니다.

원본: 리플리케이션(Replication).md 난이도: 중급 네트워크 상태 동기화 핵심: DOREPLIFETIME, RepNotify, Relevancy, Dormancy, Fast Array 검수 기준: Unreal Engine 5.7.4

Replication 전송 실험판

Replication은 서버 값이 바뀌었다고 즉시 모든 클라이언트에 가는 기능이 아닙니다. Net Tick 때 connection별 relevancy, condition, dormancy를 통과한 값만 클라이언트 복사본에 도착합니다.

Replication 한 줄 정의

Replication은 서버의 현재 Actor 상태를 connection별 relevancy, priority, dormancy, update frequency 조건에 따라 클라이언트로 보내는 시스템입니다. 서버가 바꾼 값만 의미가 있고, 클라이언트가 replicated 변수를 직접 바꿔도 서버 상태는 바뀌지 않습니다.

RPC와의 경계

Health = 42, bIsOpen = true처럼 현재 상태는 Replication입니다. ServerTryOpenDoor(), ClientShowHitMarker()처럼 요청과 순간 응답은 RPC입니다.

시각화 요약: 서버 상태가 클라이언트에 보이는 과정

Server Actor 권위 있는 상태가 바뀝니다. 클라이언트 로컬 변경은 기준 상태가 아닙니다.
NetDriver Connection별로 복제 대상 Actor를 평가합니다.
Relevancy / Dormancy 거리, 소유권, dormancy, update frequency 조건으로 전송 여부를 줄입니다.
Actor Channel RepLayout과 condition에 맞는 변경 property를 보냅니다.
Client OnRep 클라이언트 값이 갱신되고 RepNotify에서 UI나 연출을 반영합니다.

가장 기본적인 Property Replication

공식 5.7 문서 기준 replicated property는 Replicated 또는 ReplicatedUsing specifier로 표시하고, GetLifetimeReplicatedProps에서 DOREPLIFETIME 계열 매크로로 등록합니다. 

// MyActor.h
UCLASS()
class AMyActor : public AActor
{
    GENERATED_BODY()

public:
    AMyActor();

    UPROPERTY(ReplicatedUsing=OnRep_Health)
    int32 Health = 100;

    UFUNCTION()
    void OnRep_Health(int32 OldHealth);

    virtual void GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const override;
};

// MyActor.cpp
#include "Net/UnrealNetwork.h"

AMyActor::AMyActor()
{
    bReplicates = true;
}

void AMyActor::GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const
{
    Super::GetLifetimeReplicatedProps(OutLifetimeProps);
    DOREPLIFETIME(AMyActor, Health);
}
요소 빠지면 생기는 문제
bReplicates = true Actor가 네트워크 복제 대상이 되지 않습니다.
UPROPERTY(Replicated) 리플렉션 시스템이 이 변수를 replicated property로 알지 못합니다.
GetLifetimeReplicatedProps 어떤 property를 어떤 조건으로 보낼지 등록되지 않습니다.
DOREPLIFETIME 해당 property가 lifetime replication list에 들어가지 않습니다.

RepNotify와 조건

ReplicatedUsing은 값이 클라이언트에 도착했을 때 OnRep 함수를 실행합니다. OnRep는 서버에서 대입하는 순간 자동 호출되는 서버 콜백이 아니라, 수신 후처리입니다.

REPNOTIFY_OnChanged

기본 동작입니다. 수신 측 기존 값과 다를 때만 OnRep가 호출됩니다.

REPNOTIFY_Always

값 차이와 무관하게 property가 복제될 때마다 OnRep를 호출합니다.

이전 값 파라미터

OnRep_Health(int32 OldHealth)처럼 같은 타입 파라미터를 받으면 이전 값을 받을 수 있습니다.

서버 로컬 처리

서버에서도 UI나 로컬 후처리가 필요하면 상태 변경 직후 직접 함수를 호출해야 합니다.

Condition 사용 감각
COND_None relevant한 모든 connection에 보냅니다.
COND_InitialOnly 초기 복제 때만 필요한 설정값에 사용합니다.
COND_OwnerOnly 개인 HUD, 개인 리소스처럼 owner에게만 필요한 값에 사용합니다.
COND_SkipOwner owner는 이미 예측/로컬 처리했고 다른 클라이언트만 알아야 할 때 사용합니다.
COND_SimulatedOnly simulated proxy에게만 필요한 보정값에 사용합니다.
COND_Dynamic 런타임에 조건 자체를 바꿔야 하는 고급 상황에서만 신중하게 사용합니다.

Actor Replication 흐름

5.7의 Detailed Actor Replication Flow 문서 기준으로, 대부분의 Actor 복제는 NetDriver가 복제 대상 Actor를 고르고, connection별 relevancy와 priority를 판단한 뒤 UActorChannel::ReplicateActor가 실제 Actor와 Component property를 보냅니다.

1 대상 선별 SetReplicates(true), dormancy, update frequency를 확인합니다.
2 PreReplication 복제 직전 값 계산과 active override를 처리합니다.
3 Connection별 검사 level loaded, relevancy, dormancy, channel 상태를 봅니다.
4 Priority 정렬 연결이 포화될 수 있으므로 우선순위가 높은 Actor부터 처리합니다.
5 ReplicateActor Actor, Component, subobject의 변경 property를 전송합니다.

Relevancy, Frequency, Dormancy

개념 질문 대표 설정/API
Relevancy 이 Actor를 이 connection에 지금 보낼 가치가 있는가? IsNetRelevantFor, bAlwaysRelevant, bOnlyRelevantToOwner, NetCullDistanceSquared
Frequency 이 Actor가 얼마나 자주 복제 기회를 얻는가? NetUpdateFrequency, MinNetUpdateFrequency, ForceNetUpdate
Dormancy 한동안 바뀌지 않는 Actor를 네트워크 비용에서 쉬게 할 것인가? SetNetDormancy, FlushNetDormancy, ForceNetUpdate

Dormant Actor 실수

dormant Actor의 replicated property를 바꾸고 깨우지 않으면 클라이언트가 새 값을 받지 못할 수 있습니다. 문, 상자, 채집물처럼 자주 안 바뀌는 Actor는 dormancy와 ForceNetUpdate 호출 타이밍을 함께 설계합니다.

고급 Replication 선택지

Push Model

bIsPushBased = true로 등록하고 변경 시 dirty mark합니다. 큰 데이터에서 비교 비용을 줄일 수 있지만 dirty mark 누락이 곧 버그입니다.

Fast Array

큰 TArray<UStruct>의 add/remove/change를 delta로 보내는 패턴입니다. 인벤토리, 버프 목록, ability spec list에 적합합니다.

Component Replication

Actor가 replicate하고 Component도 replicate 설정되어야 합니다. Component는 자신의 property와 RPC, subobject를 가질 수 있습니다.

Registered Subobject List

UObject subobject를 Actor/Component 아래에서 복제할 때 현대적인 등록 리스트 방식을 우선 검토합니다.

복습 질문

Q1. OnRep가 서버에서 자동 호출되지 않는 이유는?

OnRep는 클라이언트가 replicated property를 수신했을 때의 후처리이기 때문입니다. 서버 로컬 후처리는 직접 호출해야 합니다.

Q2. UPROPERTY(Replicated)만 붙였는데 값이 안 가는 대표 원인은?

bReplicates 누락, GetLifetimeReplicatedProps 등록 누락, relevancy 없음, dormancy, 서버가 생성한 Actor가 아님 등이 있습니다.

Q3. 큰 인벤토리 배열에 Fast Array를 검토하는 이유는?

배열 전체가 아니라 item add/remove/change를 delta로 보내고 콜백을 받을 수 있어 큰 배열의 변경 전송에 유리하기 때문입니다.
