Gameplay Ability System

게임플레이 이펙트의 생성 과정

Gameplay Effect는 GE 자산을 바로 대상에게 던지는 방식이 아니라, 실행 문맥인 Context와 런타임 인스턴스인 Spec을 만든 뒤 ASC에 적용됩니다. 이 순서를 이해하면 SetByCaller, HitResult, SourceObject, 투사체 전달 흐름이 훨씬 명확해집니다.

원본: 게임 어빌리티 시스템(GAS)/게임플레이 이펙트의 생성 과정.md 난이도: GE 적용 흐름 핵심: ContextHandle, SpecHandle, MakeOutgoingSpec 검수 기준: Unreal Engine 5.7.4

한 줄 정의

GE 생성 과정은 “Context를 만들고, 그 Context로 Spec을 만든 뒤, Spec을 ASC에 적용하는 과정”입니다. GE 자산은 설계 데이터이고, 실제 적용 단위는 FGameplayEffectSpec입니다.

GameplayEffectContext

누가 만들었는지, 어떤 수단으로 만들었는지, 어떤 HitResult나 TargetData가 있는지 담는 실행 문맥입니다.

GameplayEffectContextHandle

Context를 직접 들고 다니지 않고 GAS가 핸들로 간접 관리하기 위한 포장 객체입니다.

GameplayEffectSpec

GE 자산에서 만들어지는 런타임 적용 정보입니다. 레벨, Modifier Magnitude, 태그, ContextHandle을 담습니다.

GameplayEffectSpecHandle

Spec을 안전하게 전달하고 유효성을 검사하기 위한 핸들입니다. 적용 전 SetByCaller 값을 추가할 수 있습니다.

생성 순서

순서는 중요합니다. Spec이 ContextHandle을 포함하므로, 먼저 Context를 만들고 필요한 정보를 채운 뒤 Spec을 생성해야 합니다.

1. Context 문맥 생성 MakeEffectContext로 ContextHandle을 만듭니다.
2. Data 추가 정보 기록 SourceObject, Instigator, Causer, HitResult, TargetData 등을 넣습니다.
3. Spec Spec 생성 MakeOutgoingSpec으로 GE 클래스, 레벨, Context를 묶습니다.
4. Runtime 런타임 값 보강 SetByCaller, Dynamic Tag, Stack 같은 적용 직전 값을 넣을 수 있습니다.
5. Apply ASC에 적용 Self 또는 Target ASC에 Spec을 적용하고 결과 Handle을 받습니다.

Context와 Spec의 책임 분리

구분 담는 정보 대표 사용처
Context Instigator, EffectCauser, SourceObject, HitResult, TargetData 누가 어떤 상황에서 이 효과를 만들었는지 Execution, Cue, AttributeSet에서 참조합니다.
Spec GE 클래스, 레벨, 계산된 Modifier, SetByCaller, 동적 태그, ContextHandle 실제 대상 ASC에 적용되는 런타임 GE 인스턴스 역할을 합니다.
Active GE 대상 ASC에 적용되어 유지 중인 Spec, 남은 시간, 스택 상태 Duration 또는 Infinite GE가 적용된 후 ASC의 ActiveGameplayEffects에 보관됩니다.

기본 코드 흐름

원본 노트의 코드는 자기 자신에게 GE를 적용하는 가장 기본적인 형태입니다. 타겟에게 적용할 때는 마지막 단계에서 대상 ASC의 ApplyGameplayEffectSpecToSelf 계열 함수를 호출한다고 보면 됩니다. 

FGameplayEffectContextHandle EffectContextHandle = ASC->MakeEffectContext();
EffectContextHandle.AddSourceObject(this);

FGameplayEffectSpecHandle EffectSpecHandle =
    ASC->MakeOutgoingSpec(EffectToApply, 1.0f, EffectContextHandle);

if (EffectSpecHandle.IsValid())
{
    ASC->BP_ApplyGameplayEffectSpecToSelf(EffectSpecHandle);
}

확장 지점

충전 시간, 타겟팅 결과, 무기 데이터처럼 실행 중에 결정되는 값은 Spec 생성 후 적용 전에 SetByCaller나 Context의 SourceObject/HitResult를 통해 전달하는 식으로 설계합니다.

5.7 어빌리티 헬퍼 기준으로 읽기

UGameplayAbility에는 make_outgoing_gameplay_effect_spec, apply_gameplay_effect_spec_to_owner, apply_gameplay_effect_spec_to_target 같은 Spec 생성/적용 헬퍼가 제공됩니다. 핵심은 적용 전에 Spec이 유효한지 확인하고, SetByCaller 같은 런타임 값은 Apply 전에 채워야 한다는 점입니다.

자주 헷갈리는 지점

GE 자산과 Spec은 다릅니다

GE 자산은 기본 규칙입니다. Spec은 그 규칙을 특정 레벨, 특정 문맥, 특정 런타임 값으로 적용하기 위해 만든 객체입니다.

Context를 나중에 끼워 넣는 구조가 아닙니다

Spec이 ContextHandle을 포함하므로 Context를 먼저 만들고 필요한 문맥을 채운 뒤 Spec을 만드는 흐름을 기본으로 잡아야 합니다.

상황 어디에 넣을까? 이유
이 효과를 발생시킨 무기 Context의 SourceObject 또는 EffectCauser ExecutionCalculation, Cue, AttributeSet에서 원인 객체를 참조할 수 있습니다.
라인 트레이스 적중 정보 Context의 HitResult 또는 TargetData GameplayCue 위치, 헤드샷 판정, 물리 표면 반응에 활용할 수 있습니다.
충전 시간 기반 피해량 Spec의 SetByCaller GE 자산에는 고정할 수 없는 런타임 수치이기 때문입니다.
스킬 레벨 MakeOutgoingSpec의 Level ScalableFloat와 레벨 기반 Modifier 계산에 사용됩니다.

복습 질문

1. GE 적용 전에 Context를 먼저 만드는 이유는?

정답: Spec이 ContextHandle을 포함하므로, 적용 문맥을 먼저 만든 뒤 그 문맥으로 Spec을 생성해야 합니다.

2. GameplayEffectSpec은 무엇인가?

정답: GE 자산을 특정 레벨, 문맥, 런타임 값으로 적용하기 위해 만든 런타임 적용 정보입니다.

3. HitResult는 Context와 Spec 중 어디에 가까운가?

정답: Context입니다. 적중 위치와 판정 정보는 효과가 발생한 문맥에 해당합니다.

4. Spec을 만든 후 적용 전에 할 수 있는 대표 작업은?

정답: SetByCaller 값 추가, 동적 태그 추가, 적용 전 유효성 검사를 할 수 있습니다.
