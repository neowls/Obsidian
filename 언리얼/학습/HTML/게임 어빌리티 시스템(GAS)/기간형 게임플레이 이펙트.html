Gameplay Ability System

기간형 게임플레이 이펙트

기간형 Gameplay Effect는 한 프레임에 끝나는 효과가 아니라 ASC에 일정 시간 또는 무기한 남아 상태를 표현합니다. 버프, 디버프, 쿨다운, 기절, 이동속도 변화처럼 "유지되는 규칙"을 설계할 때 핵심이 됩니다.

원본: 게임 어빌리티 시스템(GAS)/기간형 게임플레이 이펙트.md 난이도: GE 지속/스택 핵심: Active GE, CurrentValue, Stack, Period 검수 기준: Unreal Engine 5.7.4

Duration GE 스택/주기 실험판

기간형 GE는 Active 상태로 남아 남은 시간, 스택 수, Period 실행을 함께 관리합니다. 독 효과를 예로 들어 스택과 주기 피해가 어떻게 연결되는지 확인하세요.

Health 100
Poison Stack 0 / 5
Remaining Duration 0s

Poison을 적용하면 스택이 늘고 5초로 시간이 갱신됩니다. Tick마다 Stack x 4 피해가 들어갑니다.

한 줄 정의

기간형 GE는 Instant가 아닌 GE, 즉 HasDuration 또는 Infinite 정책으로 ASC에 남아 있는 Gameplay Effect입니다. ASC에 Active Gameplay Effect로 보관되는 동안 Attribute Modifier, Granted Tag, Gameplay Cue, Stack Count 같은 상태를 유지합니다.

Instant와 기간형의 가장 큰 차이

일반적인 Attribute Modifier 기준으로 Instant GE는 즉시 BaseValue를 바꾸고 끝납니다. 반대로 Duration/Infinite GE는 유지되는 동안 CurrentValue 계산에 참여하고, 제거되면 원래 계산 결과로 돌아가도록 설계됩니다.

Duration GE

정해진 시간이 끝나면 자동으로 만료됩니다. 5초 이동속도 버프, 3초 기절, 10초 독 상태에 적합합니다.

Infinite GE

명시적으로 제거할 때까지 유지됩니다. 장비 효과, 패시브, 오라, 토글형 상태에 적합합니다.

Granted Tag

효과가 활성인 동안 태그를 부여합니다. State.Stunned, Cooldown.Fireball 같은 상태 표현에 좋습니다.

Modifier 없이도 유용

Attribute를 바꾸지 않아도 태그, Cue, 차단 조건, 쿨다운 상태만으로 충분히 의미 있는 GE가 됩니다.

활성 수명 흐름

기간형 GE는 적용 순간에 끝나지 않습니다. 적용 후 ASC의 ActiveGameplayEffects에 등록되고, 유지 시간 동안 상태를 제공하다가 만료 또는 제거됩니다.

1. Apply Spec 적용 GA나 코드가 GE Spec을 대상 ASC에 적용합니다.
2. Active ASC에 보관 Instant가 아니므로 Active GE로 남아 남은 시간과 스택을 추적합니다.
3. State 상태 유지 CurrentValue 계산, Granted Tag, Cue의 WhileActive 상태에 영향을 줍니다.
4. Period 선택적 반복 Period가 있으면 일정 간격으로 주기 실행을 할 수 있습니다.
5. Remove 만료 또는 제거 시간 만료, 조건 제거, 수동 제거로 Active GE가 사라집니다.
설정 의미 설계 질문
Duration Magnitude HasDuration GE가 얼마나 유지될지 정합니다. 고정 시간인가, 레벨/커브/SetByCaller로 달라지는가?
Period 효과가 활성인 동안 반복 실행되는 간격입니다. 매초 피해/회복처럼 틱이 필요한가?
Execute on Application 주기 효과를 적용 즉시 한 번 실행할지 정합니다. 독이 즉시 한 번 피해를 주고 시작해야 하는가, 첫 주기까지 기다려야 하는가?
Ongoing Tag Requirements 태그 조건에 따라 활성 효과를 억제하거나 다시 활성화할 수 있습니다. 무적, 정화, 지역 이탈 같은 조건에 반응해야 하는가?

BaseValue와 CurrentValue

Attribute는 보통 기본값인 BaseValue와 현재 계산 결과인 CurrentValue를 구분해서 생각하면 이해하기 쉽습니다. 기간형 Modifier는 "현재 적용 중인 보정"이므로 효과가 사라지면 CurrentValue 계산에서도 빠집니다.

Instant 피해

체력 100에 Instant 피해 -30을 적용하면 BaseValue 자체가 70이 됩니다. 효과는 즉시 끝났기 때문에 제거해서 되돌릴 Active GE가 없습니다.

Duration 이동속도 버프

이동속도 BaseValue가 600이고 5초 동안 +200 버프가 있으면 CurrentValue는 800처럼 계산됩니다. 5초 후 GE가 만료되면 CurrentValue 계산에서 +200이 빠집니다.

주기 실행은 별도로 판단합니다

Duration GE라도 Period를 사용해 매초 피해를 실행하는 구조라면, 각 주기 실행이 Attribute에 누적 변화를 만들 수 있습니다. "기간형은 항상 되돌아간다"가 아니라, Modifier와 Period 실행의 책임을 나누어 봐야 합니다.

스택 설계

기간형 GE는 같은 효과가 다시 들어왔을 때 새 인스턴스로 둘지, 스택 카운트를 올릴지, 지속 시간을 갱신할지 정할 수 있습니다. 이 설정이 독, 출혈, 방어 버프, 쿨다운 같은 효과의 체감을 크게 바꿉니다.

정책 선택지 학습 포인트
Stacking Type None, Aggregate by Source, Aggregate by Target 누가 다시 걸었을 때 같은 스택으로 볼지 결정합니다.
Stack Limit Count 최대 스택 수 중첩 상한을 정해 폭주하는 수치를 막습니다.
Duration Policy Refresh on Successful Application, Never Refresh, Extend Duration 재적용 시 시간을 새로 채울지, 유지할지, 새 GE Spec의 지속 시간을 남은 시간에 더할지 결정합니다.
Period Policy Reset on Successful Application, Never Reset 주기 실행 카운터가 재적용 때 초기화되는지 결정합니다.
Expiration Policy Clear Entire Stack, Remove Single Stack and Refresh Duration, Refresh Duration 시간이 끝났을 때 전체를 지울지, 한 스택만 줄일지 정합니다.

5.7 스택 지속 시간의 핵심

Extend Duration은 새 스택이 들어올 때 현재 남은 시간에 새 GE Spec의 Duration을 더합니다. 독이나 출혈처럼 "다시 맞으면 더 오래 지속되는" 체감을 만들 수 있지만, 상한과 정화 규칙을 함께 정하지 않으면 지속 시간이 과하게 늘어날 수 있습니다.

대표 설계 예시

효과 추천 구조 핵심 이유
기절 Duration GE + State.Stunned Granted Tag Attribute 변경 없이도 태그만으로 입력, 이동, 어빌리티 발동을 차단할 수 있습니다.
쿨다운 Duration GE + Cooldown.SkillName Tag GA의 ActivationBlockedTags가 쿨다운 태그를 보고 재사용을 막습니다.
이동속도 버프 Duration GE + MoveSpeed Additive/Multiplicative Modifier 만료 시 CurrentValue 보정이 사라져 원래 이동속도 계산으로 돌아갑니다.
독 Duration GE + Period + Stack 틱 피해와 중첩 체감을 함께 설계할 수 있습니다.
장비 보너스 Infinite GE + 장비 해제 시 Remove 장착 중에는 계속 유지되고, 제거 경로가 명확해야 합니다.

복습 질문

1. 기간형 GE가 Instant GE와 다른 가장 큰 점은?

정답: 적용 후 ASC에 Active Gameplay Effect로 남아 일정 시간 또는 무기한 상태를 유지합니다.

2. Attribute Modifier 기준으로 기간형 GE가 주로 바꾸는 값은?

정답: 유지되는 동안 CurrentValue 계산에 참여합니다. 제거되면 그 보정이 빠집니다.

3. Modifier가 없는 기간형 GE도 필요한 이유는?

정답: Granted Tag, 쿨다운, 입력 차단, Cue 유지처럼 숫자 변경 없이도 상태를 표현할 수 있기 때문입니다.

4. 같은 독 효과가 다시 적용될 때 봐야 할 스택 설정은?

정답: Stacking Type, Stack Limit Count, Duration/Period/Expiration Policy를 함께 봐야 합니다.
