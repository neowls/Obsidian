Gameplay Ability System

게임플레이 어빌리티 스펙(Spec)

FGameplayAbilitySpec은 ASC가 “이 액터에게 어떤 어빌리티가 부여되어 있고, 현재 어떤 상태인지”를 추적하는 등록 정보입니다. 실제 어빌리티 로직과 실행 인스턴스를 바로 같은 것으로 보지 않고, Spec과 Handle을 기준으로 구분하면 GAS 흐름이 훨씬 선명해집니다.

원본: 게임 어빌리티 시스템(GAS)/게임플레이 어빌리티 스펙(Spec).md 난이도: 기초 개념 핵심: Spec, Handle, ASC 검수 기준: Unreal Engine 5.7.4

한 줄 정의

Gameplay Ability Spec은 ASC가 보유한 어빌리티 한 건에 대한 등록표입니다. 이 등록표에는 어빌리티 클래스, 레벨, 입력 바인딩, 소스 오브젝트, 활성화 상태, 인스턴스 참조 같은 정보가 모입니다.

핵심 감각

게임 코드에서 “어빌리티를 줬다”는 말은 대개 ASC의 ActivatableAbilities 목록에 FGameplayAbilitySpec을 추가했다는 뜻입니다.

5.7 공식 문서의 정의로 다시 정리

FGameplayAbilitySpec은 ASC에 보관되는 활성화 가능한 어빌리티 등록 정보입니다. 어빌리티 클래스, 레벨, 입력 바인딩 같은 "무엇을 가지고 있는가"와 활성 카운트, 인스턴스 목록, 제거 대기 같은 "현재 상태"를 함께 들고 있습니다. 그래서 Spec은 단순 설정값이 아니라 ASC가 어빌리티를 실행하고 복제하기 위한 런타임 관리 단위입니다.

Gameplay Ability

점프, 대시, 공격 같은 능력의 로직입니다. 보통 UGameplayAbility 클래스로 작성합니다.

Ability Spec

ASC가 보관하는 어빌리티 등록 정보입니다. 어떤 어빌리티인지와 현재 상태를 함께 담습니다.

Spec Handle

ASC 안에서 특정 Spec을 찾고 제어하기 위한 식별자입니다. 제거, 활성화, 조회 흐름에서 자주 사용합니다.

Ability Instance

활성화 시점에 실제 실행되는 인스턴스입니다. 인스턴싱 정책에 따라 없거나, 재사용되거나, 실행마다 생성될 수 있습니다.

ASC에서 Spec이 움직이는 흐름

Spec을 이해할 때는 “부여”, “보관”, “식별”, “활성화”, “종료/제거” 순서로 보면 됩니다. Handle은 이 흐름에서 ASC가 특정 Spec을 다시 찾기 위한 주소표처럼 쓰입니다.

1. Grant 어빌리티 부여 GiveAbility 등으로 ASC에 어빌리티를 등록합니다.
2. Spec Spec 생성 클래스, 레벨, 입력 ID, 소스 정보가 Spec에 담깁니다.
3. Handle 식별자 발급 Spec Handle로 이후 조작 대상을 특정합니다.
4. Activate 활성화 입력, 태그, Handle 등을 통해 Spec에 연결된 어빌리티를 실행합니다.
5. Runtime 상태 추적 활성 카운트, 인스턴스, 제거 대기 같은 런타임 정보가 갱신됩니다.

정확히 구분해야 할 점

Spec은 어빌리티 그 자체가 아닙니다

Spec은 ASC가 어빌리티를 관리하기 위한 등록 정보입니다. 실제 실행 로직은 UGameplayAbility 쪽에 있고, Spec은 그 로직을 어떤 레벨과 상태로 보유하는지를 나타냅니다.

Handle은 인스턴스 포인터가 아닙니다

Spec Handle은 ASC 내부의 Spec을 식별하기 위한 값입니다. 어빌리티 인스턴스에 직접 접근하는 포인터처럼 생각하면 인스턴싱 정책과 제거 타이밍에서 혼동이 생깁니다.

기억할 문장

  • ASC는 어빌리티를 “Spec 목록”으로 관리한다.
  • Spec은 어빌리티의 정적 정보와 런타임 상태를 함께 담는다.
  • 외부에서 특정 어빌리티를 조작할 때는 Spec Handle을 기준으로 접근하는 흐름이 많다.
  • Ability, Spec, Handle, Instance를 분리해서 말하면 GAS 디버깅이 쉬워진다.

코드에서 마주치는 형태

실제 프로젝트에서는 보통 서버 권한에서 어빌리티를 부여하고, 반환받은 Handle을 저장해 나중에 제거하거나 활성화 조건을 추적합니다. 

FGameplayAbilitySpecHandle Handle = AbilitySystemComponent->GiveAbility(
    FGameplayAbilitySpec(AbilityClass, AbilityLevel, InputID, SourceObject)
);

// 이후 Handle을 기준으로 해당 Spec을 찾거나 제거하는 흐름을 구성한다.

복습 질문

1. ASC가 어빌리티를 관리하는 기본 단위는?

정답: FGameplayAbilitySpec. ASC의 부여된 어빌리티 목록에 들어가는 등록 정보입니다.

2. Spec Handle은 무엇을 위한 값인가?

정답: ASC 내부에서 특정 Spec을 식별하고 제어하기 위한 값입니다.

3. Spec과 Ability Instance를 구분해야 하는 이유는?

정답: Spec은 보유 정보와 상태이고, Instance는 활성화 중 실행되는 객체입니다. 인스턴싱 정책에 따라 Instance의 생성 방식이 달라집니다.

4. “어빌리티를 줬다”는 말은 GAS 내부에서 무엇을 의미하나?

정답: ASC에 해당 어빌리티의 Spec이 추가되어 활성화 가능한 목록에 들어갔다는 의미입니다.
