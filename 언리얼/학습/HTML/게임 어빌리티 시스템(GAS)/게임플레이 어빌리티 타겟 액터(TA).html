Gameplay Ability System

게임플레이 어빌리티 타겟 액터(TA)

Target Actor는 Gameplay Ability 안에서 “어디를, 누구를, 어떤 방식으로 맞췄는가”를 판정하고 그 결과를 TargetData로 만들어 어빌리티 흐름에 돌려주는 특수 액터입니다.

원본: 게임 어빌리티 시스템(GAS)/게임플레이 어빌리티 타겟 액터(TA).md 난이도: 타겟팅 기초 핵심: TargetActor, WaitTargetData, TargetDataHandle 검수 기준: Unreal Engine 5.7.4

한 줄 정의

Target Actor는 타겟 판정을 어빌리티 실행 흐름 밖의 액터로 분리한 것입니다. 보통 AGameplayAbilityTargetActor를 상속해 만들고, UAbilityTask_WaitTargetData 같은 Ability Task가 스폰하거나 사용합니다.

왜 액터로 분리하는가?

타겟팅은 즉시 끝날 수도 있고, 플레이어의 확인 입력을 기다릴 수도 있고, 월드에 범위 표시나 레티클을 띄워야 할 수도 있습니다. 이처럼 “시간이 걸리고 월드 표현이 필요한 판정”을 어빌리티 본문에서 분리하기 위해 Target Actor를 씁니다.

WaitTargetData를 무조건 남발하지 않습니다

5.7 API 문서의 AbilityTask_WaitTargetData는 Target Actor가 어빌리티 활성화마다 생성될 수 있음을 전제로 합니다. 조준 UI처럼 오래 유지되는 시스템이나 매우 자주 쓰는 즉시 판정은 프로젝트 전용 Target Actor 재사용, ASC/Ability 내부 트레이스, 서버 검증 전용 로직으로 분리하는 편이 더 낫습니다.

Instant Trace

버튼을 누른 순간 라인 트레이스나 오버랩을 수행해 즉시 TargetData를 만듭니다.

Confirmed Targeting

조준 또는 범위 선택 후, 확인 입력을 받아 최종 타겟을 확정합니다.

World Reticle

공격 범위, 설치 위치, 현재 타겟을 시각적으로 보여주는 보조 액터입니다.

TargetData

판정 결과를 담아 Ability, GameplayEffect, 서버 검증 흐름으로 넘기는 데이터입니다.

타겟팅 흐름

Target Actor를 사용할 때는 “Ability가 직접 판정한다”보다 “Ability가 타겟 데이터가 준비될 때까지 기다린다”로 이해하는 편이 좋습니다.

1. Ability 어빌리티 활성화 스킬 입력이나 이벤트로 Gameplay Ability가 시작됩니다.
2. Task WaitTargetData Ability Task가 Target Actor를 스폰하거나 기존 액터를 사용합니다.
3. TargetActor 판정 시작 StartTargeting 이후 Trace, Overlap, Reticle 갱신을 수행합니다.
4. Confirm 확정 또는 취소 확인 입력은 TargetData를 만들고, 취소 입력은 타겟팅을 중단합니다.
5. Consume 결과 소비 Ability가 TargetData를 받아 GameplayEffect 적용이나 후속 로직에 사용합니다.

주요 함수

함수 역할 볼 때의 기준
StartTargeting 타겟팅 로직을 초기화하고 시작합니다. 어떤 Ability를 기준으로 타겟을 판정하는가?
ConfirmTargetingAndContinue 타겟팅을 확정하고 TargetData를 브로드캐스트해 Ability Task 흐름을 계속 진행합니다. 확정 시점에 어떤 데이터가 만들어지는가?
ConfirmTargeting 태스크 진행과 별개로 타겟팅 확정만 수행합니다. 확정 이벤트와 후속 처리 흐름이 분리되어 있는가?
CancelTargeting 타겟팅을 중단하고 진행 중인 선택을 버립니다. 취소 시 Reticle, Delegate, Task 정리가 되는가?
IsConfirmTargetingAllowed 현재 상태에서 타겟 확정이 가능한지 판단합니다. 유효하지 않은 위치나 대상에서 확정을 막아야 하는가?

게임플레이 어빌리티 타겟 데이터

TargetData는 Target Actor가 판정한 결과입니다. 실무에서는 단일 데이터보다 FGameplayAbilityTargetDataHandle로 여러 TargetData를 묶어 전달하는 흐름이 일반적입니다.

FGameplayAbilityTargetDataHandle

여러 TargetData를 담는 핸들입니다. HitResult 기반 데이터, Actor 배열 기반 데이터, 커스텀 데이터처럼 서로 다른 TargetData 타입을 함께 다룰 수 있습니다.

HitResult

라인 트레이스, 구체 트레이스, 지면 선택처럼 충돌 결과가 중요한 경우 사용합니다.

Actor Pointers

범위 안의 적 목록, 선택된 아군 대상처럼 액터 집합을 전달할 때 사용합니다.

Origin / End

트레이스 시작점과 끝점, 발사 방향, 선택 위치 같은 공간 정보를 함께 보관합니다.

네트워크에서의 주의점

클라이언트가 만든 TargetData는 반응성이 좋지만 서버 검증이 필요합니다. 서버가 직접 TargetData를 만들면 치팅 위험은 줄지만, 소유 클라이언트의 예측과 어긋날 수 있습니다.

사용 패턴 비교

패턴 잘 맞는 상황 주의점
즉시 트레이스 히트스캔 총, 즉발 클릭 판정 시각적 확인이나 취소가 필요 없을 때 적합합니다.
지면 범위 선택 메테오, 장판, 설치형 스킬 Reticle 위치 갱신과 유효 위치 검사가 중요합니다.
타겟 락온 유도 미사일, 단일 대상 지정 대상이 트레이스 밖으로 벗어났을 때 유지할지 결정해야 합니다.
커스텀 TargetData 특수한 선택 정보나 추가 페이로드가 필요한 스킬 네트워크 직렬화와 서버 검증 경로를 같이 설계해야 합니다.

복습 질문

1. Target Actor는 어떤 클래스를 상속해 구현하는가?

정답: AGameplayAbilityTargetActor를 상속해 구현합니다.

2. World Reticle은 왜 쓰는가?

정답: 공격 범위, 선택 위치, 현재 타겟 같은 타겟팅 상태를 월드에 시각화하기 위해 사용합니다.

3. TargetDataHandle은 왜 필요한가?

정답: 여러 TargetData를 묶고, 서로 다른 TargetData 타입을 하나의 전달 단위로 다루기 위해 사용합니다.

4. 클라이언트가 TargetData를 만들 때 필요한 조치는?

정답: 서버에서 거리, 시야, 유효 대상 여부 같은 검증을 수행해야 합니다.
