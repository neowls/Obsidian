Gameplay Ability System

어빌리티 태스크(AT)의 제작 규칙

커스텀 Ability Task는 GA에서 반복되는 비동기 패턴을 재사용 가능한 노드로 분리하는 방법입니다. static 생성 함수, 델리게이트, Activate, OnDestroy, 대기 상태, Tick 여부를 일관되게 설계해야 누수와 중복 브로드캐스트를 피할 수 있습니다.

원본: 게임 어빌리티 시스템(GAS)/어빌리티 태스크(AT)의 제작 규칙.md 난이도: 커스텀 Task 구현 핵심: NewAbilityTask, Activate, OnDestroy, Delegate 검수 기준: Unreal Engine 5.7.4

한 줄 정의

커스텀 Ability Task는 UAbilityTask를 상속해 GA 전용 비동기 작업을 Blueprint/C++에서 재사용 가능하게 만든 클래스입니다. 5.7 API에는 NewAbilityTask, SetWaitingOnAvatar, ShouldBroadcastAbilityTaskDelegates, OnDestroy 같은 제작에 필요한 기본 도구가 있습니다.

Task는 한 번 만들고 끝나는 UObject입니다

Task는 GA의 활성화 흐름에 붙어 있는 일시적 객체입니다. 외부 Delegate, Timer, Actor 참조, Tick을 사용했다면 OnDestroy에서 반드시 해제해야 합니다.

제작 절차

원본 노트의 규칙을 실제 구현 순서로 풀면 아래와 같습니다. 핵심은 “생성 함수에서 준비하고, Activate에서 시작하고, 결과를 델리게이트로 알리고, OnDestroy에서 정리한다”입니다.

1. Class UAbilityTask 상속 GA에서만 쓰는 비동기 작업은 UAbilityTask를 기반으로 만듭니다.
2. Factory static 생성 함수 Blueprint 노드로 보일 static 함수를 만들고 내부에서 NewAbilityTask를 호출합니다.
3. Delegate 결과 델리게이트 선언 완료, 실패, 취소, 데이터 도착 같은 결과를 GA에 알릴 델리게이트를 둡니다.
4. Activate 작업 시작 Timer, 바인딩, 타겟팅, 이동, 대기 상태 설정을 시작합니다.
5. OnDestroy 정리 Delegate 해제, Timer 정리, 외부 참조 해제, Tick 중단을 처리합니다.

수명주기와 안전장치

규칙 이유 확인 지점
static factory 함수 Blueprint 노드 형태로 Task를 만들고 입력 파라미터를 저장합니다. BlueprintInternalUseOnly, DefaultToSelf 메타 사용 여부
Activate override Task의 실제 작업 시작 지점입니다. 외부 Delegate/Timer 바인딩, 대기 상태 설정, 즉시 실패 처리
ShouldBroadcastAbilityTaskDelegates Ability가 이미 끝난 뒤 잘못 브로드캐스트하는 것을 막습니다. 결과 델리게이트 호출 직전 검사
SetWaitingOnAvatar Avatar/Movement 같은 상태를 기다리는 Task임을 표시합니다. 이동, 애니메이션, 캐릭터 상태 대기형 Task
bTickingTask 매 프레임 확인이 필요할 때만 켭니다. Timer나 Delegate로 대체할 수 없는지 먼저 확인
OnDestroy override Task 종료, Ability 종료, 취소, 복제 정리 경로에서 호출됩니다. 외부 바인딩 해제, Timer 정리, Super 호출

C++ 뼈대

아래는 일정 시간 후 완료를 알리는 Task의 축약 예시입니다. 실제 프로젝트에서는 Prediction, 서버/클라이언트 실행 위치, Ability 종료 시 정리 정책을 더 엄격히 다뤄야 합니다. 

DECLARE_DYNAMIC_MULTICAST_DELEGATE(FProjectAbilityTaskDelegate);

UCLASS()
class UAT_WaitSimpleDelay : public UAbilityTask
{
    GENERATED_BODY()

public:
    UPROPERTY(BlueprintAssignable)
    FProjectAbilityTaskDelegate OnFinished;

    UFUNCTION(BlueprintCallable, Category="Ability|Tasks",
        meta=(HidePin="OwningAbility", DefaultToSelf="OwningAbility",
              BlueprintInternalUseOnly="true"))
    static UAT_WaitSimpleDelay* WaitSimpleDelay(
        UGameplayAbility* OwningAbility,
        float Duration);

    virtual void Activate() override;
    virtual void OnDestroy(bool bInOwnerFinished) override;

private:
    float Duration = 0.0f;
    FTimerHandle TimerHandle;
    void HandleTimerFinished();
};
UAT_WaitSimpleDelay* UAT_WaitSimpleDelay::WaitSimpleDelay(
    UGameplayAbility* OwningAbility,
    float InDuration)
{
    UAT_WaitSimpleDelay* Task =
        NewAbilityTask<UAT_WaitSimpleDelay>(OwningAbility);
    Task->Duration = InDuration;
    return Task;
}

void UAT_WaitSimpleDelay::Activate()
{
    SetWaitingOnAvatar();
    GetWorld()->GetTimerManager().SetTimer(
        TimerHandle, this,
        &UAT_WaitSimpleDelay::HandleTimerFinished,
        Duration, false);
}

void UAT_WaitSimpleDelay::HandleTimerFinished()
{
    if (ShouldBroadcastAbilityTaskDelegates())
    {
        OnFinished.Broadcast();
    }
    EndTask();
}

void UAT_WaitSimpleDelay::OnDestroy(bool bInOwnerFinished)
{
    if (UWorld* World = GetWorld())
    {
        World->GetTimerManager().ClearTimer(TimerHandle);
    }

    Super::OnDestroy(bInOwnerFinished);
}

제작 체크리스트

  • Task가 무엇을 기다리는지 한 문장으로 설명합니다. 애니메이션인지, 입력인지, 서버 데이터인지 불명확하면 GA 본문이 더 낫습니다.
  • Delegate는 결과별로 분리합니다. 완료, 취소, 실패, 데이터 도착을 하나의 bool로 뭉개면 Blueprint 사용성이 떨어집니다.
  • 브로드캐스트 직전 ShouldBroadcastAbilityTaskDelegates를 확인합니다. Ability가 이미 끝난 뒤 이벤트가 튀어나오는 문제를 줄입니다.
  • 외부 바인딩은 반드시 해제합니다. ASC Delegate, Anim Delegate, Timer, Actor 이벤트는 OnDestroy에서 정리합니다.
  • Tick은 마지막 선택지로 둡니다. Timer, Delegate, Gameplay Event로 해결할 수 있으면 Tick Task를 피합니다.

복습 질문

1. 커스텀 AT는 어떤 클래스를 상속하는가?

정답: UAbilityTask를 상속합니다.

2. static 생성 함수가 필요한 이유는?

정답: GA/Blueprint에서 Task를 생성하는 노드 역할을 하며 입력 파라미터를 Task에 저장하기 위해서입니다.

3. 결과 Delegate를 브로드캐스트하기 전에 확인할 함수는?

정답: ShouldBroadcastAbilityTaskDelegates입니다.

4. OnDestroy에서 해야 할 일은?

정답: 외부 Delegate, Timer, 참조, Tick 관련 정리를 하고 Super::OnDestroy를 호출합니다.
