Gameplay Ability System

GAS Documentation 종합 정리

원본 GAS Documentation.md는 GAS 전반을 다루는 대형 참고 문서입니다. 이 HTML은 원문을 그대로 길게 옮기는 대신, Unreal Engine 5.7.4 학습 기준으로 핵심 판단 기준과 세부 문서 이동 경로를 재구성한 종합 목차입니다.

원본: 게임 어빌리티 시스템(GAS)/GAS Documentation.md 난이도: 종합 참고 핵심: Setup, ASC, Attribute, GE, GA, Prediction, Debug 검수 기준: Unreal Engine 5.7.4

이 문서의 역할

이 페이지는 GAS 세부 문서 17개를 연결하는 학습 지도입니다. 원본은 플러그인 소개, 샘플 프로젝트, 설정, ASC, Attribute, GE, GA, AT, GC, Prediction, Targeting, Debug, Optimization까지 한 파일에 담고 있습니다. 학습용 HTML에서는 각 개념을 개별 문서로 나눴으므로, 여기서는 어떤 순서로 보고 어떤 결정을 해야 하는지에 집중합니다.

5.7.4 기준으로 다시 읽어야 할 부분

원본에는 UE 4.x와 5.1~5.3 시기의 주석이 섞여 있습니다. 5.7.4에서는 공식 문서 표기상 5.7 API를 기준으로 보고, 특히 GameplayEffectComponent 계열, GameplayModOp 연산명, Gameplay Cue Blueprint 이벤트명, 스택 Duration Policy의 Extend Duration 같은 변경점을 함께 확인해야 합니다.

ASC

능력, 효과, 태그, Attribute를 관리하는 중심입니다. Owner/Avatar와 복제 모드를 먼저 결정합니다.

Attribute

BaseValue, CurrentValue, Meta Attribute, AttributeSet 콜백으로 수치 흐름을 구성합니다.

GE

Modifier, Duration, Stack, Tag, Cue, Component를 통해 상태 변화를 데이터로 표현합니다.

GA

입력, 비용, 쿨다운, 타겟팅, Task, 네트워크 실행 정책을 묶는 실행 흐름입니다.

5.7.4 기준 업데이트 포인트

영역 최신화 포인트 학습 시 주의
Gameplay Effect 부가 기능이 GameplayEffectComponent 계열로 정리되어 있습니다. 예전 속성명만 외우지 말고 GE에 어떤 Component가 붙는지 확인합니다.
Modifier 연산 AddBase, MultiplyAdditive, DivideAdditive, Override, MultiplyCompound, AddFinal 흐름으로 읽습니다. 단순 Add/Multiply/Divide로만 설명하면 적용 순서와 최종 값이 헷갈립니다.
Stack Duration Extend Duration이 Duration Policy 선택지에 포함됩니다. 재적용 시 시간을 새로 채우는지, 유지하는지, 누적하는지 분명히 정합니다.
Gameplay Cue Blueprint Notify 이벤트에서 On Burst, On Become Relevant, On Cease Relevant 명칭을 함께 봅니다. 개념 이벤트와 Blueprint 노출명이 다르게 보일 수 있습니다.
InitGlobalData 원본의 4.24~5.2 TargetData 수동 초기화 주석은 역사적 맥락입니다. 5.7 프로젝트에서는 현재 엔진 초기화 흐름을 기준으로 확인하고, 구버전 우회 코드를 그대로 복사하지 않습니다.

프로젝트 적용 체크리스트

  • 플러그인과 모듈을 확인합니다. GameplayAbilities, GameplayTags, GameplayTasks 의존성이 Build.cs에 들어가야 합니다.
  • ASC의 위치를 결정합니다. 리스폰 후 상태 유지가 필요하면 PlayerState, 몸체와 함께 사라져도 되면 Character/Pawn을 우선 검토합니다.
  • 복제 모드를 정합니다. 플레이어 소유 ASC와 AI ASC는 Full/Mixed/Minimal 선택 기준이 다릅니다.
  • Attribute는 GE로 바꿉니다. 직접 대입은 초기화나 특수 상황으로 제한하고, 일반 변화는 GE를 통과시킵니다.
  • 쿨다운과 비용은 GE로 표현합니다. GA 내부 bool이나 Timer만으로 만들면 태그 차단, UI, 복제 흐름이 약해집니다.
  • 입력은 요청이고, 실행 가능 여부는 GAS가 결정합니다. 태그 차단, 비용, 쿨다운, 권한 검사를 우회하지 않습니다.
  • Task와 Cue에 게임플레이 판정을 넣지 않습니다. Task는 대기/흐름, Cue는 표현, GE/Execution은 상태 변화라는 책임을 유지합니다.

대표 구현 패턴

기능 추천 구성 판단 기준
스턴 Duration GE + State.Stunned Tag + GA ActivationBlockedTags 상태 수명, 입력 차단, Cue 표시가 같은 GE 수명을 따라가야 합니다.
질주 GA + WaitInputRelease + Duration/Infinite GE + Stamina Cost GE 홀드 입력, 예측, 이동속도 보정, 비용 소모 주기를 함께 봅니다.
조준 GA + 입력 홀드 + 카메라/이동속도 GE + 로컬 UI/Reticle 게임플레이 수치 변화와 순수 로컬 카메라 연출을 분리합니다.
피해 처리 Damage Meta Attribute + ExecutionCalculation + PostGameplayEffectExecute 방어력, 실드, 무적, 크리티컬을 한 후처리 흐름으로 모읍니다.
범위 지정 스킬 GA + WaitTargetData + Target Actor + GE Spec Apply 클라이언트 TargetData는 서버 검증과 예측 보정 정책이 필요합니다.

디버깅과 운영

GAS는 데이터가 여러 컨테이너로 나뉘기 때문에 “값이 이상하다”를 단순히 변수 하나로 추적하기 어렵습니다. 원본 문서의 디버그 섹션은 여전히 유용하지만, 먼저 무엇을 볼지 정해야 합니다.

먼저 볼 것

  • ASC에 Ability Spec이 실제로 부여되어 있는가?
  • ActivationBlockedTags와 RequiredTags가 예상과 같은가?
  • Active GE의 Duration, Stack, Granted Tag가 남아 있는가?
  • Attribute의 BaseValue와 CurrentValue 중 어느 쪽이 달라졌는가?

흔한 원인

  • 클라이언트에서 ASC ActorInfo 초기화 누락
  • Tag Count가 0이 아닌 다른 GE/Loose Tag 잔여
  • Ability가 EndAbility로 끝나지 않음
  • SetByCaller 키 불일치 또는 Apply 전에 값 미설정

복습 질문

1. 이 종합 문서는 어떤 용도로 봐야 하는가?

정답: 세부 개념을 반복 설명하는 문서가 아니라, GAS 전체 학습 순서와 프로젝트 적용 체크리스트로 봅니다.

2. 5.7.4 기준으로 GE를 볼 때 추가로 확인할 것은?

정답: Modifier와 Duration뿐 아니라 GameplayEffectComponent 계열 설정도 함께 확인합니다.

3. GAS 디버깅에서 Attribute만 보면 부족한 이유는?

정답: Attribute 값은 Active GE, Tag Count, Ability 상태, Prediction, SetByCaller 값의 결과이기 때문입니다.

4. Task와 Cue에 넣으면 안 좋은 것은?

정답: 최종 게임플레이 판정입니다. Task는 비동기 흐름, Cue는 표현 효과에 집중해야 합니다.
