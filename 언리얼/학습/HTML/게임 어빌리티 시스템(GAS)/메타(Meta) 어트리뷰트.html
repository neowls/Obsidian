Gameplay Ability System

메타(Meta) 어트리뷰트

Meta Attribute는 Health나 Shield처럼 장기 상태로 남기는 값이 아니라, Damage처럼 한 번 계산하고 소비하는 임시 Attribute입니다. 최종 수치를 바로 체력에 적용하지 않고 중간 값으로 받아 후처리하면 무적, 실드, 방어력, 콤보 보정을 유연하게 추가할 수 있습니다.

Damage Meta Attribute 분배 실험판

Damage를 Health에 바로 적용하지 않고 Meta Attribute로 받은 뒤, Attribute Set에서 Shield와 Health로 분배하는 흐름을 시각화합니다.

Shield40
Health100

Damage GE가 Meta Attribute에 값을 넣고, PostGameplayEffectExecute가 실드와 체력에 분배합니다.

한 줄 정의

Meta Attribute는 GE가 전달한 계산 결과를 Attribute Set에서 후처리하기 위한 임시 Attribute입니다. 공식 타입 이름이라기보다 GAS 프로젝트에서 널리 쓰는 설계 패턴이며, 실제 구현은 일반 FGameplayAttributeData Attribute로 둡니다.

왜 Health를 바로 깎지 않는가?

데미지를 바로 Health에 적용하면 이후 실드, 무적, 방어력, 피해 흡수, 콤보 배율 같은 규칙을 추가할 때 GE나 ExecutionCalculation이 복잡해집니다. Damage라는 중간 Attribute로 받은 뒤 PostGameplayEffectExecute에서 Health와 Shield에 분배하면 책임이 선명해집니다.

Damage Meta Attribute

GE 또는 ExecutionCalculation이 최종 피해 후보 값을 이 Attribute에 넣습니다.

Shield

Damage를 먼저 흡수할 수 있는 장기 상태 Attribute입니다.

Health

Shield가 처리하고 남은 Damage가 최종적으로 적용되는 장기 상태 Attribute입니다.

Rules

무적, 방어력, 취약, 헤드샷, 콤보 배율 같은 프로젝트 규칙을 한 지점에서 처리합니다.

Damage 처리 흐름

Meta Attribute를 쓰면 GE는 “피해 후보값”을 넣고, Attribute Set은 “이 피해가 실제로 어떤 값에 반영되는가”를 결정합니다.

1. Spec 피해 수치 계산 GE Modifier, SetByCaller, ExecutionCalculation이 Damage 값을 결정합니다.
2. Meta Damage에 적용 Health가 아니라 Damage Meta Attribute에 먼저 들어갑니다.
3. Execute 후처리 콜백 PostGameplayEffectExecute에서 Damage 값을 읽습니다.
4. Distribute 분배 무적, 실드, 방어력, 체력 감소 규칙을 적용합니다.
5. Reset 초기화 소비한 Meta Attribute를 0으로 되돌립니다.
규칙 추가 Health 직접 적용 Damage Meta Attribute
무적 모든 피해 GE가 무적 조건을 알아야 합니다. 후처리에서 Damage를 0으로 만들면 됩니다.
실드 GE마다 Shield/Health 분배 규칙을 복제하게 됩니다. 한 함수에서 Shield를 먼저 줄이고 남은 값만 Health에 적용합니다.
콤보 보정 Health Modifier와 배율 규칙이 섞입니다. Execution 또는 SetByCaller로 Damage를 보정한 뒤 동일한 후처리를 탑니다.

설계 규칙

Meta Attribute로 두기 좋은 값

  • Damage, Healing처럼 후처리 규칙이 필요한 값
  • 방어력, 실드, 무적, 상태 이상과 상호작용하는 값
  • GE 적용 순간에만 의미 있고 이후 저장할 필요가 없는 값

일반 Attribute로 둬야 하는 값

  • Health, Mana, Shield처럼 UI와 저장, 복제가 필요한 장기 상태
  • MoveSpeed, AttackPower처럼 지속 버프와 장비 보정이 붙는 값
  • 플레이어가 현재 상태로 인식해야 하는 수치

복제에서 제외하는 이유

원본 노트처럼 Meta Attribute는 일반적으로 복제하지 않습니다. Damage는 최종 결과가 아니라 처리 중간값이므로, 클라이언트에 오래 남거나 저장될 필요가 없습니다. UI와 네트워크가 봐야 하는 값은 Damage가 아니라 후처리 결과인 Health, Shield, 상태 태그입니다.

C++ 작성 감각

Damage Meta Attribute는 GE가 건드리는 Attribute로 선언하되, 복제하지 않고 PostGameplayEffectExecute에서 소비하는 식으로 구성합니다. 

UPROPERTY(BlueprintReadOnly, Category = "Meta")
FGameplayAttributeData Damage;
ATTRIBUTE_ACCESSORS(UProjectAttributeSet, Damage)

void UProjectAttributeSet::PostGameplayEffectExecute(
    const FGameplayEffectModCallbackData& Data)
{
    Super::PostGameplayEffectExecute(Data);

    if (Data.EvaluatedData.Attribute == GetDamageAttribute())
    {
        float LocalDamage = GetDamage();
        SetDamage(0.0f);

        if (bIsInvincible)
        {
            return;
        }

        const float ShieldDamage = FMath::Min(GetShield(), LocalDamage);
        SetShield(GetShield() - ShieldDamage);
        LocalDamage -= ShieldDamage;

        if (LocalDamage > 0.0f)
        {
            SetHealth(FMath::Clamp(GetHealth() - LocalDamage, 0.0f, GetMaxHealth()));
        }
    }
}

자주 하는 실수

실수 문제 해결
Damage를 초기화하지 않음 다음 GE 처리 때 이전 피해가 남아 있는 것처럼 보일 수 있습니다. 소비 직후 0으로 되돌립니다.
Damage를 UI에 표시 중간값과 최종 결과가 섞여 혼란이 생깁니다. UI는 Health/Shield 변화나 별도 Combat Log 이벤트를 봅니다.
모든 값을 Meta로 만듦 상태 저장과 복제 기준이 사라집니다. 장기 상태는 일반 Attribute, 순간 계산은 Meta Attribute로 나눕니다.

복습 질문

1. Meta Attribute는 무엇인가?

정답: GE가 전달한 계산 결과를 Attribute Set에서 후처리하기 위한 임시 Attribute입니다.

2. Damage를 Health에 바로 적용하지 않는 이유는?

정답: 무적, 실드, 방어력, 콤보 보정 같은 규칙을 한 지점에서 유연하게 처리하기 위해서입니다.

3. Meta Attribute는 처리 후 어떻게 해야 하는가?

정답: 보통 PostGameplayEffectExecute에서 소비한 뒤 0으로 초기화합니다.

4. Meta Attribute를 복제하지 않는 이유는?

정답: 클라이언트가 봐야 할 장기 상태가 아니라 서버/AttributeSet 내부의 중간 처리 값이기 때문입니다.

관련 노트

  • 어트리뷰트 세트(Attribute Set): Meta Attribute가 선언되고 소비되는 위치
  • 게임플레이 이펙트(GE): Damage 값을 넣는 Modifier/ExecutionCalculation
  • 게임플레이 이펙트의 생성 과정: Spec과 Context로 Damage 값을 전달하는 흐름
  • 레벨과 커브 테이블: Damage Magnitude를 레벨별로 데이터화하는 방식
  • 기간형 게임플레이 이펙트: 지속 Modifier와 순간 Damage 처리의 차이
