C++ / UObject References

UPROPERTY UObject Reference Guide

UPROPERTY() UObject*와 UPROPERTY() TObjectPtr<UObject>는 둘 다 GC가 보는 강한 UObject 참조입니다. 새 reflected 멤버 변수에는 TObjectPtr를 기본 선택지로 두고, 함수 파라미터와 로컬 변수에는 raw pointer를 쓰는 기준으로 정리합니다.

원본: UPROPERTYObjectReferenceGuide.md 난이도: C++ UObject 참조 정책 핵심: UObject*, TObjectPtr, TWeakObjectPtr, TSoftObjectPtr 검수 기준: Unreal Engine 5.7.4

가장 중요한 결론

UPROPERTY() UObject*도 strong reference이고, UPROPERTY() TObjectPtr<UObject>도 strong reference입니다. 차이는 GC가 보느냐가 아니라, TObjectPtr가 엔진의 object handle, access tracking, editor/cook/tooling 경로에 더 잘 맞는 wrapper라는 점입니다.

UE5 방향성

UE5 Migration Guide는 C++ 프로젝트가 raw object pointer를 유지할 수 있지만, TObjectPtr 사용을 선택할 수 있다고 설명합니다. 새 코드에서는 reflected UObject 멤버를 TObjectPtr로 두는 편이 현재 엔진 방향과 코드 리뷰 기준에 더 잘 맞습니다.

실무 선택 기준

강한 멤버 참조

UPROPERTY() TObjectPtr<T>를 기본으로 사용합니다. Component, DataAsset, UObject 멤버 참조가 여기에 해당합니다.

파라미터 / 반환 / 로컬

T* raw pointer를 사용합니다. TObjectPtr를 함수 경계까지 퍼뜨리는 방식은 UE 사용 패턴과 맞지 않습니다.

소유하지 않는 관찰

객체를 살려두면 안 되고 살아 있는지만 확인하려면 TWeakObjectPtr<T>를 사용합니다.

지연 로드 에셋

에셋 경로만 보관하고 필요할 때 로드하려면 TSoftObjectPtr<T> 또는 soft reference를 사용합니다.

시각화 요약: UObject 참조 타입 선택

UPROPERTY 멤버 소유 관계가 있고 GC가 지켜야 하는 새 UObject 멤버는 TObjectPtr<T>를 기본으로 둡니다.
함수 인자 / 로컬 일시적으로 접근만 하는 함수 경계에서는 일반 T*가 가장 자연스럽습니다.
비소유 관찰 객체를 살려두면 안 되는 참조는 TWeakObjectPtr<T>로 생존 여부를 확인합니다.
지연 로드 에셋 로드 비용을 늦추고 싶으면 TSoftObjectPtr<T>로 경로를 보관합니다.
로드 단위 관리 아이템, 스킬, 퀘스트처럼 관리 단위가 필요하면 Primary Asset과 Asset Manager로 올립니다.
주의 raw pointer가 항상 약한 참조라는 뜻은 아닙니다. UPROPERTY() 여부와 컨테이너가 더 중요합니다. 
UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category="Camera")
TObjectPtr<UCameraComponent> CameraComponent = nullptr;

UPROPERTY(EditDefaultsOnly, Category="Config")
TObjectPtr<UDataAsset> ItemConfig = nullptr;

UCameraComponent* GetCameraComponent() const
{
    return CameraComponent;
}

void ApplyDamage(AActor* TargetActor);

성능 관점

TObjectPtr는 보통 프레임 타임을 직접 줄이는 최적화 수단이 아닙니다. 주요 이점은 editor build의 동적 resolve와 access tracking, cook dependency 추적, incremental GC, 리인스턴싱과 직렬화 안정성에 가깝습니다.

hot path 패턴

매우 뜨거운 루프에서는 멤버는 TObjectPtr로 유지하되, 함수 내부에서는 한 번 raw pointer로 받아 반복 접근하는 방식이 자연스럽습니다. 성능은 포인터 타입 자체보다 접근 빈도와 로딩/resolve 경로를 프로파일링해서 판단합니다.

자주 나오는 오해

  • TObjectPtr만 GC safe한 것이 아닙니다. UPROPERTY() UObject*도 GC가 보는 strong reference입니다.
  • TObjectPtr는 TSoftObjectPtr를 대체하지 않습니다. 로드를 미루려면 soft pointer를 사용합니다.
  • TObjectPtr는 TSharedPtr 같은 C++ ownership 포인터가 아닙니다. UObject lifetime은 UE object system이 관리합니다.
  • 기존 raw pointer 멤버가 즉시 틀린 코드는 아닙니다. 다만 새 reflected 멤버는 TObjectPtr로 맞추는 편이 좋습니다.
  • 함수 파라미터와 반환값까지 전부 TObjectPtr로 바꾸는 것은 권장 흐름이 아닙니다.

복습 질문

Q1. UPROPERTY() UObject*와 UPROPERTY() TObjectPtr<UObject>의 가장 중요한 공통점은?

둘 다 GC가 보는 reflected strong reference라는 점입니다.

Q2. 로드를 미루고 싶은 에셋 참조에는 무엇을 써야 하는가?

TObjectPtr가 아니라 TSoftObjectPtr 또는 soft reference를 사용해야 합니다.

Q3. 새 UObject 멤버 변수의 기본 선택지는?

UPROPERTY() TObjectPtr<T>입니다. 함수 파라미터/반환/로컬은 raw T*를 유지합니다.
