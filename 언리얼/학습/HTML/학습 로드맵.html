추천 원칙

문법을 먼저 외우기보다 "이 시스템이 어떤 문제를 해결하는가"를 기준으로 읽는 편이 좋습니다. 예를 들어 GAS를 보기 전에는 Delegate, 언리얼 포인터, Networking의 기본 경계를 먼저 잡으면 이해가 빠릅니다. 구조가 잘 잡히지 않으면 각 문서의 개념 섹션에 포함된 관계도와 흐름도를 먼저 보고 돌아오면 됩니다.

추천 학습 경로

  • 1. 내적과 외적 트레이스, 이동 방향, 애니메이션 방향 판정의 수학 기초를 먼저 정리합니다.
  • 2. 트레이스(Trace) 상호작용, 공격 판정, 타겟팅, 네트워크 검증에서 계속 쓰이는 collision query를 이해합니다.
  • 3. 델리게이트(Delegate) GAS Ability Task, 비동기 이벤트, UI 갱신, Asset Registry 콜백의 기반입니다.
  • 4. 언리얼 포인터 UObject 참조, Soft/Weak/Class pointer, SharedPtr 경계를 먼저 잡은 뒤 에셋과 GAS 문서로 넘어갑니다.
  • 5. Asset Registry 로드하지 않은 에셋을 메타데이터로 찾는 방식을 이해합니다.
  • 6. Asset Manager Primary Asset, Bundle, Soft Reference 기반 로딩 정책을 잡습니다.
  • 7. Behavior Tree 개요 AI Controller, Blackboard, Composite, Decorator, Service, Task의 큰 그림을 잡습니다.
  • 8. Animation 최적화 AnimBP의 Tick 비용, Fast Path, Thread Safe Update를 먼저 이해합니다.
  • 9. Motion Matching Pose Search 기반 로코모션을 Schema, Database, AnimGraph 노드 순서로 봅니다.
  • 10. 언리얼 네트워킹 Authority, Ownership, Relevancy를 잡은 뒤 Replication과 RPC로 나눕니다.
  • 11. GAS 개요 ASC를 중심으로 Ability, Effect, Attribute, Tag, Cue, Task의 연결 구조를 읽습니다.

4주 학습 계획

1주차: 엔진 기초

내적/외적, Trace, Delegate, 언리얼 포인터, Asset Registry/Manager를 읽고 예제 코드를 직접 따라 적습니다.

2주차: AI와 Animation

Behavior Tree 노드 역할과 Animation 최적화, Motion Matching, Motion Warping의 문제 영역을 구분합니다.

3주차: Networking

Replication과 RPC를 상태/요청/연출 관점으로 나누고, ownership과 relevancy 실패 케이스를 설명해 봅니다.

4주차: GAS

ASC, GA, GE, Attribute, Tag, Cue, Task 문서를 연결해서 하나의 스킬 실행 흐름으로 다시 그립니다.

복습 점검

  • Trace가 안 맞을 때 Channel, Object Type, Collision Enabled 중 무엇을 먼저 볼지 설명할 수 있다.
  • UObject 멤버, 함수 파라미터, 지연 로드 에셋 참조에 어떤 포인터 타입을 쓸지 고를 수 있다.
  • Behavior Tree에서 Decorator와 Service를 혼동하지 않는다.
  • Animation Blueprint Event Graph 비용을 줄이는 방법을 설명할 수 있다.
  • RPC가 안 갈 때 ownership과 owning connection을 먼저 확인한다.
  • RepNotify를 서버 로컬 callback으로 오해하지 않는다.
  • GAS에서 Ability 실행, Effect 적용, Attribute 변경, Cue 연출의 책임을 분리할 수 있다.
