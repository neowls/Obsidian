환경 쿼리 시스템(EQS)

EQS는 기억을 저장하는 시스템이 아니라, 실행 시점의 후보를 만들고 테스트로 걸러 점수를 매긴 뒤 RunMode에 맞는 결과를 돌려주는 환경 질의 계층입니다.

런타임 처리 흐름

RequestFEnvQueryRequest가 template, owner, named params를 묶음
ManagerUEnvQueryManager::RunQuery()가 instance 준비
InstanceFEnvQueryInstance가 items, context cache, tests 상태 보관
ExecuteOneStepGenerator 이후 Test를 시간 분할로 진행할 수 있음
FinalizeRunMode에 따라 Single, RandomBest, AllMatching 결과 확정

즉시 함수로만 보면 위험합니다

MaxAllowedTestingTime 안에서 여러 프레임에 나눠 실행될 수 있으므로, 완료 delegate와 BT message 흐름까지 같이 설계해야 합니다.

Generator / Test / Context / ItemType

Generator후보 생성SimpleGrid는 point, PerceivedActors는 actor 후보를 만듭니다.
Test필터와 점수Distance, Trace처럼 후보를 줄이거나 점수를 부여합니다.
Context비교 기준Querier, Target 같은 기준점은 ContextCache에 저장됩니다.
ItemType결과 해석Point인지 Actor인지에 따라 결과와 Blackboard 저장 방식이 달라집니다.
RunMode의미주의점
SingleResult최상위 결과 하나BT에서 가장 흔한 목적지/대상 선택
RandomBest5Pct상위 5% 안 랜덤같은 위치만 반복 선택하는 문제 완화
RandomBest25Pct상위 25% 안 랜덤더 넓은 변동성
AllMatching살아남은 모든 결과BT Blackboard 저장 단계에서는 단일 값으로 축약될 수 있음

복습 질문

Q1. EQS와 Perception의 차이는?

Perception은 자극 기억을 유지하고, EQS는 현재 후보를 평가해 결과를 뽑는 질의 시스템입니다.

Q2. 비싼 테스트를 뒤로 미루는 이유는?

값싼 필터로 후보 수를 먼저 줄이면 Trace/Pathfinding 같은 고비용 테스트 호출량을 줄일 수 있습니다.
