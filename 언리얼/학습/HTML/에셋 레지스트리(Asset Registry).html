Asset Registry / Metadata

에셋 레지스트리(Asset Registry)

Asset Registry는 에셋을 실제로 로드하지 않고도 경로, 클래스, 이름, 태그 같은 메타데이터로 검색할 수 있게 해 주는 인덱스입니다. Content Browser, Asset Manager, 에디터 도구, 빌드 파이프라인의 기반 데이터로 사용됩니다.

원본: 에셋 레지스트리(Asset Registry).md 난이도: 중급 에디터/런타임 데이터 핵심: FAssetData, FARFilter, AssetRegistrySearchable, Async Scan 검수 기준: Unreal Engine 5.7.4

한 줄 정의

Asset Registry는 로드되지 않은 에셋을 포함해 프로젝트 에셋의 메타데이터를 검색 가능한 형태로 보관하는 시스템입니다. 에디터에서는 파일을 비동기로 스캔해 최신 상태를 유지하고, Cooked 빌드에서도 필요한 레지스트리 데이터가 사용됩니다.

원본 내용의 최신화

원본은 이전 문서 기반의 구식 클래스 필터와 FName ObjectPath, AssetClass 흐름이 섞여 있었습니다. UE 5.x에서는 클래스 필터에 ClassPaths와 FTopLevelAssetPath를 사용하는 흐름을 우선으로 정리하는 것이 맞습니다.

에셋 목록 구하기

C++에서는 AssetRegistry 모듈을 로드한 뒤 IAssetRegistry에 질의합니다. 전체 검색은 느릴 수 있으므로, 가능한 경로와 클래스 필터를 함께 쓰는 것이 좋습니다. 

#include "AssetRegistry/AssetRegistryModule.h"

FAssetRegistryModule& AssetRegistryModule =
    FModuleManager::LoadModuleChecked("AssetRegistry");

IAssetRegistry& AssetRegistry = AssetRegistryModule.Get();

TArray StaticMeshes;
AssetRegistry.GetAssetsByClass(
    UStaticMesh::StaticClass()->GetClassPathName(),
    StaticMeshes,
    true
);
함수 용도
GetAssetsByClass 특정 클래스 경로에 해당하는 에셋을 찾습니다. 5.x에서는 전체 클래스 경로를 사용하는 형태를 우선합니다.
GetAssetsByPath 특정 패키지 경로 아래의 에셋을 찾습니다. 재귀 검색 여부를 지정할 수 있습니다.
GetAssetByObjectPath 특정 오브젝트 경로의 에셋 데이터를 찾습니다. 5.x에서는 SoftObjectPath 기반 오버로드를 우선 고려합니다.
GetAllAssets 레지스트리의 모든 에셋을 가져옵니다. 공식 API도 느릴 수 있으므로 필터 사용을 권장합니다.

FARFilter

FARFilter는 Asset Registry 쿼리용 필터 구조체입니다. 공식 5.7 API 설명처럼 각 필터 배열 내부는 OR로 처리되고, 서로 다른 필터 구성 요소는 AND로 결합됩니다. 

FARFilter Filter;
Filter.ClassPaths.Add(UStaticMesh::StaticClass()->GetClassPathName());
Filter.PackagePaths.Add(FName("/Game/Meshes"));
Filter.bRecursivePaths = true;
Filter.bRecursiveClasses = true;

TArray Assets;
AssetRegistry.GetAssets(Filter, Assets);

PackagePaths

검색할 Content 경로입니다. 하위 폴더까지 보려면 bRecursivePaths를 켭니다.

ClassPaths

검색할 에셋 클래스 경로입니다. 구버전의 ClassNames 사용은 피합니다.

TagsAndValues

AssetRegistrySearchable 프로퍼티나 커스텀 태그 값으로 검색할 때 사용합니다.

On Disk Only

디스크에서 수집된 데이터만 사용할지 정합니다. 로드된 UObject 상태와 구분해야 할 때 중요합니다.

FAssetData와 태그

FAssetData는 에셋을 로드하기 전에 알 수 있는 패키지 이름, 경로, 에셋 이름, 클래스 경로, 태그 값을 담습니다. GetAsset()을 호출하면 실제 UObject를 로드할 수 있지만, 단순 검색 단계에서는 가능하면 로드하지 않고 메타데이터만 사용합니다. 

UPROPERTY(EditDefaultsOnly, AssetRegistrySearchable)
FName ItemCategory;

AssetRegistrySearchable

이 메타 지정자는 에셋 저장 시 해당 프로퍼티 값을 레지스트리 태그로 기록하게 합니다. UObject 직계 프로퍼티가 아닌 정보를 검색 가능하게 만들고 싶다면 클래스에서 Asset Registry Tag를 직접 제공하는 방식을 사용합니다.

비동기 스캔과 이벤트

에디터 시작 중 Asset Registry는 파일을 비동기로 스캔합니다. 따라서 초기 시점에는 모든 에셋 정보가 아직 준비되지 않았을 수 있고, 도구 코드는 로딩 완료와 에셋 추가/삭제/이름 변경 이벤트를 고려해야 합니다.

이벤트/함수 의미
OnAssetAdded 새 에셋이 발견되거나 생성되었을 때 호출됩니다.
OnAssetRemoved 레지스트리에서 에셋이 제거되었을 때 호출됩니다.
OnAssetRenamed 에셋 이름이나 경로가 바뀌었을 때 호출됩니다.
OnFilesLoaded 초기 파일 스캔이 완료되었을 때 사용합니다.
IsLoadingAssets 현재 에셋 스캔이 진행 중인지 확인합니다.

콜백은 짧게

OnAssetAdded 같은 레지스트리 콜백에서 무거운 작업을 하면 스캔과 에디터 반응성이 나빠질 수 있습니다. 필요한 데이터만 큐에 넣고 실제 처리는 별도 타이밍에 넘기는 구조가 안전합니다.

복습 질문

Q1. FAssetData::GetAsset()을 남발하면 안 되는 이유는?

메타데이터 검색만 하려던 에셋을 실제 UObject로 로드해 메모리와 로딩 시간을 증가시킬 수 있기 때문입니다.

Q2. UE 5.x에서 클래스 필터를 작성할 때 구버전 Classes 대신 무엇을 우선해야 하는가?

ClassPaths와 FTopLevelAssetPath 기반 흐름을 우선해야 합니다.

Q3. FARFilter에서 배열 내부와 배열 간 조건 결합 방식은?

같은 필터 배열 내부는 OR, 서로 다른 필터 구성 요소는 AND로 처리됩니다.
