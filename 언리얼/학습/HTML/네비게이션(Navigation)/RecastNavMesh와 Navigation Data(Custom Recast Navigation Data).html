Navigation Data / Recast

RecastNavMesh와 Navigation Data

NavigationData는 nav data와 generator의 수명 주기를 조정하고, RecastNavMesh는 실제 recast/detour query와 tiled navmesh build를 연결하는 구현체입니다.

원본: RecastNavMesh와 Navigation Data.md 핵심: ANavigationData, ARecastNavMesh, FRecastNavMeshGenerator

NavData와 Generator 계층

UNavigationSystemV1agent props에 맞는 nav data를 선택합니다.
ANavigationDataconfig, runtime generation, rebuild, generator 수명 관리를 담당합니다.
ARecastNavMeshProjectPoint, FindPath, random point query를 recast impl에 위임합니다.
FRecastNavMeshGeneratorbounds, dirty area, tile task, async build를 관리합니다.
dtNavMesh실제 타일과 polygon 데이터가 저장되는 detour mesh입니다.

Query 경로

FindPathSyncNavigationSystem이 NavData를 채우고 query를 넘김
ARecastNavMeshFindPath, ProjectPoint 같은 public API 진입
Recast Impl실제 navmesh polygon 질의 수행
Resultpath, projected point, random reachable point 반환

Query와 Build는 다른 경로입니다

Pathfinding 실패를 볼 때 dirty area rebuild 문제와 query filter 문제를 같은 층으로 섞지 않아야 합니다.

Build / Rebuild 경로

RebuildAll전체 재빌드전처리 후 generator를 구성하고 모든 bounds를 dirty 처리
Dirty Areas부분 재빌드변경 bounds를 dirty area로 모음
MarkDirtyTiles타일 변환dirty bounds를 tile 좌표와 pending tile로 변환
TickAsyncBuild비동기 빌드task 완료 후 generation finished 알림

Suspend는 공짜가 아닙니다

SetRebuildingSuspended() 상태에서 dirty area가 너무 많이 쌓이면 부분 재생성 대신 전체 rebuild로 승격될 수 있습니다.

복습 질문

Q1. ANavigationData와 ARecastNavMesh의 차이는?

ANavigationData는 공통 수명 주기와 rebuild 관리 기반이고, ARecastNavMesh는 Recast 기반 실제 nav data 구현체입니다.

Q2. 런타임 navmesh 비용의 직접 기준은?

dirty area 개수보다 최종적으로 몇 개 tile이 다시 빌드되는지가 더 직접적입니다.
