Nav Area / Query Filter

커스텀 네비게이션 영역과 Query Filter

NavArea는 polygon의 기본 성질이고, Query Filter는 이번 pathfinding에서 그 area를 얼마나 선호하거나 배제할지 결정하는 정책입니다.

UNavArea월드 polygon에 붙는 기본 비용과 flag를 정의합니다.
FNavigationFilterArea특정 area에 대한 cost override 또는 exclude 한 줄입니다.
UNavigationQueryFilterarea override, include/exclude flags, meta filter 정책을 묶습니다.

Pathfinding에 개입하는 순서

NavMesh Areapolygon은 area id와 flags를 가집니다.
MoveRequestSetNavigationFilter()로 filter class 지정
GetQueryFilterNavData 캐시 또는 새 runtime filter 준비
InitializeFilterarea cost, exclude, include/exclude flags 반영
FindPathruntime filter가 path cost 계산에 사용됨

Cost와 Exclude의 차이

정책효과사용 상황
DefaultCost해당 area를 지날 때 거리 비용을 곱합니다.위험/느린 구역을 우회 유도
FixedAreaEnteringCostarea에 들어갈 때 한 번 비용을 더합니다.짧은 구역도 진입 자체를 꺼리게 할 때
bIsExcluded이번 query에서 해당 area를 경로 후보에서 제거합니다.절대 지나가면 안 되는 상황
UNavArea_Null기본적으로 통과 불가 area입니다.물리적 차단 또는 금지 구역

Meta Filter와 캐시

Meta Filter외부에서는 하나의 filter처럼 보이지만, querier를 보고 실제 simple filter class를 고르는 라우터 역할을 합니다.
bInstantiateForQuerier꺼져 있으면 nav data 캐시의 공유 filter를 재사용하므로 querier별 런타임 상태를 기대하면 안 됩니다.

복습 질문

Q1. Area와 Filter의 차이는?

Area는 월드 polygon의 기본 성질이고, Filter는 이번 pathfinding에서 그 area를 해석하는 정책입니다.

Q2. 우회 유도와 완전 차단은 어떻게 다르게 표현하는가?

우회 유도는 cost 상승, 완전 차단은 exclude 또는 Null area가 더 명확합니다.
