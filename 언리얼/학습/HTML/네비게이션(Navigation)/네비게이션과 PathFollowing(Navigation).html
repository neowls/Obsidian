Navigation / PathFollowing

네비게이션과 PathFollowing

Navigation은 목적지까지의 경로를 계산하고, PathFollowing은 계산된 경로를 상태 기계로 추종하며 도착 또는 실패를 판정합니다. MoveTo는 이 전체 흐름의 진입점입니다.

원본: 네비게이션과 PathFollowing(Navigation).md 핵심: FAIMoveRequest, FindPathSync, UPathFollowingComponent

MoveTo / PathFollowing 실험판

MoveTo는 경로 계산 함수 하나가 아니라 이동 요청 계약입니다. 목적지 조건과 옵션을 바꾸면 Project Goal, HasReached, FindPathSync, RequestMove, FollowPathSegment 중 어느 단계까지 가는지가 달라집니다.

MoveTo 런타임 흐름

MoveToActor/LocationFAIMoveRequest 구성
Project Goal필요하면 목적지를 NavMesh 위로 투영
HasReached이미 도착했으면 path query 없이 성공 처리
Build QueryFPathFindingQuery 생성
FindPathSyncNavSystem이 NavData에 실제 탐색 위임
RequestMovePathFollowingComponent가 경로를 받고 이동 시작

PathFollowing 상태 기계

Idle현재 이동 요청 없음
Waiting경로가 완전히 준비되지 않았거나 observer 대기
MovingUpdatePathSegment()와 FollowPathSegment() 반복
Paused리소스나 외부 제어로 이동 일시 중단

진짜 프레임 단위 이동은 PathFollowing이 담당합니다

Controller는 request를 만들고, path following component가 path observer, segment 갱신, movement component 입력, 완료 결과를 관리합니다.

도착 판정과 Acceptance Radius

ReachMode반경 계산 감각
ExactLocationAcceptance radius만 사용합니다.
OverlapAgentAcceptance radius에 agent 반지름을 포함합니다.
OverlapGoalAcceptance radius에 goal 반지름을 포함합니다.
OverlapAgentAndGoal둘 다 포함하므로 체감 도착 반경이 커집니다.

복습 질문

Q1. 목표가 NavMesh 위가 아니면 무엇을 확인해야 하는가?

SetProjectGoalLocation() 또는 Blueprint의 Project Destination 옵션을 확인합니다.

Q2. MoveTo 호출이 항상 pathfinding을 발생시키는가?

아닙니다. HasReached()가 먼저 성공하면 AlreadyAtGoal로 끝날 수 있습니다.
