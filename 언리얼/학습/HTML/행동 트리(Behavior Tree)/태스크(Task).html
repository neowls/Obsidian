Behavior Tree

태스크(Task)

Task는 Behavior Tree의 리프 노드로, AI가 실제로 수행할 작업입니다. 이동, 대기, 공격, Blackboard 값 변경처럼 실행 결과가 Success, Failure, InProgress로 이어지는 행동을 Task로 만듭니다.

원본: 행동 트리(Behavior Tree)/태스크(Task).md 난이도: BT 행동 노드 핵심: ExecuteTask, FinishExecute, Success, Failure 검수 기준: Unreal Engine 5.7.4

한 줄 정의

Task는 Behavior Tree가 선택한 브랜치에서 실제 행동을 수행하고 결과를 반환하는 리프 노드입니다. 5.7 Python API의 BTTaskNode도 Task를 실제 액션을 수행하는 Behavior Tree leaf node로 설명합니다.

Task에는 Decorator와 Service를 붙일 수 있습니다

Task 자체는 행동을 수행하지만, 실행 조건은 Decorator가 보고 실행 중 필요한 정보 갱신은 Service가 담당할 수 있습니다. 예를 들어 Move To Task에 “TargetActor가 유효할 때만” Decorator를 붙이고, Service가 TargetActor 위치를 갱신하게 만들 수 있습니다.

Task 결과

결과 의미 Composite에 미치는 영향
Succeeded 작업이 성공적으로 끝났습니다. Sequence는 다음 자식으로 진행하고, Selector는 성공으로 멈춥니다.
Failed 작업을 수행할 수 없거나 실패했습니다. Sequence는 실패로 중단하고, Selector는 다음 후보 자식으로 넘어갑니다.
InProgress 작업이 아직 진행 중입니다. Move To, 장시간 액션처럼 완료 신호가 올 때까지 브랜치가 유지됩니다.
Aborted Decorator Abort나 트리 전환으로 중단됐습니다. Task는 진행 중인 이동, 애니메이션, Delegate를 정리해야 합니다.

커스텀 Task 제작 감각

Blueprint Task는 빠르게 반복 제작하기 좋고, C++ Task는 많은 AI가 동시에 쓰는 성능 민감 작업에 적합합니다. 공식 API는 Task Node가 기본적으로 공유될 수 있음을 전제로 하므로, C++에서 런타임 상태를 UObject 멤버에 막 저장하면 안 됩니다.

공유 노드와 NodeMemory

5.7 BTTaskNode API는 인스턴스화되지 않은 Task 노드가 같은 Behavior Tree Asset을 쓰는 여러 AI 사이에서 공유될 수 있음을 경고합니다. C++ Native Task에서 AI별 런타임 상태가 필요하면 인스턴싱 또는 NodeMemory 사용 방식을 명확히 해야 합니다. 

// C++ Task의 개념 흐름
EBTNodeResult::Type UBTTask_Attack::ExecuteTask(
    UBehaviorTreeComponent& OwnerComp,
    uint8* NodeMemory)
{
    AAIController* AI = OwnerComp.GetAIOwner();
    APawn* Pawn = AI ? AI->GetPawn() : nullptr;

    if (!Pawn)
    {
        return EBTNodeResult::Failed;
    }

    // 공격 시작. 즉시 끝나면 Succeeded, 애니메이션 대기가 필요하면 InProgress.
    return EBTNodeResult::Succeeded;
}

Task 설계 체크리스트

  • 이 노드가 실제 행동인지 확인합니다. 조건이면 Decorator, 정보 갱신이면 Service가 더 적합합니다.
  • 성공/실패 기준을 명확히 둡니다. Move To 실패, 타겟 없음, 애니메이션 재생 실패 같은 경우를 분리합니다.
  • InProgress Task는 종료 경로가 있어야 합니다. 완료 콜백, 타임아웃, Abort 정리를 모두 처리합니다.
  • Blueprint Task는 AI 버전 이벤트를 우선 사용합니다. AI Controller 대상이면 Receive Execute AI, Receive Abort AI가 더 명확합니다.
  • 반복 실행되는 많은 AI의 Task는 C++를 검토합니다. Blueprint Task는 빠른 제작에는 좋지만 대규모 AI에서는 비용을 확인해야 합니다.

복습 질문

1. Task는 Behavior Tree에서 어떤 노드인가?

정답: 실제 행동을 수행하는 리프 노드입니다.

2. Task가 실패하면 Sequence는 어떻게 되는가?

정답: Sequence도 실패로 중단됩니다.

3. 오래 걸리는 Task가 반환할 수 있는 결과는?

정답: InProgress입니다. 이후 완료 또는 중단 시 정리해야 합니다.

4. C++ Task에서 AI별 상태를 멤버 변수에 바로 두면 위험한 이유는?

정답: 기본적으로 Task 노드가 여러 AI 사이에서 공유될 수 있기 때문입니다.
