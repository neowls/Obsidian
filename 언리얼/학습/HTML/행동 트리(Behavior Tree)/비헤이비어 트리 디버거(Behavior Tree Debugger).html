Behavior Tree Debugging

비헤이비어 트리 디버거

BT 디버거는 런타임이 저장한 execution step, active path, runtime description, blackboard snapshot을 에디터가 그래프 위에 다시 표시하는 구조입니다.

원본: 비헤이비어 트리 디버거.md 핵심: DebuggerSteps, ExecutionStep, FBehaviorTreeDebugger

디버그 데이터 흐름

BT 실행UBehaviorTreeComponent가 active path를 바꿉니다.
Step 저장StoreDebuggerExecutionStep()가 현재 상태를 기록합니다.
SnapshotBlackboard 값, timestamp, instance stack, runtime desc를 묶습니다.
Editor TickFBehaviorTreeDebugger가 현재 디버그 대상의 step을 읽습니다.
Graph 표시활성 노드, 이전 경로, breakpoint, runtime text를 갱신합니다.

런타임이 저장하는 것

FBehaviorTreeExecutionSteptimestamp, step id, pause 여부, blackboard snapshot을 보관합니다.
FBehaviorTreeDebuggerInstancetree asset, root node, active path, additional active nodes, runtime desc를 보관합니다.
MaxDebuggerSteps스텝은 무한히 쌓이지 않고 manager 설정에 따라 오래된 기록이 잘립니다.

에디터 디버거의 역할

함수/동작역할
OnObjectSelected()선택한 actor에서 실제 실행 중인 BT component를 찾습니다.
OnTreeStarted()새로 시작된 tree instance를 추적 후보로 잡습니다.
UpdateDebuggerInstance()현재 에셋과 맞는 subtree stack을 선택합니다.
UpdateAssetFlags()그래프 노드의 활성/이전 활성/트리거 상태를 갱신합니다.
CollectBreakpointsFromAsset()에셋의 breakpoint를 execution index 목록으로 바꿉니다.

열어 둔 에셋만 보는 도구가 아닙니다

BT 디버거는 실제 PIE 월드에서 해당 에셋을 돌리고 있는 런타임 인스턴스를 찾아 연결합니다.

BT Debugger와 Gameplay Debugger

Behavior Tree DebuggerBT 에셋 그래프 위에서 history, active path, runtime desc, step 이동을 정밀하게 봅니다.
Gameplay Debugger게임 화면 위에서 BT, Blackboard, EQS, Perception 상태를 현장 오버레이로 확인합니다.

복습 질문

Q1. 디버거에 보이는 과거 Blackboard 값은 어디서 오는가?

FBehaviorTreeExecutionStep.BlackboardValues에 저장된 snapshot에서 옵니다.

Q2. Step 이동 기능은 언제 의미가 큰가?

PIE가 pause된 상태에서 breakpoint와 execution step을 따라 원인을 분석할 때 의미가 큽니다.
