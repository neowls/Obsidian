비헤이비어 트리(Behavior Tree)

Behavior Tree는 AI가 현재 상황에 맞는 행동 분기를 선택하고 실행하도록 만드는 시각적 의사결정 그래프입니다. Blackboard가 기억과 판단 재료를 저장하고, Behavior Tree는 그 값을 바탕으로 어떤 Task를 실행할지 정합니다.

원본: 행동 트리(Behavior Tree)/비헤이비어 트리(Behavior Tree).md 난이도: AI 기초 구조 핵심: Blackboard, Composite, Decorator, Service, Task 검수 기준: Unreal Engine 5.7.4

Behavior Tree 실행 실험판

Selector는 왼쪽부터 조건을 평가하고, 조건이 성공한 브랜치의 Task를 실행합니다. Blackboard 값을 바꾸면 Attack, Chase, Patrol 중 어떤 브랜치가 선택되는지 확인할 수 있습니다.

RootAI Controller Tick
Selector왼쪽 우선순위
DecoratorTarget && InRange
Task: Attack공격 실행
DecoratorTarget exists
Task: Move To추격
Fallback조건 없음
Task: Patrol순찰

Evaluate를 누르면 Blackboard 조건에 맞는 브랜치가 점등됩니다.

한 줄 정의

Behavior Tree는 AI Controller가 실행하는 의사결정 트리이고, Blackboard는 그 트리가 읽고 쓰는 공유 메모리입니다. 예를 들어 HasLineOfSight, TargetActor, PatrolLocation 같은 Blackboard Key를 보고 추격, 순찰, 공격 브랜치를 선택합니다.

Behavior Tree와 Blackboard의 분리

Behavior Tree는 “어떤 행동을 할지”를 구성하고, Blackboard는 “판단에 필요한 현재 정보”를 저장합니다. AI Perception, EQS, Service, Task가 Blackboard 값을 갱신하면 Decorator와 Composite가 그 값을 기준으로 실행 흐름을 바꿉니다.

기본 실행 흐름

언리얼 Behavior Tree는 그래프 배치 순서를 기준으로 왼쪽에서 오른쪽, 위에서 아래로 우선순위를 판단합니다. 보통 AI Controller가 Pawn을 Possess한 뒤 Behavior Tree를 실행하고, Pawn이 이동하려면 Nav Mesh도 필요합니다.

1. Blackboard Key 정의 AI가 알아야 할 Target, Bool, Vector 값을 만듭니다.
2. Tree 브랜치 구성 Composite 아래에 Decorator, Service, Task를 배치합니다.
3. AI Controller Run Behavior Tree Possess 또는 BeginPlay 흐름에서 BT Asset을 실행합니다.
4. Evaluate 조건 판단 Decorator가 Blackboard 값을 보고 브랜치 진입/중단을 결정합니다.
5. Act Task 수행 Move To, Wait, Attack 같은 실제 작업을 실행합니다.

시각화 요약: 판단 데이터에서 행동까지

AI Controller Pawn을 Possess하고 Behavior Tree 실행을 시작합니다.
Blackboard Target, Location, Bool 같은 판단용 공유 값을 저장합니다.
Composite Selector, Sequence가 우선순위와 실행 순서를 정합니다.
Decorator / Service 조건을 검사하고 반복 관찰 값은 Service가 갱신합니다.
Task Move To, Attack, Wait처럼 실제 행동을 수행합니다.

이벤트 주도형으로 이해합니다

언리얼 Behavior Tree는 매 프레임 전체 트리를 무작정 다시 평가하는 모델보다 이벤트와 Blackboard 변화에 반응하는 구조에 가깝습니다. 따라서 조건은 Task 리프 노드로 만들기보다 Decorator로 붙이고, 반복 관찰은 Service로 나누는 편이 디버깅과 성능에 유리합니다.

노드 역할 지도

노드 역할 대표 질문
Composite 자식 브랜치를 어떤 규칙과 순서로 실행할지 정합니다. 여러 후보 중 하나를 고를 것인가, 순서대로 모두 성공해야 하는가?
Decorator 브랜치 또는 노드를 실행할 수 있는 조건을 검사합니다. 이 분기는 지금 열려 있는가? 조건이 바뀌면 중단해야 하는가?
Service 브랜치가 활성인 동안 일정 간격으로 정보 갱신을 수행합니다. 타겟, 거리, 시야, EQS 결과를 계속 갱신해야 하는가?
Task AI가 실제로 수행할 작업입니다. 이동, 대기, 공격, Blackboard 값 쓰기 같은 액션은 무엇인가?

구성 팁

  • 왼쪽 브랜치에 높은 우선순위를 둡니다. 추격/공격처럼 더 긴급한 행동을 순찰보다 왼쪽에 배치합니다.
  • 조건은 Decorator로 표현합니다. 조건 확인 Task를 리프에 두면 실제 행동과 판단이 섞입니다.
  • 지식 갱신은 Service로 분리합니다. 시야, 거리, EQS 결과는 Task마다 계산하지 말고 Blackboard에 갱신합니다.
  • 실제 액션은 Task로 둡니다. Move To, Wait, Attack처럼 성공/실패/진행 중 결과가 있어야 합니다.
  • 움직임이 필요하면 Nav Mesh를 먼저 확인합니다. Move To 실패는 트리 문제가 아니라 내비게이션 설정 문제일 수 있습니다.

복습 질문

1. Behavior Tree와 Blackboard의 차이는?

정답: Behavior Tree는 행동 흐름이고, Blackboard는 판단에 필요한 데이터를 저장하는 공유 메모리입니다.

2. 조건문 역할을 하는 BT 노드는?

정답: Decorator입니다.

3. 브랜치 활성 중 주기적으로 Blackboard를 갱신하는 노드는?

정답: Service입니다.

4. 실제 AI 행동을 수행하는 리프 노드는?

정답: Task입니다.

관련 노트

  • 컴포짓(Composite): Selector, Sequence, Simple Parallel의 실행 규칙
  • 데코레이터(Decorator): 브랜치 조건과 Observer Aborts
  • 서비스(Service): 활성 브랜치의 주기적 정보 갱신
  • 태스크(Task): AI가 수행하는 실제 작업
