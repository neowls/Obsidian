Behavior Tree

서비스(Service)

Service는 Behavior Tree의 브랜치가 활성화되어 있는 동안 일정 주기로 실행되는 보조 노드입니다. 보통 AI Perception, 거리 계산, EQS, 타겟 유효성 검사 결과를 Blackboard에 갱신하는 데 사용합니다.

원본: 행동 트리(Behavior Tree)/서비스(Service).md 난이도: BT 정보 갱신 핵심: Interval, Blackboard Update, Background Knowledge 검수 기준: Unreal Engine 5.7.4

한 줄 정의

Service는 Composite 또는 Task에 붙어, 해당 브랜치가 실행 중일 때 주기적으로 AI 지식을 갱신하는 노드입니다. 5.7 API의 UBTService도 AI의 지식을 업데이트하는 백그라운드 작업으로 설명합니다.

전통적 Parallel 노드의 일부 역할을 대체합니다

언리얼 Behavior Tree는 복잡한 병렬 노드 대신 Service와 Decorator Abort를 조합해 “행동하면서 관찰하기”를 구성하는 경우가 많습니다. 예를 들어 순찰 브랜치가 실행되는 동안 Service가 시야를 갱신하고, 타겟이 보이면 Decorator가 추격 브랜치로 전환합니다.

실행 주기

설정 의미 설계 감각
Interval Service가 다시 실행될 시간 간격입니다. 자주 바뀌는 시야/거리 정보는 짧게, 비용 큰 EQS는 길게 둡니다.
Random Deviation 실행 간격에 랜덤 편차를 더합니다. 많은 AI가 같은 프레임에 Service를 실행하는 스파이크를 줄입니다.
Call Tick on Search Start 브랜치 진입 검색 시점에도 Tick을 호출합니다. 브랜치 시작 즉시 Blackboard 값을 갱신해야 할 때 유용합니다.
Restart Timer on Each Activation 브랜치가 다시 활성화될 때 타이머를 초기화합니다. 재진입 때마다 같은 지연을 줄지, 기존 리듬을 유지할지 결정합니다.

좋은 Service와 나쁜 Service

잘 맞는 작업

  • TargetActor, LastKnownLocation, HasLineOfSight Blackboard 갱신
  • 거리, 사거리, 커버 위치, EQS 결과 계산
  • 현재 브랜치가 활성인 동안만 필요한 관찰

피해야 할 작업

  • Move To, Attack처럼 성공/실패 결과가 필요한 실제 행동
  • 한 번만 실행하면 되는 초기화 작업을 짧은 Interval로 반복
  • 매 프레임 비싼 탐색을 모든 AI가 동시에 수행

Service는 실행 결과를 반환하지 않습니다

Task처럼 Success/Failure/InProgress를 반환해 트리 흐름을 직접 바꾸는 노드가 아닙니다. Service는 Blackboard 값을 갱신하고, 그 값에 붙은 Decorator가 실행 흐름을 바꾸게 만드는 것이 일반적인 설계입니다.

복습 질문

1. Service는 언제 실행되는가?

정답: 붙어 있는 Composite 또는 Task의 브랜치가 활성화되어 있는 동안 정의된 빈도로 실행됩니다.

2. Service가 주로 갱신하는 대상은?

정답: Blackboard Key입니다.

3. Service가 직접 Success/Failure를 반환해 흐름을 바꾸는가?

정답: 아닙니다. 흐름 변경은 보통 Decorator 조건과 Abort가 담당합니다.

4. 많은 AI가 있을 때 Random Deviation이 유용한 이유는?

정답: 같은 프레임에 Service가 몰리는 부하 스파이크를 줄일 수 있기 때문입니다.

관련 노트

  • 태스크(Task): Service와 달리 실제 작업 결과를 반환하는 노드
