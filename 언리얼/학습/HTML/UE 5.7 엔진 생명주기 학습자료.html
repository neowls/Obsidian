UE 5.7 엔진 생명주기

언리얼 생명주기는 하나가 아니라 프로세스/엔진 루프, 게임 세션, 액터, UObject/GC 생명주기가 겹쳐 돌아가는 구조입니다. 핵심은 훅 이름보다 어떤 경로에서 그 훅에 도달하는지를 보는 것입니다.

Session게임 세션UGameInstance -> Browse -> LoadMap -> UWorld -> StartPlay
Actor액터Load / PIE Duplicate / Spawn -> Initialize -> BeginPlay -> EndPlay
UObject객체와 GCNewObject / PostLoad -> 사용 -> BeginDestroy -> FinishDestroy

GEngine 생성FEngineLoop::Init이 엔진 구현체 결정
GameInstance맵보다 먼저 세션 객체 생성
LoadMap월드 생성/교체와 플레이 준비
Tick / GC프레임 루프와 조건부 garbage collection

LoadMap에서 BeginPlay까지

LoadMapInitWorld월드를 루트에 붙이고 초기화합니다.
RuleSetGameMode서버 기준 GameMode를 세팅합니다.
AICreateAISystem월드 AI 시스템을 준비합니다.
ActorInitializeActorsForPlay네트워크 액터, GameMode InitGame, 컴포넌트 초기화 루프
PlayerSpawnPlayActor로컬 플레이어용 pawn/controller 흐름
PlayBeginPlayGameMode -> GameState -> WorldSettings -> Actor로 라우팅

BeginPlay는 World가 직접 모든 Actor를 바로 호출하는 모델이 아닙니다

UWorld::BeginPlay -> GameModeBase::StartPlay -> GameStateBase::HandleBeginPlay -> WorldSettings::NotifyBeginPlay -> Actor::DispatchBeginPlay 체인으로 이해해야 합니다.

Disk LoadPostLoad레벨/패키지에서 로드된 액터는 저장 데이터 보정이 핵심입니다.
PIEPostDuplicate에디터 월드의 액터를 PIE 월드로 복제해 플레이용으로 준비합니다.

PostInitializeComponents액터와 컴포넌트가 실질적으로 조립 완료
DispatchBeginPlay조건 만족 시 컴포넌트 BeginPlay와 ReceiveBeginPlay 전파

UObject와 GC

NewObject 경로StaticConstructObject_Internal -> C++ 생성자 -> PostInitProperties
로드 경로ConditionalPostLoad -> PostLoad. 저장된 옛 값 보정은 주로 여기서 수행합니다.
파괴 경로Destroy는 제거 요청이고, 실제 메모리 해제는 GC 파이프라인에서 일어납니다.
CollectGarbageGC 요청
Reachability도달 가능성 분석
BeginDestroy도달 불가 객체 파괴 시작
IncrementalPurge시간 제한 기반 purge
FinishDestroy최종 파괴와 메모리 회수

어떤 훅에 코드를 넣을까

훅맞는 용도주의
생성자기본 서브오브젝트 생성, 기본값 설정월드/게임플레이 상태를 가정하지 않음
PostLoad저장 데이터 마이그레이션, deprecated property fixup스폰 액터에서는 호출되지 않음
OnConstruction에디터 배치/런타임 스폰 construction 결과 조정게임플레이 시작 훅이 아님
PostInitializeComponents컴포넌트 간 참조 연결, 런타임 준비, 복제 설정Super 호출 누락 주의
BeginPlay타이머 시작, AI 시작, 외부 시스템 등록construction과 구분
EndPlaydelegate 해제, 타이머 중지, gameplay cleanup대부분의 gameplay cleanup은 여기
BeginDestroy/FinishDestroylow-level 자원 정리gameplay logic cleanup 용도로 쓰지 않음

복습 질문

Q1. LoadMap의 핵심 순서는?

InitWorld -> SetGameMode -> CreateAISystem -> InitializeActorsForPlay -> SpawnPlayActor -> BeginPlay입니다.

Q2. Destroy 직후 메모리가 바로 사라지는가?

아닙니다. Destroy()는 제거 요청이고 실제 해제는 GC의 BeginDestroy -> FinishDestroy 파이프라인에서 일어납니다.
