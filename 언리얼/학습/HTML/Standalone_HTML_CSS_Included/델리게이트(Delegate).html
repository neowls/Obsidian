델리게이트(Delegate)

Delegate는 호출하는 쪽이 대상 클래스의 구체 타입을 몰라도, 미리 약속한 함수 시그니처를 안전하게 호출할 수 있게 해 주는 언리얼의 콜백 시스템입니다. 싱글캐스트, 멀티캐스트, 다이내믹 델리게이트를 목적에 맞게 구분하는 것이 핵심입니다.

원본: 델리게이트(Delegate).md 난이도: 중급 C++ 핵심: DECLARE_DELEGATE, BindUObject, Broadcast, Dynamic Delegate 검수 기준: Unreal Engine 5.7.4

Broadcast 흐름 시각화

멀티캐스트 델리게이트는 이벤트 발행자가 구체 객체를 직접 호출하지 않고, 바인딩된 리스너들에게 같은 알림을 전달합니다. 아래 실험판에서 리스너를 켜고 끈 뒤 Broadcast를 눌러 호출 흐름을 확인하세요.

Publisher HealthComponent 체력이 바뀌면 이벤트를 발행합니다.
Multicast Delegate FOnHealthChanged Broadcast(NewHealth)

대기 중입니다. 바인딩된 리스너는 밝은 테두리로 표시됩니다.

한 줄 정의

Delegate는 함수 포인터를 언리얼 객체 수명, 리플렉션, 멀티캐스트 이벤트 흐름에 맞게 확장한 타입 안전 콜백입니다. UI 버튼 클릭, 보스 사망 이벤트, 비동기 로딩 완료, GAS 이벤트처럼 "나중에 누군가에게 알려야 하는" 구조에 자주 사용됩니다.

종류 특징 대표 실행 함수
Single-cast 한 함수만 바인딩합니다. 반환값이 필요한 콜백에 적합합니다. Execute, ExecuteIfBound
Multi-cast 여러 함수를 바인딩해 한 번에 알립니다. 반환값은 사용할 수 없습니다. Broadcast
Dynamic UObject 리플렉션 기반으로 직렬화와 블루프린트 바인딩을 지원하지만 일반 델리게이트보다 느립니다. Execute, Broadcast
Event 멀티캐스트 델리게이트를 감싸 외부에서는 바인딩만 허용하고, 소유자만 Broadcast하도록 제한하는 패턴입니다. 소유자 내부에서 Broadcast

선언 매크로

Delegate 타입은 함수 시그니처에 맞는 매크로로 선언합니다. 반환값, 파라미터 수, 멀티캐스트 여부, Dynamic 여부에 따라 매크로 이름이 달라집니다. 

DECLARE_DELEGATE(FOnSimple);
DECLARE_DELEGATE_OneParam(FOnMessage, const FString&);
DECLARE_DELEGATE_RetVal_OneParam(bool, FCanUseItem, int32);

DECLARE_MULTICAST_DELEGATE_OneParam(FOnHealthChanged, float);
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnHealthChangedBP, float, NewHealth);

Dynamic Delegate 규칙

Dynamic Delegate에 바인딩될 함수는 UObject 리플렉션을 통해 찾을 수 있어야 하므로 보통 UFUNCTION()이 필요합니다. 블루프린트 노출이나 직렬화가 필요하지 않다면 일반 C++ Delegate가 더 가볍습니다.

바인딩 방식

함수 대상 주의점
BindStatic / AddStatic 전역 함수, static 함수 객체 수명 추적이 필요 없는 함수에 사용합니다.
BindRaw / AddRaw raw C++ 포인터 객체 수명을 추적하지 않으므로 삭제 후 호출하면 위험합니다.
BindSP / AddSP Shared Pointer 기반 객체 약한 참조로 수명을 확인할 수 있습니다.
BindUObject / AddUObject UObject 멤버 함수 UObject 약한 참조를 유지하므로 ExecuteIfBound와 함께 쓰기 좋습니다.
BindDynamic / AddDynamic UFUNCTION 기반 Dynamic Delegate 함수 이름 기반 리플렉션을 사용합니다. 블루프린트 이벤트에 적합합니다.

실행과 해제

싱글캐스트 델리게이트는 실행 전에 바인딩 여부를 확인해야 합니다. 반환값이나 출력 파라미터가 있는 델리게이트를 바인딩 없이 실행하면 유효하지 않은 값을 읽을 수 있습니다. 

DECLARE_DELEGATE_OneParam(FStringDelegate, const FString&);

class FLogWriter
{
public:
    void WriteToLog(const FString& Message);
};

FStringDelegate WriteToLogDelegate;
TSharedRef LogWriter = MakeShared();

WriteToLogDelegate.BindSP(LogWriter, &FLogWriter::WriteToLog);
WriteToLogDelegate.ExecuteIfBound(TEXT("함수가 바인딩되었을 때만 실행"));

Single-cast

Execute는 바인딩을 전제로 실행합니다. 안전 호출은 IsBound 또는 ExecuteIfBound를 사용합니다.

Multi-cast

Broadcast는 아무도 바인딩되어 있지 않아도 호출 자체는 안전합니다. 호출 순서는 보장하지 않는다고 보는 편이 좋습니다.

복습 질문

Q1. Dynamic Delegate를 쓰는 대표 이유는?

직렬화, 리플렉션, 블루프린트 바인딩이 필요할 때 사용합니다.

Q2. BindRaw가 위험한 이유는?

raw 포인터 대상 객체의 수명을 델리게이트가 추적하지 않기 때문에, 객체 삭제 후 호출하면 잘못된 메모리를 호출할 수 있습니다.

Q3. 멀티캐스트 델리게이트가 반환값을 쓰지 않는 이유는?

여러 함수가 동시에 호출되므로 하나의 반환값을 의미 있게 정하기 어렵기 때문입니다.
