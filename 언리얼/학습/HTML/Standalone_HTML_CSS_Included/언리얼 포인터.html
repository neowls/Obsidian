C++ / Pointer Ownership

언리얼 포인터

언리얼 C++의 포인터 선택은 C++ 문법 문제가 아니라 UObject GC가 보는가, 에셋 로드를 미룰 것인가, 클래스를 고르는 참조인가, 일반 C++ 객체의 소유권인가를 먼저 나누는 설계 문제입니다.

신규 학습자료 난이도: C++ 참조 정책 핵심: TObjectPtr, Weak, Soft, Subclass, SharedPtr 검수 기준: Unreal Engine 5.7.4

포인터 선택 실험판

아래에서 참조 대상과 사용 의도를 바꾸면 추천 포인터, GC/로드 흐름, 샘플 코드가 함께 바뀝니다. 포인터 이름을 외우기보다 어떤 시스템이 수명을 책임지는지를 먼저 확인하세요.

Target
Intent
Recommended UPROPERTY() TObjectPtr<T>

UObject 멤버를 강하게 보관하고 GC가 추적해야 할 때 기본 선택지입니다.

GC: strong reference Load: 이미 로드된 객체 Scope: reflected member
  • 새 reflected UObject 멤버에는 TObjectPtr를 기본으로 둡니다.
  • 함수 파라미터까지 TObjectPtr로 퍼뜨릴 필요는 없습니다.
Sample 
UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category="Camera")
TObjectPtr<UCameraComponent> Camera = nullptr;

Owner의 reflected property가 Target을 강하게 잡고, GC가 이 참조를 reachability 계산에 포함합니다.

먼저 나눌 기준

UObject인가?

Actor, Component, DataAsset처럼 UObject 계층이면 수명은 UE의 GC와 reflection 시스템을 기준으로 봅니다.

로드를 미룰 것인가?

항상 로드되어도 되는 참조는 hard reference, 필요할 때 로드할 참조는 soft reference로 둡니다.

클래스인가 인스턴스인가?

Spawn할 타입을 고르는 값은 인스턴스 포인터가 아니라 TSubclassOf 또는 TSoftClassPtr입니다.

일반 C++ 객체인가?

UObject가 아니면 TUniquePtr, TSharedPtr, TWeakPtr 같은 C++ ownership 도구를 사용합니다.

UObject 포인터 계열

타입 주 용도 GC / 로드 의미 대표 패턴
T* 함수 인자, 반환값, 로컬 변수 그 자체로는 GC 추적 정보가 아닙니다. UPROPERTY() 멤버인지가 중요합니다. void Hit(AActor* Target)
TObjectPtr<T> 새 reflected UObject 멤버의 기본 선택 UPROPERTY와 함께 hard reference로 직렬화, GC, editor tooling 경로에 들어갑니다. UPROPERTY() TObjectPtr<UCameraComponent> Camera;
TWeakObjectPtr<T> 객체를 살려두지 않는 관찰자 GC 생존을 보장하지 않습니다. 사용 전 IsValid() 또는 Get() 확인이 필요합니다. TWeakObjectPtr<AActor> LastTarget;
TSoftObjectPtr<T> 에셋 경로 보관, 지연 로드 대상 패키지를 즉시 로드하지 않고 FSoftObjectPath 기반으로 나중에 로드합니다. UPROPERTY() TSoftObjectPtr<UDataAsset> Config;
TStrongObjectPtr<T> UObject가 아닌 C++ scope에서 임시로 UObject를 강하게 보관 RAII로 GC reference를 유지합니다. 일반 멤버 설계의 기본값은 아닙니다. TStrongObjectPtr<UObject> Temp = NewObject<UObject>();

raw pointer 오해

UObject*가 항상 약한 참조라는 뜻은 아닙니다. UPROPERTY() UObject* 멤버는 GC가 볼 수 있는 hard reference입니다. 다만 UE5 새 reflected 멤버는 TObjectPtr로 작성하는 쪽이 엔진의 object handle/tooling 방향과 더 잘 맞습니다.

클래스 포인터

TSubclassOf<T> 이미 로드된 UClass를 타입 안전하게 보관합니다. Spawn할 Actor 클래스, Ability 클래스, Widget 클래스 선택에 자주 씁니다.
TSoftClassPtr<T> Blueprint class asset을 바로 로드하지 않고 경로로 보관합니다. 큰 콘텐츠 목록이나 선택형 클래스에 적합합니다.
UClass* 함수 내부에서 이미 구한 클래스에 접근하거나 low-level API와 주고받을 때 자연스럽습니다. 
UPROPERTY(EditDefaultsOnly, Category="Spawn")
TSubclassOf<AEnemyCharacter> EnemyClass;

UPROPERTY(EditDefaultsOnly, Category="Spawn")
TSoftClassPtr<AEnemyCharacter> BossClassAsset;

if (UClass* LoadedClass = BossClassAsset.LoadSynchronous())
{
    GetWorld()->SpawnActor<AEnemyCharacter>(LoadedClass, SpawnTransform);
}

UObject가 아닌 C++ 객체

TSharedPtr와 TUniquePtr는 UObject 수명 관리 도구가 아닙니다. Slate, editor helper, 순수 C++ 모델처럼 UObject가 아닌 객체에 사용합니다.

타입 의미 주의점
TUniquePtr<T> 한 곳만 소유하는 heap 객체 복사 불가, 이동 가능. UObject에는 보통 쓰지 않습니다.
TSharedPtr<T> 여러 곳이 공유 소유하는 nullable 객체 참조 카운팅입니다. 순환 참조는 TWeakPtr로 끊습니다.
TSharedRef<T> null이 될 수 없는 shared reference Slate widget 생성 패턴에서 자주 보입니다.
TWeakPtr<T> shared object를 살려두지 않는 관찰자 사용 전 Pin()으로 TSharedPtr를 얻어야 합니다.

실무 패턴

1 멤버 UObject UPROPERTY() TObjectPtr<UActorComponent>
2 함수 경계 AActor*, const FHitResult&
3 비소유 관찰 TWeakObjectPtr<AActor>
4 지연 로드 TSoftObjectPtr<UDataAsset>
5 Spawn 클래스 TSubclassOf<AActor>
6 순수 C++ TUniquePtr / TSharedPtr

자주 틀리는 지점

  • TObjectPtr는 TSoftObjectPtr의 대체재가 아닙니다. 로드를 미루려면 soft pointer가 필요합니다.
  • TSharedPtr<UObject>로 UObject lifetime을 관리하려 하지 않습니다. UObject는 GC와 Outer/UPROPERTY 관계로 봅니다.
  • TWeakObjectPtr를 캐시했다면 사용할 때마다 유효성을 확인합니다.
  • TSubclassOf는 인스턴스가 아니라 클래스 선택입니다. Spawn 전까지 실제 Actor는 없습니다.
  • 함수 파라미터, 로컬 변수, 반환값까지 전부 TObjectPtr로 바꾸면 코드가 불필요하게 무거워집니다.

복습 질문

Q1. 새 reflected UObject 멤버의 기본 선택지는?

UPROPERTY() TObjectPtr<T>입니다. GC가 보는 hard reference이고 UE5 object handle/tooling 경로에 맞습니다.

Q2. 사용하지 않을 수도 있는 큰 에셋을 멤버로 고르게 하고 싶다면?

TSoftObjectPtr<T> 또는 클래스라면 TSoftClassPtr<T>로 경로를 보관하고 필요할 때 로드합니다.

Q3. 일반 C++ 객체를 여러 Slate 위젯에서 공유하려면?

UObject가 아니라면 TSharedPtr/TSharedRef를 사용하고, 소유하지 않는 쪽은 TWeakPtr를 사용합니다.
