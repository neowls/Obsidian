Gameplay Ability System

어트리뷰트 세트(Attribute Set)

Attribute Set은 체력, 마나, 스태미나, 공격력 같은 게임플레이 수치를 모아 두는 GAS 데이터 묶음입니다. 값 자체는 FGameplayAttributeData로 정의하고, 변경은 대부분 Gameplay Effect를 통해 흐르게 만드는 것이 핵심입니다.

원본: 게임 어빌리티 시스템(GAS)/어트리뷰트 세트(Attribute Set).md 난이도: GAS 수치 기초 핵심: AttributeSet, GameplayAttributeData, BaseValue, CurrentValue 검수 기준: Unreal Engine 5.7.4

한 줄 정의

Attribute Set은 ASC가 소유한 게임플레이 수치의 구조체 모음입니다. 공식 5.7 문서의 GameplayAttributeData는 AttributeSet 안에 두어 FGameplayAttribute로 접근할 수 있는 값이며, raw float 대신 이 타입 사용이 권장됩니다.

ASC와 Attribute Set의 관계

ASC는 자신과 연결된 Attribute Set을 통해 Attribute 값을 찾고, Gameplay Effect가 적용될 때 어떤 Attribute를 바꿔야 하는지 해석합니다. 그래서 Attribute Set은 단순 저장소이면서 동시에 GE 적용 전후 검증과 후처리의 기준점입니다.

Attribute Set

UAttributeSet을 상속해 만든 수치 묶음입니다. 캐릭터의 핵심 스탯을 기능별로 나눠 보관합니다.

Gameplay Attribute

Attribute Set 안의 특정 속성을 가리키는 핸들입니다. GE Modifier가 어떤 값을 바꿀지 지정할 때 사용합니다.

GameplayAttributeData

BaseValue와 CurrentValue를 함께 가진 Attribute 값 타입입니다.

Accessors

반복되는 Getter, Setter, Init 함수를 매크로로 만들어 Attribute 접근을 단순화합니다.

BaseValue와 CurrentValue

FGameplayAttributeData는 단순 float 하나가 아니라 BaseValue와 CurrentValue를 함께 봐야 합니다. 이 차이를 이해하면 Instant GE와 Duration/Infinite GE의 차이도 자연스럽게 연결됩니다.

값 의미 대표 변화
BaseValue Attribute의 기준값입니다. 영구 변화나 Instant GE 결과가 주로 여기에 반영됩니다. 피해로 체력 자체 감소, 레벨업으로 최대 체력 증가, 장비 교체 시 기본 스탯 재계산
CurrentValue BaseValue에 활성 GE Modifier가 합쳐진 현재 계산 결과입니다. 5초 이동속도 버프, 독에 의한 임시 저항 감소, 오라로 인한 공격력 증가

Attribute는 직접 수정하지 않는 습관이 중요합니다

원본 노트처럼 Attribute는 일반적으로 Gameplay Effect를 통해 수정해야 ASC가 예측, 복제, GE 집계, 콜백 흐름을 제대로 추적할 수 있습니다. 초기화나 특수 보정이 아니라면 Health = 50처럼 직접 대입하는 코드는 피하는 편이 안전합니다.

Modifier 집계 감각

5.7의 GameplayModOp는 Modifier를 다음 계산 흐름으로 집계합니다. 이 흐름 때문에 “버프가 CurrentValue에 붙는다”는 말은 실제로는 여러 연산 그룹이 순서대로 합쳐진다는 뜻입니다. 

((BaseValue + AddBase) * MultiplyAdditive / DivideAdditive * MultiplyCompound) + AddFinal
설계 질문 해석
피해가 BaseValue를 영구히 줄여야 하는가? Instant GE나 ExecutionCalculation을 통해 최종 체력 BaseValue에 반영하는 구조를 봅니다.
버프가 끝나면 원래 값으로 돌아와야 하는가? Duration/Infinite GE Modifier로 CurrentValue 계산에만 참여하게 만듭니다.
임시 계산값을 거쳐 후처리해야 하는가? Damage 같은 Meta Attribute를 사용해 PostGameplayEffectExecute에서 체력/실드로 분배합니다.

Attribute Set 주요 콜백

Attribute Set은 값이 바뀌는 순간에 개입할 수 있는 콜백을 제공합니다. 콜백은 단순 로그용이 아니라 클램프, 후처리, 파생 값 갱신, Meta Attribute 소비에 사용됩니다.

콜백 호출 시점 잘 맞는 작업
PreAttributeChange CurrentValue가 바뀌기 직전 이동속도, 최대 체력 같은 값의 상한/하한 클램프
PostAttributeChange CurrentValue가 바뀐 직후 UI 알림, 파생 값 갱신, 디버그 추적
PreGameplayEffectExecute Instant GE나 Execution 결과가 적용되기 직전 최종 적용 가능 여부 검사, 면역/방어 조건 확인
PostGameplayEffectExecute GE 실행 결과가 적용된 직후 Damage Meta Attribute를 Health/Shield에 분배, Health 클램프, 사망 판정

클램프 위치를 구분합니다

임시 버프까지 포함한 CurrentValue의 제한은 PreAttributeChange가 자연스럽습니다. Instant GE로 BaseValue가 바뀐 뒤 체력 0~MaxHealth를 보정하거나 Damage를 소비하는 로직은 PostGameplayEffectExecute에서 처리하는 편이 이해하기 쉽습니다.

C++ 작성 감각

Attribute Set은 선언이 반복되므로 프로젝트 매크로로 접근자를 만드는 패턴이 일반적입니다. 아래 코드는 구조 감각을 위한 축약 예시입니다. 

UCLASS()
class UProjectAttributeSet : public UAttributeSet
{
    GENERATED_BODY()

public:
    UPROPERTY(BlueprintReadOnly, ReplicatedUsing = OnRep_Health)
    FGameplayAttributeData Health;
    ATTRIBUTE_ACCESSORS(UProjectAttributeSet, Health)

    UPROPERTY(BlueprintReadOnly, ReplicatedUsing = OnRep_MaxHealth)
    FGameplayAttributeData MaxHealth;
    ATTRIBUTE_ACCESSORS(UProjectAttributeSet, MaxHealth)

    virtual void PreAttributeChange(
        const FGameplayAttribute& Attribute,
        float& NewValue) override;

    virtual void PostGameplayEffectExecute(
        const FGameplayEffectModCallbackData& Data) override;
};

복습 질문

1. Attribute Set은 무엇을 모아 두는가?

정답: 체력, 마나, 이동속도, 공격력 같은 Gameplay Attribute 값을 모아 둡니다.

2. BaseValue와 CurrentValue의 차이는?

정답: BaseValue는 기준값이고, CurrentValue는 활성 GE Modifier가 반영된 현재 계산 결과입니다.

3. Attribute를 GE로 수정하는 이유는?

정답: ASC가 예측, 복제, Modifier 집계, 콜백, 디버깅 흐름을 추적할 수 있기 때문입니다.

4. Damage를 Health에 분배하는 후처리는 어디가 적합한가?

정답: 보통 PostGameplayEffectExecute에서 처리합니다.

관련 노트

  • 어빌리티 시스템 컴포넌트(ASC): Attribute Set을 보유하고 조회하는 중심 컴포넌트
  • 게임플레이 이펙트(GE): Attribute를 변경하는 데이터 규칙
  • 기간형 게임플레이 이펙트: CurrentValue 계산에 참여하는 지속 Modifier
  • 메타(Meta) 어트리뷰트: Damage 같은 임시 계산용 Attribute 설계
  • 레벨과 커브 테이블: 레벨별 초기 스탯과 Modifier Magnitude 설계
