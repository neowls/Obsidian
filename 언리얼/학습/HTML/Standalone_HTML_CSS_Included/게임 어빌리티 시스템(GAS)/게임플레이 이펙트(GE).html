Gameplay Ability System

게임플레이 이펙트(GE)

Gameplay Effect는 Attribute와 Gameplay Tag를 바꾸는 데이터 중심 규칙입니다. 데미지, 회복, 버프, 디버프, 비용, 쿨다운, 지속 회복처럼 “게임 상태를 바꾸는 일” 대부분이 GE를 통해 표현됩니다.

원본: 게임 어빌리티 시스템(GAS)/게임플레이 이펙트(GE).md 난이도: GAS 핵심 핵심: DurationPolicy, Modifier, Attribute, ExecutionCalculation 검수 기준: Unreal Engine 5.7.4

GE Modifier 수치 실험판

Instant GE는 값을 적용하고 끝나지만, Duration/Infinite GE는 Active GE로 남아 CurrentValue 계산에 참여합니다. 적용 정책과 Magnitude를 바꿔 BaseValue와 CurrentValue 차이를 확인하세요.

Duration Policy
BaseValue 100
Active GE Modifier 없음 Instant는 Active GE로 남지 않습니다.
CurrentValue 100

Instant 피해는 BaseValue를 바꾸고, Duration/Infinite 버프는 CurrentValue 계산에 남습니다.

한 줄 정의

Gameplay Effect는 ASC에 적용되어 Attribute, Tag, Cue, Ability 부여 같은 게임플레이 변화를 만드는 데이터 자산입니다. 대부분의 Attribute 변경은 직접 값을 수정하기보다 GE를 통해 처리하는 편이 예측, 복제, 디버깅 흐름과 잘 맞습니다.

GE와 Attribute는 같이 이해해야 합니다

Attribute는 체력, 마나, 이동속도 같은 숫자 상태이고, GE는 그 숫자를 어떻게 바꿀지 정의합니다. 즉 “체력 -30”은 Attribute 자체의 책임이 아니라 GE의 Modifier 또는 ExecutionCalculation 책임입니다.

5.7 계열에서 볼 때의 변화

Epic 5.7 문서의 UGameplayEffect는 많은 부가 동작을 GameplayEffectComponent 계열로 분리해 설명합니다. 태그 조건, 추가 효과, 면역, 다른 효과 제거처럼 "GE에 붙는 옵션"은 예전 단일 속성 이름만 외우기보다 컴포넌트로 조립되는 구조로 이해하는 편이 안전합니다.

Gameplay Effect

게임 상태 변경을 데이터로 표현합니다. 적용 대상 ASC는 GE Spec을 받아 즉시 실행하거나 ActiveGameplayEffect로 보관합니다.

Attribute 변경

체력 감소, 스태미나 소모, 이동속도 증가처럼 숫자 값을 변경합니다.

Gameplay Tag 부여

기절, 무적, 쿨다운 중 같은 상태 태그를 GE의 지속 시간 동안 유지할 수 있습니다.

Gameplay Cue 연동

버프 시작, 피해 이펙트, 지속 파티클 같은 시각/청각 표현을 연결할 수 있습니다.

GE의 세 가지 지속 정책

GE는 적용 기간에 따라 다르게 동작합니다. 이 선택은 BaseValue와 CurrentValue 변화, 태그 유지, Cue 이벤트 처리까지 영향을 줍니다.

정책 동작 대표 사용 주의점
Instant 즉시 한 번 적용되고 Active GE로 남지 않습니다. 피해, 즉시 회복, 스태미나 비용 상태 태그를 유지하는 용도에는 맞지 않습니다.
Duration 정해진 시간 동안 유지되다가 만료됩니다. 5초 이동속도 증가, 3초 기절, 지속 피해 만료 시점과 중첩 정책을 명확히 정해야 합니다.
Infinite 명시적으로 제거할 때까지 계속 유지됩니다. 장비 보너스, 패시브 효과, 오라, 무한 재생 제거 경로를 설계하지 않으면 상태가 계속 남습니다.

게임플레이 이펙트 모디파이어

Modifier는 GE가 어떤 Attribute를 어떤 방식으로 바꿀지 정의하는 설정입니다. “무엇을 바꿀지”, “어떤 연산을 할지”, “값은 어디서 가져올지”를 함께 지정합니다.

1. Attribute 대상 선택 Health, Mana, MoveSpeed 같은 변경 대상 Attribute를 지정합니다.
2. Operation 연산 선택 AddBase, MultiplyAdditive, DivideAdditive, Override, MultiplyCompound, AddFinal 같은 적용 방식을 고릅니다.
3. Magnitude 값 계산 ScalableFloat, AttributeBased, CustomCalculationClass, SetByCaller 중 선택합니다.
4. Spec Spec 생성 레벨, Context, SetByCaller 값이 반영된 GE Spec이 만들어집니다.
5. Apply ASC에 적용 대상 ASC가 GE를 실행하거나 ActiveGameplayEffect로 보관합니다.
값 계산 방식 설명 잘 맞는 상황
ScalableFloat 고정 실수 또는 레벨/커브 테이블 기반 값을 사용합니다. 스킬 레벨별 피해량, 쿨다운 시간, 기본 비용
AttributeBased 소스 또는 타겟의 Attribute 값을 기반으로 계산합니다. 공격력 기반 피해, 최대 체력 비례 회복
CustomCalculationClass 전용 계산 클래스로 Magnitude를 산출합니다. 복잡하지만 Modifier 구조 안에 남기고 싶은 계산
SetByCaller GE Spec을 만드는 쪽에서 GameplayTag 키로 런타임 값을 주입합니다. 충전 시간 기반 피해, 타겟팅 결과에 따른 가변 값
ExecutionCalculation Modifier만으로 부족한 복잡한 적용 로직을 실행 계산으로 처리합니다. 방어력, 치명타, 보호막, 피해 분배가 섞인 최종 피해 계산
5.7 Modifier 연산 의미 설계 감각
AddBase 기본값에 먼저 더합니다. 가장 일반적인 피해, 회복, 비용의 출발점입니다.
MultiplyAdditive 곱셈 보정을 합산한 뒤 이전 결과에 곱합니다. 여러 버프의 퍼센트 보정이 더해지는 체감에 맞습니다.
DivideAdditive 나눗셈 보정을 합산한 뒤 이전 결과를 나눕니다. 감속, 저항, 페널티 계열을 별도 축으로 다룰 때 씁니다.
Override 계산 결과와 관계없이 값을 덮어씁니다. 고정 이동속도, 강제 체력 값처럼 우선순위가 분명할 때만 사용합니다.
MultiplyCompound 곱셈 보정이 서로 누적 곱으로 적용됩니다. 1.5와 1.5가 2.25처럼 커지는 복합 배율에 맞습니다.
AddFinal 최종 계산 결과에 마지막으로 더합니다. 모든 배율 뒤에 붙는 보정값이 필요할 때 씁니다.

C++ 작성 감각

아래 코드는 개념 감각을 위한 예시입니다. 실제 C++ enum 표기는 프로젝트가 사용하는 엔진 헤더의 이름을 확인해야 합니다. GE는 데이터 전용 Blueprint로 만드는 편이 일반적으로 편합니다. C++로도 만들 수 있지만, Attribute 지정과 Magnitude 설정 문법이 장황해지기 쉬워 공통 베이스나 팩토리 없이 대량 작성하기에는 부담이 큽니다. 

UProjectGE_AttackDamage::UProjectGE_AttackDamage()
{
    DurationPolicy = EGameplayEffectDurationType::Instant;

    FGameplayModifierInfo HealthModifier;
    HealthModifier.Attribute = UCharacterAttributeSet::GetHealthAttribute();
    HealthModifier.ModifierOp = EGameplayModOp::AddBase;

    HealthModifier.ModifierMagnitude =
        FGameplayEffectModifierMagnitude(FScalableFloat(-30.0f));

    Modifiers.Add(HealthModifier);
}

권장 제작 방식

디자이너가 수치와 태그를 조정해야 하는 GE는 Blueprint/Data Asset으로 만들고, C++는 AttributeSet, 공통 계산 클래스, ExecutionCalculation, MMC 같은 구조를 제공하는 쪽이 유지보수에 유리합니다.

적용 시나리오

상황 GE 설계 핵심 판단
총알 피해 Instant GE + Damage 또는 Health Modifier 단순 피해면 Modifier, 방어력/치명타가 있으면 ExecutionCalculation을 검토합니다.
질주 비용 Instant 또는 주기적 GE로 Stamina 감소 예측과 서버 권한, 입력 유지 중 비용 적용 주기를 함께 봅니다.
이동속도 버프 Duration GE + MoveSpeed Modifier 만료 시 자동 제거되고 CurrentValue가 원래 계산으로 돌아가야 합니다.
장비 패시브 Infinite GE + Attribute/Tag Modifier 장비 해제나 캐릭터 교체 시 제거 경로를 반드시 둡니다.

복습 질문

1. GE가 주로 바꾸는 대상은?

정답: Attribute와 Gameplay Tag입니다. 필요하면 Cue, Ability 부여, Stack 정책도 함께 다룹니다.

2. Duration GE와 Infinite GE의 차이는?

정답: Duration은 지정 시간이 지나면 만료되고, Infinite는 명시적으로 제거할 때까지 남습니다.

3. SetByCaller는 언제 쓰는가?

정답: GE 자산 안에 고정할 수 없는 런타임 값을 GE Spec을 만드는 쪽에서 주입할 때 씁니다.

4. Modifier만으로 부족할 때 쓰는 것은?

정답: GameplayEffectExecutionCalculation입니다. 복잡한 피해 계산, 방어력, 치명타, 보호막 분배 등에 적합합니다.
