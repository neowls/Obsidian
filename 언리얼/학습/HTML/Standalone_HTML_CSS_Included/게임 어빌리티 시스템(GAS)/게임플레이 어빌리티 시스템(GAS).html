Gameplay Ability System

게임플레이 어빌리티 시스템(GAS)

GAS는 액터가 보유하고 발동하는 능력, 수치 상태, 상태 효과, 태그 기반 조건, 네트워크 예측을 한 프레임워크 안에서 다루기 위한 언리얼 엔진 플러그인입니다. 처음에는 구성 요소가 많아 보이지만, ASC를 중심으로 각 요소가 어떤 책임을 갖는지 분리하면 전체 구조가 잡힙니다.

원본: 게임 어빌리티 시스템(GAS)/게임플레이 어빌리티 시스템(GAS).md 난이도: 전체 개요 핵심: ASC 중심 사고 검수 기준: Unreal Engine 5.7.4

GAS가 해결하려는 문제

게임 능력 시스템은 단순히 “스킬 버튼을 누르면 공격한다”에서 끝나지 않습니다. 비용, 쿨다운, 버프와 디버프, 타겟팅, 애니메이션, 사운드, UI, 네트워크 복제까지 이어집니다. GAS는 이 흐름을 개별 기능으로 흩어 놓지 않고, 데이터 기반으로 조합할 수 있는 구조를 제공합니다.

강점

  • 복잡한 액션, 패시브, 상태 효과를 범용적으로 표현할 수 있습니다.
  • GameplayTag와 GameplayEffect를 통해 데이터 중심 설계가 가능합니다.
  • 멀티플레이어 복제와 로컬 예측을 고려한 구조를 제공합니다.
  • Fortnite 같은 상용 프로젝트에서 검증된 시스템입니다.

비용

  • ASC, GA, GE, Attribute, Tag, Task 등 학습해야 할 용어가 많습니다.
  • 작은 프로젝트에서는 구조가 과하게 느껴질 수 있습니다.
  • C++ 초기 설정과 네트워크 권한 흐름을 이해해야 안정적으로 쓸 수 있습니다.

핵심 구성 요소 관계도

GAS는 Ability System Component를 중심에 둡니다. ASC가 액터의 능력, 속성, 효과, 태그를 관리하고 다른 ASC와 상호작용합니다.

ASC: Ability System Component

액터가 GAS 세계와 연결되는 중심 컴포넌트입니다. 어빌리티 부여, 활성화, 이펙트 적용, 태그 보유, 속성 접근의 관문 역할을 합니다.

GA: Gameplay Ability

점프, 대시, 공격, 패시브처럼 실행 가능한 능력의 로직입니다. 필요하면 Ability Task로 비동기 흐름을 구성합니다.

GE: Gameplay Effect

체력 감소, 이동속도 증가, 쿨다운, 비용처럼 Attribute나 Tag에 변화를 주는 데이터 중심 효과입니다.

Attribute Set

체력, 마나, 스태미나, 공격력 같은 숫자 상태를 모아 둡니다. 실제 값 변경은 주로 Gameplay Effect를 통해 일어납니다.

Gameplay Tag

State.Stun, Ability.Fire 같은 계층형 이름입니다. 조건, 차단, 분류, 이벤트 라우팅에 쓰입니다.

Gameplay Cue

파티클, 사운드, 카메라 효과처럼 게임플레이 결과를 시각적, 청각적으로 표현하는 경로입니다.

Ability Task

몽타주 재생 대기, 타겟 데이터 대기, 입력 대기 같은 비동기 작업을 어빌리티 안에서 다루는 빌딩 블록입니다.

시각화 요약: 입력에서 결과까지

Input / Event 입력, AI 명령, 충돌, Gameplay Event가 ASC로 들어옵니다.
ASC 권한, 태그, 쿨다운, 비용 조건을 확인하고 AbilitySpec을 찾습니다.
GA 실행 로직을 시작하고 필요하면 Ability Task로 비동기 단계를 나눕니다.
GE 비용, 피해, 버프, 쿨다운 같은 상태 변화를 데이터로 적용합니다.
Attribute / Tag 수치와 상태 표지가 바뀌고, 조건 판단과 UI 갱신의 기준이 됩니다.
Gameplay Cue 파티클, 사운드, 카메라 흔들림처럼 결과를 플레이어에게 보여줍니다.
핵심 판단 지점: ASC 지속 상태: GE, Attribute, Tag 순간 표현: Gameplay Cue

5.7 계열에서 GE는 컴포넌트 조립으로도 읽어야 합니다

기본 개념은 여전히 GA가 실행 흐름, GE가 상태 변화, Tag가 조건과 분류를 담당한다는 구조입니다. 다만 5.7 공식 API에서는 UGameplayEffect의 여러 부가 기능이 GameplayEffectComponent 계열로 정리되어 있으므로, GE를 볼 때 Modifier와 Duration뿐 아니라 어떤 컴포넌트가 조건, 면역, 추가 효과, 태그 처리를 담당하는지도 함께 확인해야 합니다.

구성 요소별 책임

요소 주요 책임 처음 배울 때 보는 질문
ASC GAS 객체들을 소유하고 상호작용을 중재합니다. 이 액터는 어떤 ASC를 통해 능력과 효과를 주고받는가?
GA 능력의 실행 흐름을 정의합니다. 이 행동은 언제 시작되고, 비용과 쿨다운은 언제 확정되는가?
GE Attribute와 Tag 변화를 데이터로 표현합니다. 이 효과는 즉시 적용인가, 지속인가, 무한인가?
Attribute 게임플레이 수치를 저장하고 복제합니다. 이 값은 기본값과 현재값 중 어느 쪽이 바뀌어야 하는가?
Tag 상태와 조건을 계층형 이름으로 표현합니다. bool이나 enum 대신 태그로 표현하면 조합이 쉬워지는가?
Task 어빌리티 실행 중 비동기 단계를 담당합니다. 몽타주, 타겟팅, 입력 대기처럼 완료 시점이 나중인 일이 있는가?

학습 순서

구성 요소를 모두 한 번에 외우기보다, 아래 순서로 책임을 쌓아 가면 이해가 빠릅니다.

  1. ASC: 어떤 액터가 GAS에 참여하는지 결정합니다.
  2. Attribute Set: 체력, 마나 같은 숫자 상태를 정의합니다.
  3. Gameplay Effect: 수치와 태그를 바꾸는 규칙을 만듭니다.
  4. Gameplay Ability: 입력과 실행 흐름을 연결합니다.
  5. Ability Task: 애니메이션, 타겟팅, 입력 대기 같은 비동기 흐름을 붙입니다.
  6. Gameplay Cue: 결과를 이펙트, 사운드, 카메라 연출로 표현합니다.

초기 판단 기준

프로젝트에 쿨다운, 비용, 버프/디버프, 태그 기반 차단, 네트워크 예측이 필요하다면 GAS가 유리합니다. 단순 싱글플레이 액션 몇 개만 필요하다면 일반 컴포넌트와 데이터 에셋이 더 가벼울 수 있습니다.

복습 질문

1. GAS의 중심 컴포넌트는?

정답: Ability System Component. 액터가 어빌리티, 이펙트, 태그, 속성을 주고받는 관문입니다.

2. Gameplay Ability와 Gameplay Effect의 차이는?

정답: GA는 실행 흐름이고, GE는 수치와 태그 변화를 표현하는 효과 데이터입니다.

3. Gameplay Tag가 중요한 이유는?

정답: 상태와 조건을 계층형 이름으로 표현해 차단, 허용, 분류, 이벤트 조건을 조합하기 쉽습니다.

4. GAS가 작은 프로젝트에서 부담이 될 수 있는 이유는?

정답: 구성 요소와 네트워크 권한 흐름이 많아 초기 학습 및 구조 설계 비용이 큽니다.

관련 노트

  • 게임플레이 어빌리티 스펙(Spec): ASC가 어빌리티를 보유하는 단위
  • 게임플레이 어빌리티 타겟 액터(TA): 어빌리티 타겟 판정과 TargetData 생성
  • 게임플레이 어빌리티(GA): 실행 가능한 액션 명령과 생명주기
  • 게임플레이 어빌리티(GA)의 인스턴싱 옵션: GA 인스턴스 생성과 재사용 정책
  • 어빌리티 시스템 컴포넌트(ASC): GAS의 중심 컴포넌트
  • 게임플레이 이펙트(GE): Attribute와 Tag 변화
  • 게임플레이 큐(GC): 파티클, 사운드, 카메라 효과 표현
  • 게임플레이 태그(Tag): 상태, 조건, 분류를 위한 계층형 표식
  • 어트리뷰트 세트(Attribute Set): 숫자 상태 묶음
