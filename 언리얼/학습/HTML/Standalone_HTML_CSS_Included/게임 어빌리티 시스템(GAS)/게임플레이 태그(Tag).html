Gameplay Ability System

게임플레이 태그(Tag)

Gameplay Tag는 State.Debuff.Stun처럼 계층 구조를 가진 경량 표식입니다. boolean이나 enum보다 조합과 검색이 유연해서 상태, 행동, 이벤트, Cue, Ability 조건을 표현하는 공통 언어로 쓰입니다.

원본: 게임 어빌리티 시스템(GAS)/게임플레이 태그(Tag).md 난이도: GAS 공통 기초 핵심: FGameplayTag, FGameplayTagContainer, Exact Match 검수 기준: Unreal Engine 5.7.4

한 줄 정의

Gameplay Tag는 프로젝트 전역에서 검증되고 계층 검색이 가능한 이름표입니다. 내부적으로는 FName 기반의 가벼운 데이터지만, 일반 Actor Tag와 달리 GameplayTags 시스템에 등록되어 관리됩니다.

저장 위치

에디터의 Project Settings에서 태그를 생성하면 보통 DefaultGameplayTags.ini에 저장됩니다. 서버와 클라이언트가 같은 태그 사전을 공유해야 복제와 검색이 안정적으로 동작합니다.

Gameplay Tags

행동, 상태, 이벤트, Cue, Ability 조건을 계층형 이름으로 표현합니다. 점으로 구분된 부모/자식 구조를 이용해 범주 단위 검색이 가능합니다.

Actor.Action.Rotate

액터가 수행하는 행동이나 가능한 액션 범주를 표현합니다.

Actor.State.IsRotating

액터의 현재 상태를 표현합니다. 상태 기반 차단이나 UI 표시 조건에 쓰기 좋습니다.

GameplayCue.Status.Stun

Gameplay Cue 라우팅에 쓰는 태그입니다. Cue 태그는 반드시 GameplayCue로 시작해야 합니다.

GameplayTagContainer 검색

여러 태그는 FGameplayTagContainer에 담습니다. 일반 검색은 부모 태그까지 고려하고, Exact 검색은 컨테이너에 정확히 들어 있는 태그만 인정합니다.

컨테이너 보유 태그 검사 결과 이유
A.1 HasTag(A) true 일반 검색은 부모 태그 A와 매칭됩니다.
A.1 HasTagExact(A) false 컨테이너에 정확히 A가 들어 있지 않습니다.
A.1 HasAny(A, B) true A.1이 A의 자식이므로 하나 이상 매칭됩니다.
A.1 HasAnyExact(A, B) false 정확히 A 또는 B를 가진 것이 아닙니다.
A.1, B.1 HasAll(A, B) true 부모 태그 기준으로 둘 다 매칭됩니다.
A.1, B.1 HasAllExact(A, B) false 정확히 A와 B가 들어 있지는 않습니다.

빈 컨테이너 주의

빈 입력 컨테이너를 검사할 때 대부분의 Any 계열은 false지만, All 계열은 “빠진 태그가 없다”는 의미로 true가 될 수 있습니다. 조건식에서 빈 컨테이너가 들어올 가능성을 명확히 처리해야 합니다.

ASC의 태그는 Count로 관리됩니다

같은 태그가 여러 GE나 여러 경로에서 들어오면 ASC는 단순한 Set처럼 한 번만 저장하고 끝내지 않고 Tag Count를 관리합니다. 그래서 한 효과가 제거되어도 다른 효과가 같은 태그를 아직 부여 중이면 태그는 남습니다. 태그 조건이 예상과 다르면 Exact 여부와 함께 Tag Count, Loose Tag, GE가 부여한 태그의 수명을 같이 확인해야 합니다.

Gameplay Ability에서의 태그

GA는 태그를 통해 “어떤 어빌리티인가”, “무엇을 취소할 것인가”, “어떤 상태에서 실행 가능한가”를 정의합니다. 실행 조건이 데이터로 드러나므로 디자이너와 프로그래머가 같은 기준으로 확인하기 쉽습니다.

태그 설정 대상 의미
AbilityTags 어빌리티 자체 이 어빌리티가 어떤 종류인지 분류합니다. 다른 취소/차단 규칙의 검색 대상이 됩니다.
CancelAbilitiesWithTag 다른 활성 어빌리티 여기에 등록한 태그를 AbilityTags로 가진 어빌리티를 취소합니다.
BlockAbilitiesWithTag 다른 어빌리티 활성화 특정 태그를 가진 어빌리티가 새로 실행되지 못하게 막습니다.
ActivationOwnedTags 소유 ASC 어빌리티가 실행 중일 때 ASC에 부여되는 태그입니다. 예: State.Casting
ActivationRequiredTags 소유 ASC 소유자가 이 태그를 가지고 있어야 어빌리티가 실행됩니다.
ActivationBlockedTags 소유 ASC 소유자가 이 태그를 가지고 있으면 어빌리티 실행이 막힙니다.
SourceRequiredTags / SourceBlockedTags 시전자 효과를 발생시키는 쪽의 태그 조건을 검사합니다.
TargetRequiredTags / TargetBlockedTags 시전 대상 대상에게 특정 태그가 있거나 없을 때만 어빌리티가 유효하게 만듭니다.

태그 설계 감각

태그는 코드보다 콘텐츠와 운영에서 더 많이 만지는 데이터가 될 수 있습니다. 이름 체계가 흔들리면 검색과 조건식이 빠르게 복잡해지므로, 루트 범주를 먼저 정해 두는 것이 좋습니다.

1. Root 루트 범주 State, Ability, Effect, GameplayCue처럼 큰 범주를 정합니다.
2. Meaning 의미 분리 상태 태그와 행동 태그, 이벤트 태그를 섞지 않습니다.
3. Query 검색 기준 부모 검색을 쓸지 Exact 검색을 쓸지 사용처별로 정합니다.
4. Source 부여 주체 GE가 주는 태그인지, ASC가 직접 주는 Loose Tag인지 구분합니다.
5. Debug 디버깅 태그가 “있어 보이는데 조건이 실패”하면 Exact 여부와 Tag Count를 확인합니다. 
// C++에서 등록된 GameplayTag 참조를 가져오는 기본 형태
FGameplayTag StunTag =
    FGameplayTag::RequestGameplayTag(FName("State.Debuff.Stun"));

// ASC에서 태그 변경을 감지하는 형태
AbilitySystemComponent
    ->RegisterGameplayTagEvent(StunTag, EGameplayTagEventType::NewOrRemoved)
    .AddUObject(this, &AMyCharacter::OnStunTagChanged);

Loose Tag와 GE Tag

GameplayEffect가 부여하는 태그

Duration/Infinite GE가 유지되는 동안 태그를 부여하고, GE가 제거되면 태그도 같이 사라지게 만들 수 있습니다. 상태 지속 시간과 태그 수명이 맞아야 할 때 적합합니다.

Loose Gameplay Tag

ASC에 직접 추가하는 태그입니다. GE 수명과 묶이지 않으므로 직접 추가/제거를 관리해야 합니다. 복제와 예측 요구사항을 확인하고 신중하게 사용해야 합니다.

복습 질문

1. Gameplay Tag와 일반 Actor Tag의 차이는?

정답: Gameplay Tag는 GameplayTags 시스템에 등록되고 계층 검색과 컨테이너 쿼리를 지원하는 전역 표식입니다.

2. A.1이 있을 때 HasTag(A)와 HasTagExact(A)의 결과는?

정답: HasTag(A)는 true, HasTagExact(A)는 false입니다.

3. 어빌리티 실행 중 소유자에게 붙는 태그 설정은?

정답: ActivationOwnedTags입니다.

4. Gameplay Cue 태그의 필수 루트는?

정답: GameplayCue입니다.
