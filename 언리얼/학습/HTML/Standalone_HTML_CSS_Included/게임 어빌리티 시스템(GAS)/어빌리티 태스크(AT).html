Gameplay Ability System

어빌리티 태스크(AT)

Ability Task는 Gameplay Ability 안에서 몽타주 재생, 타겟 데이터 대기, 입력 대기, 태그 변화 대기처럼 시간이 걸리는 작업을 비동기로 처리하는 빌딩 블록입니다. GA는 한 번 활성화된 뒤 Task의 델리게이트 결과를 기다리고, 결과에 따라 후속 로직이나 EndAbility로 이어집니다.

원본: 게임 어빌리티 시스템(GAS)/어빌리티 태스크(AT).md 난이도: GA 비동기 흐름 핵심: UAbilityTask, Delegate, ReadyForActivation, EndAbility 검수 기준: Unreal Engine 5.7.4

한 줄 정의

Ability Task는 GA의 실행 중 비동기 작업을 담당하고, 완료/취소/중단 결과를 델리게이트로 GA에 돌려주는 객체입니다. 공식 5.7 API에서 UAbilityTask는 UGameplayTask를 상속하며, 생성한 GA와 ASC를 참조합니다.

GA는 Tick으로 오래 버티는 구조가 아닙니다

원본 노트처럼 GA의 활성화 함수 자체는 한 번 호출되고 끝납니다. 하지만 EndAbility가 호출되기 전까지 GA는 활성 상태로 남을 수 있고, 그 사이의 대기와 이벤트 처리를 Ability Task가 맡습니다.

Task 생성

GA가 Task 노드나 static factory 함수를 통해 Task 인스턴스를 만듭니다.

Delegate 구독

완료, 취소, 중단, 입력, 태그 변경 같은 결과 델리게이트에 GA가 콜백을 연결합니다.

ReadyForActivation

구독이 끝난 뒤 Task를 실제로 시작합니다. Blueprint 노드는 내부적으로 이 흐름을 감춰 줍니다.

EndTask / EndAbility

Task는 자신을 끝내고, GA는 필요한 모든 작업이 끝났을 때 Ability를 종료합니다.

기본 실행 흐름

Ability Task는 “작업 시작 후 결과 통보” 구조입니다. GA는 Task를 만든 뒤 바로 끝나는 것이 아니라, Task 결과를 받아 다음 결정을 내립니다.

1. ActivateAbility GA 시작 비용, 쿨다운, 타겟팅, 애니메이션 시작 시점을 정합니다.
2. Create Task AT 생성 PlayMontageAndWait, WaitTargetData 같은 Task를 만듭니다.
3. Bind Delegate 연결 완료/취소/중단/입력 이벤트에 콜백을 연결합니다.
4. Ready Task 활성화 구독이 끝난 뒤 ReadyForActivation으로 실제 작업을 시작합니다.
5. Result 결과 처리 Task 결과에 따라 GE 적용, 다음 Task 실행, CancelAbility, EndAbility를 결정합니다.

Task 종료와 Ability 종료는 다릅니다

하나의 Task가 끝났다고 항상 Ability가 끝나는 것은 아닙니다. 콤보, 조준 후 발사, 몽타주 후 GE 적용처럼 여러 Task가 순서대로 이어질 수 있으므로, GA의 모든 성공/실패/취소 경로가 최종적으로 EndAbility로 이어지는지 확인해야 합니다.

대표 Task 종류

5.7의 UAbilityTask 파생 클래스는 몽타주, 입력, Attribute 변화, Gameplay Event, TargetData, Root Motion 등 다양한 대기 작업을 제공합니다.

Task 역할 사용 예
PlayMontageAndWait 애니메이션 몽타주를 재생하고 완료/블렌드아웃/중단/취소를 기다립니다. 공격 모션이 끝난 뒤 데미지 적용 또는 콤보 창 열기
WaitInputPress / WaitInputRelease 활성 GA 안에서 입력 눌림/뗌 이벤트를 기다립니다. 차징 스킬, 홀드형 조준, 버튼을 떼면 발사
WaitTargetData Target Actor가 만든 TargetData를 기다립니다. 장판 위치 선택, 락온 타겟 확정, 범위 판정
WaitGameplayEvent Gameplay Event Tag와 Payload를 기다립니다. 애니메이션 노티파이, 피격 이벤트, 외부 시스템 트리거
WaitAttributeChange Attribute 값 변화를 기다립니다. 체력이 일정 이하일 때 패시브 발동, 스태미나 회복 대기

설계 감각

Task로 빼기 좋은 작업

  • 시간이 걸리고 완료 이벤트가 필요한 작업
  • 입력, 애니메이션, 타겟팅, 네트워크 동기화처럼 비동기인 작업
  • 여러 GA에서 재사용할 수 있는 대기 패턴

Task로 만들기 애매한 작업

  • 즉시 계산하고 끝나는 단순 수치 계산
  • GA와 무관한 일반 컴포넌트 Tick 로직
  • 서버 권한 판정을 우회하려는 로컬 전용 게임플레이 결정
// 개념 예시: C++ GA에서 Task 결과를 기다리는 흐름
UAbilityTask_PlayMontageAndWait* Task =
    UAbilityTask_PlayMontageAndWait::CreatePlayMontageAndWaitProxy(
        this, NAME_None, AttackMontage);

Task->OnCompleted.AddDynamic(this, &UAttackAbility::OnMontageCompleted);
Task->OnInterrupted.AddDynamic(this, &UAttackAbility::OnMontageInterrupted);
Task->OnCancelled.AddDynamic(this, &UAttackAbility::OnMontageCancelled);

Task->ReadyForActivation();

복습 질문

1. Ability Task가 필요한 이유는?

정답: GA 안에서 애니메이션, 입력, 타겟팅처럼 시간이 걸리는 비동기 작업을 기다리기 위해서입니다.

2. GA가 Task를 만든 뒤 바로 해야 할 일은?

정답: 완료/취소/중단 같은 델리게이트를 구독한 뒤 Task를 활성화해야 합니다.

3. Task가 끝나면 Ability도 자동으로 끝나는가?

정답: 아닙니다. GA가 콜백에서 후속 처리와 EndAbility 호출 여부를 결정해야 합니다.

4. 몽타주 재생과 완료 대기에 적합한 Task는?

정답: PlayMontageAndWait 계열 Ability Task입니다.

관련 노트

  • 게임플레이 어빌리티(GA): Task를 생성하고 결과를 받아 종료하는 주체
  • 어빌리티 태스크(AT)의 제작 규칙: 커스텀 Task 구현 규칙
  • 어빌리티 시스템 컴포넌트의 입력 처리: WaitInputPress/Release와 InputID 흐름
  • 게임플레이 어빌리티 타겟 액터(TA): WaitTargetData와 Target Actor 연결
  • 게임플레이 이펙트(GE): Task 완료 후 적용하는 비용, 쿨다운, 피해 효과
