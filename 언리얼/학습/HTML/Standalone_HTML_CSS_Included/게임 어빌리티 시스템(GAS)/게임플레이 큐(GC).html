Gameplay Ability System

게임플레이 큐(GC)

Gameplay Cue는 파티클, 사운드, 카메라 흔들림 같은 표현 효과를 게임 로직과 분리해서 실행하는 GAS의 연출 경로입니다. 데미지 계산이나 상태 변경은 GE가 맡고, 그 결과를 보여주는 일은 GC가 맡는 식으로 책임을 나누면 구조가 깔끔해집니다.

원본: 게임 어빌리티 시스템(GAS)/게임플레이 큐(GC).md 난이도: 표현 효과 기초 핵심: GameplayCueNotify, GameplayCueManager, GameplayCue Tag 검수 기준: Unreal Engine 5.7.4

한 줄 정의

Gameplay Cue는 게임플레이 결과를 시각적, 청각적으로 표현하는 비게임플레이 로직입니다. 서버 판정, Attribute 변경, 데미지 계산 같은 핵심 로직을 담당하지 않고, 클라이언트가 볼 효과를 재생하는 데 집중합니다.

태그 규칙

Gameplay Cue를 발동하는 태그는 반드시 GameplayCue로 시작해야 합니다. 예: GameplayCue.Weapon.Fire.Impact, GameplayCue.Status.Stun

GameplayCueManager

GameplayCue Tag와 이벤트를 받아 알맞은 GameplayCueNotify로 라우팅합니다. GC 재생은 다른 GAS 로직과 분리된 매니저가 담당합니다.

GameplayEffect

GE가 성공적으로 적용될 때 연결된 GameplayCue를 자동으로 Execute, Add, Remove할 수 있습니다.

GameplayCue Tag

어떤 Cue를 실행할지 식별하는 태그입니다. GameplayCue로 시작하는 계층형 태그를 씁니다.

GameplayCueParameters

위치, Instigator, EffectContext, Magnitude, SourceObject 같은 연출에 필요한 추가 정보를 전달합니다.

두 종류의 GameplayCueNotify

GC는 보통 일회성 효과와 지속 효과로 나눠 생각하면 됩니다. 한 번 터지고 끝나는 효과는 Static, 일정 시간 유지되며 정리가 필요한 효과는 Actor가 잘 맞습니다.

종류 주요 이벤트 잘 맞는 효과 주의점
GameplayCueNotify_Static Execute 피격 임팩트, 총구 화염, 한 번 재생되는 사운드 인스턴스가 없으므로 상태를 오래 보관하는 용도에는 맞지 않습니다.
GameplayCueNotify_Actor Add, WhileActive, Remove
BP: On Burst, On Become Relevant, On Cease Relevant		 스턴 이펙트, 질주 루프 파티클, 지속 오라, 루프 사운드 Remove에서 정리해야 하며, Auto Destroy 설정을 확인해야 합니다.

이벤트 흐름

Instant GE는 보통 Execute를 호출하고, Duration/Infinite GE는 Add와 Remove를 통해 지속 연출을 관리합니다.

1. Trigger 태그로 호출 ASC, GA, GE가 GameplayCue.* 태그와 이벤트를 보냅니다.
2. Manager 매니저 라우팅 GameplayCueManager가 태그에 맞는 Notify를 찾습니다.
3. Execute 일회성 재생 Static Notify가 즉발 파티클, 사운드, 카메라 효과를 재생합니다.
4. Add 지속 효과 시작 Actor Notify가 스폰되고 루프 효과를 시작합니다.
5. Remove 정리 GE 만료나 수동 제거 시 루프 효과와 인스턴스를 정리합니다.
이벤트 의미 사용 예
Executed 즉시 실행되는 이벤트입니다. 총알 충돌, 타격 스파크, 폭발음
OnActive 지속 Cue가 처음 활성화될 때 호출됩니다. 5.7 Blueprint Notify에서는 On Burst 명칭도 함께 확인해야 합니다. 버프 시작 효과, 기절 시작 사운드
WhileActive Cue가 활성 상태로 보일 때 호출됩니다. 5.7 Blueprint Notify에서는 On Become Relevant 흐름과 대응됩니다. 중도 참여자도 봐야 하는 루프 파티클 시작
Removed 지속 Cue가 제거될 때 호출됩니다. 5.7 Blueprint Notify에서는 On Cease Relevant 명칭과 대응됩니다. 루프 파티클 중단, 사운드 페이드아웃, 컴포넌트 정리

이벤트 이름을 두 층으로 읽기

GAS의 개념 이벤트는 여전히 Executed, OnActive, WhileActive, Removed로 이해하면 됩니다. 다만 5.7의 GameplayCueNotify_Actor Blueprint API에서는 활성/중지 이벤트가 On Burst, On Become Relevant, On Cease Relevant처럼 보일 수 있습니다.

GE와 연결되는 방식

GameplayEffect 안에 GameplayCue 태그를 지정하면 GE 적용 방식에 따라 적절한 이벤트가 자동으로 호출됩니다. 즉, 버프 GE는 버프 연출을 켜고 만료 시 끄는 구조를 자연스럽게 만들 수 있습니다.

GE 타입 GC 이벤트 대표 예시
Instant Execute 피격 이펙트, 즉발 폭발, 회복 팝업
Duration Add, WhileActive, Remove 5초 기절 파티클, 일정 시간 보호막 연출
Infinite Add, WhileActive, Remove 장비 오라, 패시브 효과, 무한 루프 사운드
Periodic Execute 반복 가능 독 데미지 틱, 화상 틱 임팩트

네트워크와 안전성

GC는 표현 효과입니다

GC는 일반적으로 비신뢰성 멀티캐스트 경로를 탈 수 있으므로, 데미지 판정이나 상태 변경 같은 게임플레이 결정을 GC에 넣지 않는 것이 맞습니다.

데디케이티드 서버

데디케이티드 서버는 화면과 사운드가 없으므로 GC의 시각/청각 재생 자체가 필요하지 않습니다. 서버는 판정과 상태 변경을 처리하고, 클라이언트가 Cue를 재생하게 두는 구조가 자연스럽습니다. 

// 어빌리티 또는 ASC에서 수동으로 Cue를 호출하는 감각
ExecuteGameplayCue(FGameplayTag::RequestGameplayTag(TEXT("GameplayCue.Weapon.Impact")));

// 지속 Cue는 Add와 Remove가 짝을 이뤄야 한다.
AddGameplayCue(FGameplayTag::RequestGameplayTag(TEXT("GameplayCue.Status.Stun")));
RemoveGameplayCue(FGameplayTag::RequestGameplayTag(TEXT("GameplayCue.Status.Stun")));

복습 질문

1. Gameplay Cue의 주된 책임은?

정답: 파티클, 사운드, 카메라 흔들림 같은 표현 효과를 재생하는 것입니다.

2. GC 태그는 무엇으로 시작해야 하는가?

정답: 반드시 GameplayCue로 시작해야 합니다.

3. Static Cue와 Actor Cue의 차이는?

정답: Static은 일회성 Execute 효과에 맞고, Actor는 인스턴스가 생성되어 지속 효과와 정리에 맞습니다.

4. GC에 넣으면 안 좋은 로직은?

정답: 데미지 판정, Attribute 변경, 상태 결정처럼 게임플레이 결과를 바꾸는 로직입니다.

관련 노트

  • 게임플레이 이펙트의 생성 과정: EffectContext와 CueParameters로 전달되는 정보
