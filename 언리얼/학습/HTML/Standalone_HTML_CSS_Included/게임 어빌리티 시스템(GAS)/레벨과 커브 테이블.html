Gameplay Ability System

레벨과 커브 테이블

Gameplay Effect의 Level은 단순한 표시 값이 아니라, ScalableFloat가 커브 테이블에서 어떤 수치를 읽을지 결정하는 입력값입니다. 같은 GE라도 Level과 Row를 바꾸면 스킬 성장, 콤보 배율, 캐릭터 초기 스탯을 데이터 중심으로 조정할 수 있습니다.

원본: 게임 어빌리티 시스템(GAS)/레벨과 커브 테이블.md 난이도: GE 수치 설계 핵심: GE Level, FScalableFloat, Curve Table 검수 기준: Unreal Engine 5.7.4

한 줄 정의

레벨과 커브 테이블은 GE에 전달된 Level로 커브 테이블의 값을 평가해 Modifier Magnitude를 결정하는 데이터 기반 수치 설계 방식입니다. 수치를 코드에 박아두지 않고 Curve Table에 분리하면 밸런싱, 레벨별 성장, 직업별 보정값을 에디터에서 조정하기 쉬워집니다.

ScalableFloat의 감각

FScalableFloat는 기본 값과 커브 참조를 함께 가질 수 있습니다. 커브가 연결된 경우 GE Spec의 Level을 X값처럼 사용해 Curve Table Row를 평가하고, 그 결과를 Modifier Magnitude에 반영합니다.

GE Level

MakeOutgoingSpec이나 Blueprint Apply 노드에서 전달되는 레벨입니다. 스킬 레벨, 캐릭터 레벨, 콤보 단계가 될 수 있습니다.

ScalableFloat

고정값으로도 쓰고, Curve Table Row와 연결해 레벨별 값을 읽는 Magnitude 타입으로도 씁니다.

Curve Table

행은 수치 이름, 열 또는 X축은 레벨 구간, 셀 또는 커브 값은 해당 레벨의 결과값이라고 보면 됩니다.

밸런싱 포인트

데미지, 비용, 쿨다운, 지속시간, 초기 스탯 같은 반복 조정 수치를 데이터로 분리합니다.

레벨이 수치가 되는 흐름

중요한 연결점은 Spec 생성 시 전달되는 Level입니다. 이 값이 ScalableFloat 계산으로 들어가고, 커브 테이블이 있으면 해당 Row를 Level 위치에서 평가합니다.

1. Source 레벨 결정 GA 레벨, 캐릭터 레벨, 콤보 단계 같은 입력 레벨을 정합니다.
2. Spec GE Spec 생성 MakeOutgoingSpec에 Level을 넘깁니다.
3. Modifier ScalableFloat 평가 Modifier Magnitude가 Spec Level을 사용해 값을 계산합니다.
4. Table Curve Row 조회 Curve Table Row가 있으면 Level 위치의 곡선 값을 읽습니다.
5. Apply Attribute 반영 계산된 Magnitude가 AddBase, MultiplyAdditive, Override 같은 GE Modifier 연산으로 적용됩니다. 
const float AbilityLevel = GetAbilityLevel();

FGameplayEffectContextHandle Context = ASC->MakeEffectContext();
FGameplayEffectSpecHandle Spec =
    ASC->MakeOutgoingSpec(DamageEffectClass, AbilityLevel, Context);

// DamageEffectClass 안의 ScalableFloat Modifier가 AbilityLevel로 커브 값을 평가합니다.

커브 테이블 예시

아래처럼 RowName을 기능별로 나누면 하나의 Curve Table에서 데미지, 비용, 쿨다운, 초기 스탯을 함께 관리할 수 있습니다. ScalableFloat는 필요한 Row를 참조하고, GE Spec Level이 어느 열 또는 X값을 읽을지 결정합니다.

RowName Level 1 Level 2 Level 3 사용 예
Fireball_Damage 80 115 155 스킬 레벨별 피해량
Fireball_ManaCost 20 28 38 레벨이 오를수록 증가하는 비용
Combo_DamageRate 1.0 1.15 1.35 콤보 단계별 최종 데미지 배율
Initial_MaxHealth 300 345 395 캐릭터 레벨별 초기 스탯

적용 시나리오

목표 레벨 입력 Curve Row 설계 포인트
콤보 추가 피해 콤보 단계 Combo_DamageRate ExecutionCalculation이나 SetByCaller와 조합해 최종 피해 배율로 쓰기 좋습니다.
캐릭터 초기 스탯 캐릭터 레벨 Initial_MaxHealth 스폰/초기화 시 Infinite 또는 Instant GE로 기본 스탯을 세팅합니다.
스킬 레벨별 비용 GA 레벨 Fireball_ManaCost Cost GE의 Modifier Magnitude를 ScalableFloat로 두면 레벨별 비용을 코드 수정 없이 바꿀 수 있습니다.
쿨다운 성장 GA 레벨 Fireball_Cooldown Duration Magnitude에 커브를 연결하면 레벨별 쿨다운 시간을 다르게 줄 수 있습니다.

설계 체크리스트

  • Level의 의미를 먼저 정합니다. 스킬 레벨인지, 캐릭터 레벨인지, 콤보 단계인지 섞이지 않게 이름으로 드러내야 합니다.
  • RowName은 기능 단위로 명확히 둡니다. Damage보다 Fireball_Damage, Initial_MaxHealth처럼 검색 가능한 이름이 좋습니다.
  • Curve Table의 보간 방식을 의식합니다. 정수 레벨만 쓸지, 1.5 같은 중간 레벨도 허용할지에 따라 Constant/Linear/Cubic 선택이 달라집니다.
  • GE Level과 SetByCaller를 구분합니다. 성장 곡선은 Level/Curve, 실행 순간 값은 SetByCaller로 분리하면 추적이 쉽습니다.

Level은 항상 정수처럼만 쓰지 않아도 됩니다

GE Spec 생성 함수의 Level은 float로 전달되는 흐름이 많습니다. 정수 레벨만 허용할지, 1.5 같은 중간 값을 커브 보간으로 허용할지는 밸런스 정책입니다. 그래서 Curve Table의 보간 방식과 Level 입력의 의미를 문서화해 두는 것이 좋습니다.

복습 질문

1. GE에 전달한 Level은 어디에 주로 사용되는가?

정답: ScalableFloat Modifier나 Duration Magnitude가 커브 테이블 값을 평가할 때 사용됩니다.

2. 콤보 단계별 배율을 데이터화하려면?

정답: 콤보 단계를 Level처럼 넘기고, Combo_DamageRate 같은 Curve Row를 ScalableFloat에서 참조하게 만들 수 있습니다.

3. 커브 테이블을 쓰는 가장 큰 장점은?

정답: 수치를 코드와 분리해 에디터에서 레벨별 밸런스를 빠르게 조정할 수 있습니다.

4. 성장 곡선과 런타임 변수는 어떻게 나누면 좋은가?

정답: 레벨 기반 성장 수치는 Curve Table, 타겟 수나 충전 시간 같은 실행 순간 값은 SetByCaller로 나누는 편이 명확합니다.
