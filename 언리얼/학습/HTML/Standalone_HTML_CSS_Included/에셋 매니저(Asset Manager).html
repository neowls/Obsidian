Asset Management

에셋 매니저(Asset Manager)

Asset Manager는 프로젝트의 Primary Asset을 발견하고, 비동기 로딩과 언로딩, 번들, 쿠킹/청킹 규칙을 관리하는 싱글톤 시스템입니다. Asset Registry가 "어떤 에셋이 있는가"를 알려준다면, Asset Manager는 "어떤 게임 단위로 언제 로드할 것인가"를 결정합니다.

원본: 에셋 매니저(Asset Manager).md 난이도: 중급 에셋 로딩 핵심: Primary Asset, Secondary Asset, Asset Bundle, Streamable Handle 검수 기준: Unreal Engine 5.7.4

한 줄 정의

Asset Manager는 직접 로드 단위로 삼을 Primary Asset을 기준으로 에셋 검색, 비동기 로딩, 번들 로딩, 쿠킹 규칙을 묶는 프로젝트 단위 관리자입니다. 맵이나 게임 모드에 종속되지 않는 싱글톤이며, 프로젝트에서 상속해 확장할 수 있습니다.

Asset Registry

로드되지 않은 에셋의 메타데이터를 검색하고 목록화합니다.

Asset Manager

Primary Asset ID를 기준으로 발견, 로딩 상태, 번들, 쿠킹/청킹 규칙을 관리합니다.

Streamable Manager

실제 비동기 로드와 메모리 유지 핸들을 처리합니다.

Primary와 Secondary

구분 의미 예시
Primary Asset Asset Manager가 FPrimaryAssetId로 직접 발견하고 로드/언로드할 수 있는 에셋입니다. 맵(UWorld), UPrimaryDataAsset 기반 아이템 데이터, 프로젝트에서 지정한 데이터 에셋
Secondary Asset Primary Asset이 참조하거나 사용할 때 함께 로드되는 일반 에셋입니다. 메시, 텍스처, 사운드, 애니메이션, 이펙트

5.7 기준 핵심

공식 문서 기준으로 기본 Primary Asset은 UWorld 에셋이며, 다른 UObject 기반 에셋을 Primary로 만들려면 GetPrimaryAssetId를 오버라이드해 유효한 FPrimaryAssetId를 반환해야 합니다. UPrimaryDataAsset은 이 흐름과 Asset Bundle 지원을 위해 제공되는 편의 기반 클래스입니다.

Asset Bundle

Asset Bundle은 Primary Asset과 관련된 Secondary Asset의 이름 붙은 묶음입니다. 예를 들어 아이템 데이터는 메뉴에서는 아이콘만, 게임 플레이에서는 메시와 사운드까지 로드하도록 번들을 나눌 수 있습니다. 

UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = Display,
          meta = (AssetBundles = "UI"))
TSoftObjectPtr Icon;

UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = Display,
          meta = (AssetBundles = "Game"))
TSoftObjectPtr Mesh;

하드 참조 줄이기

항상 필요한 에셋이 아니라면 TSoftObjectPtr와 번들로 로딩 시점을 분리합니다.

상태별 로딩

클라이언트, 서버, 메뉴, 인게임처럼 필요한 번들이 다른 상황을 분리할 수 있습니다.

사용 흐름

1 Primary 타입 정의 DataAsset 클래스를 만들고 GetPrimaryAssetId 또는 설정으로 식별합니다.
2 검색 경로 설정 Project Settings 또는 커스텀 Asset Manager에서 스캔할 경로를 지정합니다.
3 Soft Reference 사용 아이콘, 메시, 사운드 등은 필요한 번들에 묶습니다.
4 비동기 로드 LoadPrimaryAsset 계열 함수로 필요한 시점에 로드합니다.
5 언로드 더 이상 필요 없는 Primary Asset과 번들을 명시적으로 해제합니다.

시각화 요약: Primary Asset 로딩 파이프라인

UPrimaryDataAsset 아이템, 스킬, 퀘스트 같은 로드 단위 데이터를 정의합니다.
FPrimaryAssetId Type과 Name으로 Asset Manager가 다룰 고유 ID를 만듭니다.
Asset Registry 로드하지 않은 상태에서도 경로와 태그 메타데이터를 검색합니다.
Asset Bundle UI, Game처럼 상황별로 필요한 secondary asset 묶음을 고릅니다.
LoadPrimaryAsset 필요한 번들만 비동기로 요청합니다.
StreamableHandle 로드 완료, 유지, 해제를 추적하는 핸들을 관리합니다.

언제 써야 하는가

  • 인벤토리 아이템, 카드, 스킬, 퀘스트처럼 로드 가능한 데이터 단위가 많을 때
  • 하드 참조 때문에 메뉴 진입이나 맵 로딩 시간이 길어질 때
  • 클라이언트와 서버가 서로 다른 에셋 묶음을 로드해야 할 때
  • DLC, 패치, 청크, 플랫폼별 쿠킹 규칙을 프로젝트 데이터 기준으로 관리해야 할 때
  • ObjectLibrary 기반 검색을 더 체계적인 Primary Asset ID 시스템으로 바꾸고 싶을 때

복습 질문

Q1. Asset Registry와 Asset Manager의 차이는?

Asset Registry는 에셋 메타데이터 검색 저장소이고, Asset Manager는 Primary Asset 단위의 발견, 로딩, 언로딩, 번들, 쿠킹 규칙을 관리합니다.

Q2. Primary Asset ID는 무엇으로 구성되는가?

Primary Asset Type과 Primary Asset Name으로 구성되며, 프로젝트 안에서 유일하게 식별되어야 합니다.

Q3. Asset Bundle을 쓰는 이유는?

하나의 Primary Asset과 관련된 Secondary Asset을 UI, Game 같은 상황별 묶음으로 나누어 필요한 시점에 로드하기 위해서입니다.
